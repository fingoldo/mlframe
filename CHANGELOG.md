# Changelog

All notable user-facing changes to **mlframe** are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

This file is intentionally lean and user-focused. For the full engineering
record (per-commit kernel tuning, profiling numbers, audit notes) see the git
history.

## [Unreleased]

### Added

- The environment banner names each booster's bundled native library and its size, not only the package version. Two installs can report the same version and ship different binaries, and a crash dump names the library it died in but not which copy of it -- a question a production crash left unanswerable from its log.
- Commit pressure is reported at WARNING, at startup and in the heartbeat: when the host is nearly out of commit charge, and when this interpreter holds a large commit charge that is not resident. Both are fatal on Windows and neither is fixable from inside the run - the second needs a kernel restart, because freed polars/Rust arenas are not returned to the operating system while numpy's are. A production run started with 1.0 GB of commit available against a 344 GB limit, holding 204.8 GB of private commit against a 0.8 GB resident set, and died 27 minutes later.
- The benchmark roster went from 21 arms to 52, so no method family is judged by a proxy of another. The information-theoretic family is now one arm per criterion -- MIM, CMIM, JMIM and RelaxMRMR on one shared binning and one greedy driver, so a difference between two of them is a difference between CRITERIA -- plus the MRMR class's own variants (`pld` relevance, RelaxMRMR inside MRMR, tree rescue, the cluster-medoid wrapper with expansion on and off, stability selection). Every wrapper, stability, bandit and cascade method in the repository joins it, as do the registry-built RFECV and BorutaShap the pre-registration always required, five univariate filters, and an oracle reference pair that hands the panel exactly the answer key and exactly its complement, so every arm's number sits between two measured endpoints. Each `score_kind` was set by running the arm and reading what came back: greedy backward elimination is ordinal rather than a selection order (its survivors are an unordered set), the cluster-medoid wrapper returns a set sorted by column index, and `StabilityMRMR` carries a genuine full-coverage score.
- The pre-registration's rule that every method be predicted to break on at least two beds now has an executor. The rule was stated in section 8 and no test enforced it; four methods already in the roster were in violation. All 33 methods that needed predictions got them from mechanism before running, recorded with their reasons in section 2e; the registry lock shows sixteen beds whose expectations changed and none whose structure did.

- Every run logs the interpreter path, the platform and the versions of the libraries a crash is usually blamed on (boosters, frame libraries, JIT, GPU stacks) before training starts. A crash dump names the library it died in but never its version, and a run may use a different interpreter than the checkout read afterwards. Versions come from distribution metadata, so nothing extra is imported (42.7 ms, once per run).
- The oracle's exact mutual information is now confirmed by a library this repository did not write. `assert_estimators_disjoint` kept the oracle's estimator families apart from the arms' backends, which stops the rank-correlation metric measuring self-agreement; it said nothing about the closed form itself being wrong, and the formula and every test of it were written here against one understanding of it. The check hands `dit` the same exact joint law -- for a discrete column the generator knows `P(x, y)` exactly, so neither side estimates anything -- and the two agree to 8.9e-16 nats at 2, 5, 17 and 64 levels. Every run's manifest carries the verdict, and when `dit` is absent it carries a record saying the check did NOT run and why, because an omitted field reads as a run whose oracle was never in question.
- Where each arm's advantage actually moves, split across the bed, the data draw, the inner split and the rows. The leaderboard says whether one arm beats another; this says whether that answer survives naming the bed it was measured on. It runs on the paired difference, so the bed's own difficulty cancels rather than dominating every component, and it is estimated by the method of moments with each level de-biased by the one below it -- without that subtraction the spread of the per-bed means is pure seed noise published as a real bed effect. A component the data says is absent is reported as absent: the negative moment estimates are kept beside the clamped ones, and an unmeasured row component reads as unmeasured rather than as zero.
- Eleven beds across four new families, chosen by measuring what the generator could already express and no bed used. The corruption layer was the largest: `NoiseSpec` was implemented, tested and reachable, and all thirty-one beds stood on `kind="none"`, so the suite had no case where the declared ceiling and the reachable one differ. It does now -- a fifteen per cent label flip leaves the ceiling at 0.843 against a declared 0.85, and no link scale recovers the difference. Alongside it: label reliability that depends on a column (invisible to anything scoring against the observed label), a coarsened label, four causal shapes the library lacked (M-bias, confounding, an instrument screened off by its mediator, proxy attenuation), a bed whose informative columns cost a hundred times the probes so the Pareto leg finally has an acquisition axis, four redundancy clusters at 0.50/0.80/0.95/0.99 solved for in closed form, Simpson's sign reversal, and rows that are not independent.
- `BasisTerm(kind="group_effect")`: one value drawn per distinct level of a column and shared by every row of that level. The only term here that makes rows non-independent, which is what a bed about splitting needs -- two rows of one group share an offset no feature explains, so a row-wise split is optimistic by an amount no metric computed on that split can reveal.
- A derived column can take LATENT parents. Without it a collider whose confounders are unobserved cannot be expressed at all: `LatentSpec.reflections` overwrites its column, so a column named by two latents ends up a reflection of whichever ran last.
- Two pre-registered hypotheses answered by running them rather than arguing them. Recovery against sample size: the parametric family leads at EVERY size from 150 to 10 000 rows and the two never cross, so the atlas's small-sample framing was the wrong shape -- binning discards information at every size and converges rather than overtaking. And RFECV's 24-point aggregation grid: on the one bed of four where RFECV genuinely chooses, all twenty-four configurations give the identical result against a seed-to-seed spread of 0.289, so it names a method rather than a family. The other three beds answer nothing, and the ablation now says so instead of reporting their nulls.
- A `byproduct-ensemble` arm that keeps the models a feature search already paid for. Every wrapper fits a model per candidate subset and discards all but one; this arm walks the same nested prefixes, keeps their out-of-fold predictions, and hill-climbs a with-replacement ensemble over them, so the only new cost is storage. It is scored as a selector only by courtesy -- its support is the union of the subsets the ensemble leaned on, which answers "which columns does this use" and not "which columns matter" -- and its provenance carries the ensemble weights so a reader can tell the two apart.
- Targets that are not a coin flip: multiclass, ordinal and count beds sharing one structure so the only thing varying is the target. Each class of the multiclass bed depends on a different ROTATION of the same weights, which is what makes it multiclass rather than ordinal and makes its answer key the union over classes; the ordinal bed puts the same classes on one latent axis with ordered cut points; the count bed is heteroscedastic by construction, since a Poisson's variance is its mean. All three carry an exact ceiling computed from their own law -- mean entropy, mean largest probability, expected Poisson deviance -- rather than an estimate.
- `from_real`: partial ground truth on real data, by the NIPS-2003 construction. Injected columns are irrelevant BY CONSTRUCTION, so false discovery becomes measurable on data nobody generated, while recall stays unmeasurable and is not reported. Each probe is drawn by resampling a real column's own values, which reproduces its marginal exactly -- every point mass, every tail -- because a probe from a standard normal beside heavy-tailed real columns is findable without ever looking at the target.
- Three CatBoost arms, one per elimination criterion, so "mlframe wins" is falsifiable from outside the package being benchmarked. Measured while testing them: at twelve columns all three criteria produce a bit-identical elimination order and at forty they produce three different ones, so the distinctness check runs on a wide bed.
- `frames.py` and `replay.py`. The first converts a generated frame to polars with `pl.Enum` and explicit levels, because a `Categorical` resolves through a process-wide cache and two independently built frames can hold codes meaning different things. The second rebuilds the bed a recorded result was measured on and reports `exact`, `changed`, `unverified` or `absent` separately -- editing a bed after seeing a result is often right, and what must not happen is the edit being invisible. Every cell now records its bed's spec hash so a replay can certify itself.
- A serial GPU queue in the worker pool, a nightly tier-2 workflow that publishes its cells and manifest as an artifact, and the three benchmark figures in the chart gallery.
- `train_mlframe_models_suite` trains a `HurdleRegressor` alongside the requested models for each regression target that sits on a point mass at its minimum for at least half its train rows, and only for those targets (`TrainingBehaviorConfig.hurdle_for_zero_inflated`, default ON). Against a plain LightGBM on raw y over three seeds it ranked rows better every time (Spearman +0.02 to +0.07), never predicted a negative amount (the plain model went down to -177) and was level on RMSE; against log-scale fits, which collapse on this shape, it keeps the spread.
- A rank-aggregation arm (`rank-vote`), so "combining several rankings beats the best one" becomes a leaderboard row instead of a plausible claim. Four deliberately unlike base scorers -- a parametric test, a binned mutual information, a rank correlation and a tree importance -- are aggregated by Borda, Dowdall or Copeland through this repository's own `votenrank`, which already does the same job one level down for RFECV's per-fold importances. Its components sit in the same roster, so the comparison is direct; three beds name it in their pre-registered predictions, and a scorer that cannot run on a bed ABSTAINS rather than voting for every feature equally.
- Four run tiers with an explicit bed library each, and a `--dry-run` that prices one from an earlier run's per-arm medians before a machine is committed to it; with no history it reports UNKNOWN rather than guessing. A worker pool enforces a per-cell budget that actually stops a cell: each slot owns its own single-worker executor, so a slot over budget is killed and replaced while the others keep running, and the killed cell writes `status="timeout"` rather than vanishing from the grid.
- Three selectors stop discarding the ranking they computed. `greedy_backward_elimination` and `iterative_zero_importance_pruning` return an opt-in per-round trace, so the elimination ORDER is available to every ranking metric instead of the bare set that excluded them; and the RFECV adapter prefers the strict consensus order over `ranking_`, which assigns rank 1 to every survivor and leaves a cut to be decided by the tie-break. That tie-break is not a hypothetical failure: it is what made an earlier atlas report a perfect parity recovery that turned out to be column order.
- `docs/FS_SELECTION_BIAS.md`, the document the repository kept referring to and did not have: the four ways a number here could flatter itself, what the protocol does about each, and the one it cannot fix. The existing `SELECTION_BIAS` is about prior shift and PU learning, which is a different subject.
- Published results carry an expiry date. Staleness is counted in commits to the PATHS a result is a claim about, not in days and not in total repository activity, with a separate `unknown` verdict for a manifest that records no commit -- an undatable result would otherwise read as a fresh one.
- Eleven scenario families where the generator had four. Published reference beds (Friedman 1-3, Weston-Guyon) whose formulas nobody here chose, so part of the suite is comparable to outside work; marginal beds isolating heavy tails, fixed-rate contamination, a point mass and quantisation from the dependence they sit on; mixed-type beds for cardinality bias, power-law levels and the identifier trap; and an observation layer carrying all three missingness mechanisms on sibling columns of one bed, a rare-class bed sized from its minority count, and the two halves of drift as a pair differing in exactly one declaration. The spec language grew named nonlinear terms (`BasisTerm`), feature quantisation and `MissingnessSpec` to express them.
- A bed that isolates tail dependence, which the existing copula pair does not. Measured, a symmetric gate at the eightieth percentile fires only 1.1 times as often under a t copula as under a correlation-matched Gaussian one, which is why those two beds split the roster identically and demonstrate non-monotonicity rather than tails. The new bed pairs Clayton and Gaussian columns at matching Spearman, matching Pearson and matching marginals, gated one-sidedly at the second percentile where the firing rates differ threefold; every column is a genuine cause, so the measurement is a rank gap between the two groups rather than set recovery, and a gap of zero is what every rank statistic must produce.
- Timings are now quotable. Each cell drains both MRMR memo caches and VERIFIES they are empty before the fit -- the roster runs several MRMR-family arms against one training frame, so a memoized fit returns the right answer instantly and the recorded cost is a dictionary lookup -- and records a fixed single-threaded calibration workload beside its own wall-clock, so two machines can be compared by ratio where they cannot be compared in seconds. A cell that cannot verify its drain records `memo_drained=False`, which invalidates its timing instead of publishing it.
- Every leaderboard row carries the smallest paired difference its own seed count could have resolved, and a non-rejection whose observed difference falls below it is labelled `underpowered` rather than `indistinguishable`. The two were printed identically, and on the real leg -- whose threshold is 0.013 to 0.031 AUC, larger than most gains the synthetic legs measured -- reading one as the other turns "we could not have seen this" into "there is nothing here".
- Two runnable ablations that need no new selector code: the 24-point `VotesAggregation` x `fi_missing_policy` grid, which decides whether "RFECV" names a method or a family, and a recovery-versus-sample-size sweep that reports the bracket where a binned estimator overtakes a parametric one instead of their ranking at one hand-picked size.
- Meta-tests for the two anti-rigging properties that were asserted and never checked: variance sorting must not recover any bed's answer key (averaged over seeds, because on unit-variance columns a single draw is a coin toss), and every arm's cost must be MEASURED rather than reported as unknown -- an uninstrumented arm looks free, and free is the most flattering thing a cost table can say.
- **`HurdleRegressor`** (`mlframe.training.composite`) for zero-inflated targets: a classifier learns `P(y != zero_value)` on every row, a regressor learns `E[y | event]` on the event rows only, and `predict` returns `zero_value + P * (E[y|event] - zero_value)`. `predict_event_proba` and `predict_magnitude` expose the two halves. On a synthetic reproducing a production target (71% zeros, heavy-tailed magnitude) a single model on `log1p(y)` collapsed to a prediction spread of 1.8% of the target's -- the production figure -- while the hurdle kept 12.1% and had the best R2 of the three variants at every tail weight tested. The edge over a single raw-MSE regressor is real but modest (+8-14% relative R2 on moderate tails) and shrinks with n. The magnitude defaults to a log target with Duan smearing (`magnitude_target="log"`, `smearing="insample"`); `smearing="oof"` trades per-row error for an unbiased predicted total, and the docstring tabulates that trade-off.
- **A target-maturity sensor** (`mlframe.training.targets.target_maturity_audit`). A cumulative or duration-valued target is not fully observed for rows created near the extract, so its marginal declines toward the present, a temporal split puts exactly those rows in TEST, and test metrics measure the censoring rather than the model. Right-censoring and a declining regime look identical in the marginal -- calendar time and remaining-observation-window are perfectly collinear -- so the audit uses the one constraint that separates them: a quantity that accrues from nothing must extrapolate to ~0 at a zero observation window. It reports `censoring_likely` / `declining_level` / `stable` with the extrapolated `origin_ratio` as evidence, and runs for the cost of a rank correlation on the bins the temporal audit already computes. The temporal audit surfaces its warning and, when censoring is indicated, withdraws the "train on the most-recent stable segment" recommendation -- under censoring that segment is the LEAST mature one.
- Regression label drift is tested on three scale-free ratios (level, dispersion, upper tail) beside the existing sigma test, each skipped when the train reference is inside its own sampling noise (`DEFAULT_REGRESSION_REL_SHIFT_WARN_THRESHOLD`, 20%).
- Composite specs carry `honest_holdout_rmse_gain_se`, the paired standard error of their gain against the raw baseline on identical holdout rows, and `min_honest_gain_z` (default 2.0) raises the ship/no-ship floor to `max(constant, z x se)`.
- Regression sensor trips (collapse detector, prediction-envelope clip) are recorded in a process-level ledger and repeated at `save_mlframe_model` time, so a flagged artefact says so where it is persisted rather than only hundreds of log lines earlier.

- Thirteen py-ci-shared checks now run as meta tests (`tests/test_meta/test_shared_checks_wired.py`): GPU timings must synchronize before the timer stops, string constants are never compared by identity, no `datetime.utcnow()` and no naive datetime anywhere ruff reaches (`timezone_honest`), optional numbers are tested with `is None`, a test loop whose only asserts sit inside it must state a floor, functions over 150 lines may not grow or appear, docstring examples run (`package_doctests`), documents may not name flags, identifiers or paths the code lacks, the README install block must match the declared extras, audit dispositions must name files and tests that exist, every audit tracker must be machine-countable, a blocking gate must declare every narrowing and pass its tool's config, and every `slow`/`gpu`/`fuzz` test must be selected by some CI run. `requirements-dev.txt` moves py-ci-shared from da63ad7 to 861b595 for them.
- Exact, reusable splits (`TrainingSplitConfig`). `id_column` names a stable row key: every run with a `data_dir` writes `<split_dir>/split_ids.parquet` ([id, split]) plus a `split_ids.json` sidecar (counts, start of each holdout's sequential block) and records `metadata["split_membership"]`; the key is dropped from features at train and predict. `split_ids_path` + `reuse_splits` (default `("test", "val")`) replay that membership on another, e.g. larger, frame: listed ids go to exactly their split, unpinned splits are carved from the remaining rows by the normal splitter, the rest is train. `test_start`/`test_end`/`val_start`/`val_end` pin holdouts by half-open date windows instead. With `train_before_holdout=True` (default) rows newer than the earliest pinned holdout start are excluded from train. Duplicate/null ids and a split pinned twice raise; ids missing from the frame are warned per split; groups spanning train and a pinned holdout are warned. Without any of the new fields the split is unchanged. Recipes: `docs/examples/fixed_splits.md`; rules: `mlframe/training/_fixed_splits.py`.
- CatBoost GPU fits are supervised again. Callbacks are stripped from the fit kwargs before the fit when the model resolves to `task_type="GPU"` (no more failed first attempt + Pool rebuild per fit); a one-time WARNING names what that disables and which native early stopping is in effect; a side thread (`MLFRAME_CB_GPU_MONITOR_S`, default 60 s, 0 disables) reads CatBoost's own `time_left.tsv` from a unique per-fit `train_dir` and logs iteration, it/s, elapsed, ETA and GPU utilisation / memory / other GPU processes, WARNing on throughput collapse, stalls and an exceeded `time_budget_mins` (CatBoost has no native wall-clock limit and interrupting a fit discards the model, so it only warns).
- Crash diagnostics: `enable_crash_reporting` now points faulthandler at a persistent `mlframe_faulthandler_<ts>_pid<pid>.log` next to the log file (`MLFRAME_CRASH_LOG_DIR` overrides), routes uncaught main-thread and thread exceptions to the logger with the full traceback, logs a "suite process exiting" line at exit (its absence means an abrupt kill), logs commit limit / page file at startup on Windows, and runs a heartbeat (`MLFRAME_CRASH_HEARTBEAT_S`, default 300 s, 0 disables) with active phases, RSS / private commit / available RAM and commit headroom, and GPU memory.
- The corrected joint-tail beds produce the suite's largest non-artefact separation, and it is not the one that was predicted: every mutual-information arm recovers the two-column answer key perfectly while every linear statistic -- F-test, LARS path, FDR on an F-test -- sits at chance and costs 0.20 AUC. The line falls between monotone and non-monotone statistics, not between binned and continuous ones, and the t-copula bed and its Gaussian control split the roster identically, so nothing here distinguishes tail dependence from non-monotonicity.
- The atlas is restated from the corrected SCM leg (2 560 cells, no failures). Its headline result is withdrawn and replaced by its opposite: no arm in the roster solves three-way parity -- all thirteen sit at chance -- and `rfecv`, which the artefact had made the hero, has a pooled advantage of -0.098 with P(>0) = 0.003. The collider separation survives and is now the sharpest real one, and the pre-registration's own predictions are scored at 62% (adversarial) and 52% (SCM).
- Copula dependence, so a bed can have correlation without tail dependence or with it. Almost every synthetic correlated dataset is a Cholesky factor, which is a Gaussian copula and has zero tail dependence at any correlation below one; an equal-mass binned estimator puts an entire joint tail in one histogram cell, so a dependence living only there is invisible to it rather than merely hard. Gaussian, Student-t and Clayton families, a `tail_gate` link whose signal fires only in the joint upper tail, and a registered pair of beds -- t-copula and its Gaussian control -- that share a correlation and differ only in the tail.
- The benchmark now scores its own pre-registered predictions. Each bed declares before the run which arms it expects to defeat; the report states the hit rate, names every prediction that failed (the bed expected to defeat an arm and the arm paid anyway) and every unpredicted failure. On the adversarial leg 18 of 29 predictions held, and the misses are informative: `boruta` gained 0.127 AUC on the bed that named it. Cost is now split into the arm's own fits and the panel's, because every arm pays the same panel and a combined total made a free filter and an expensive wrapper read alike.
- The dataset oracle: `GroundTruth.ceiling()` and `mi_reference()` now compute instead of raising. The ceiling is exact rather than estimated -- every corruption in the package must state how it moves `true_prob`, so the achievable Brier is `mean p(1-p)`, the log-loss `mean H(p)`, and the AUC the exact pairwise probability under that law. Reference MI reports an exact value where the law supplies one, three disagreeing estimator families beside it, and marks itself unreliable when their spread exceeds the effects the benchmark measures. `assert_estimators_disjoint` refuses to let an oracle share an estimator family with the arms it scores.
- `test_pyutilz_pin`: every pyutilz pin in the workflows and `pyproject.toml` names one commit, and the installed
  pyutilz includes it. `requirements-dev.txt` moves py-ci-shared from v1.4.2 to da63ad7 for the check
  (`git_dependency_pins`), and for a source-text detector that now sees a generator over a `glob("*.py")` and a
  bare `assert m` after `re.search` over source; the source-text baseline gains the 11 claims it had missed.

- **Locked dependency graph (`uv.lock`).** 594 packages pinned across Python 3.9.2-3.14 on Linux, Windows
  and macOS, so an upstream release can no longer turn the matrix red with no local change and any run is
  reproducible after the fact. `pyutilz` resolves through `[tool.uv.sources]` by branch, with the exact
  commit recorded in the lock -- bump it with `uv lock --upgrade-package pyutilz` rather than by editing a
  SHA in `pyproject.toml`. A new `lockfile` CI job runs `uv lock --check` and an actual `uv sync --frozen`,
  because a lock that resolves is not necessarily a lock that installs. Dependabot moves from the `pip`
  ecosystem to `uv` so a dependency bump and its lock arrive in one PR.
- A `pinned-tool-versions` pre-commit hook fails when the ruff version CI runs (defined once in py-ci-shared,
  v1.4.2), the `ruff==` pin, the `ruff-pre-commit` revs and the interpreter's ruff disagree. The pin and the revs
  said 0.16.1 while the shared ruff-blocking workflow still ran 0.15.22; it now runs 0.16.1 too, so a local pass
  and CI check the same rule set. `requirements-dev.txt` moves py-ci-shared to v1.4.2 for it.
- `requirements-dev.txt` now carries contributor tooling that project metadata cannot legally hold, and no
  longer a bare `-e .[all,dev]` convenience line. Install with
  `pip install -e ".[all,dev]" -r requirements-dev.txt`.

- `docs/FS_ATLAS.md`: which feature-selection method to reach for in which regime, from three legs and 7 829 cells. The first-order finding is that the downstream model decides more than the selector does (a linear model gains on 16 of 17 synthetic beds, a gradient-boosted tree on 7, and on real beds neither at any K the design could resolve). Four separations are clean enough to act on, the sharpest being that a subset wrapper recovers a 3-way parity perfectly and identically on all 20 seeds while every other arm is at chance and unstable.
- Benchmark charts, built as specs through this repository's own renderer so both backends and every configured format come for free: signed bars with paired intervals against the null, a cost-versus-quality frontier, and the posterior CDF of the pooled effect so a reader applies their own region of practical equivalence. Colours are validated rather than chosen -- the four-series order deliberately avoids tab10's orange/green pair, which is 0.7 apart under protanopia when adjacent and therefore invisible to a red-green colourblind reader.
- The synthetic control leg finished (3 029 cells, 20 seeds per arm-bed) and settles what the Phase 0 kill criterion was about: with the same lightgbm downstream that could not use selection on the real beds, some arm beats the null on 5 of 9 synthetic beds at the tightest K and 7 of 9 at the widest. The verdict is about the data, not the model. The gains are 0.003-0.017 AUC, which mostly sits inside the real leg's own blind spot, so the control rules out one explanation without establishing its opposite. Written up in `docs/BENCHMARK_SYNTH_CONTROL.md` and recorded in the pre-registration.
- The benchmark records each arm's own reported optimum together with the metric it is expressed in, and reports the winner's curse: the gap between what a selector claimed at selection time and what its choice scored on the honest holdout. The comparison is declined, loudly, when the two metrics differ -- this repository's RFECV optimises a probabilistic error internally while the report reads AUC, and subtracting one from the other yields a unit mismatch with the shape of optimism.
- The benchmark report now carries a cost-versus-quality frontier: an arm is dominated when another is at least as good and no more expensive, and the dominating arm is named so the claim can be checked. The null hypothesis sits on the frontier at zero cost, so an arm that fails to beat it is reported as dominated by doing nothing. An arm whose cost was never measured is listed as unpriced, never as free, and can never dominate another.
- Blind aggregation for the feature-selection benchmark: `FS_HYBRID_BLIND=<salt>` relabels every arm before the report is built and writes the mapping to a separate file the analysis never reads, so the tables can be read before anyone knows which row is the author's own method. Labels are salted rather than alphabetical, so a reader cannot carry a previous run's mapping into the next one from memory; the null hypothesis stays visible, since every contrast is stated against it and it is nobody's method.
- The SCM scenario library is wired into the feature-selection benchmark as its own leg: the same roster and protocol on beds whose answer key is derived from the graph that generated the data, so support recovery is a fact rather than an annotation and each bed's ceiling is calibrated rather than incidental. Kept in a separate results file from the real and adversarial legs, which ask different questions and must not be pooled.
- A scenario library over the generator: ten named beds across null, linear, redundancy, synergy and causal families, each declaring what it exists to break and which answer key it is scored against, hashed into `REGISTRY.lock.json` so a bed edited after the results were seen shows up as a post-hoc change. Declared edges are now realised as data -- a column with parents is generated from them, before the target if it feeds the link and from the sampled label if it is a child of it -- so a bed that declares a collider has one instead of a noise column with a collider's name.
- `mlframe.data.datasets.generate` turns a `DatasetSpec` into data plus the ground truth that produced it: marginal families spanning heavy tails, skew, point masses and categorical levels; latent factors whose reflections carry private parts, so a redundancy-collapsing selector provably loses signal; parity links whose operands are individually invisible; heteroscedastic noise whose drivers are recorded as informative about uncertainty rather than about the mean; and label corruptions that must state how they move `true_prob`. Difficulty is set by bisecting the link scale until the exact Bayes AUC of the SHIPPED probabilities (after prevalence and corruption) hits a declared target, so a bed that says "AUC 0.80 achievable" is one. Streams are addressed by name, so inserting a column into the middle of a spec leaves every other column bit-identical.
- A tier-1 benchmark gate runs six real cells with committed numbers on every run of the feature-selection suite, so a selector change is measured against something instead of against nobody. It pins each bed's difficulty through the null arm's downstream AUC, the parity bed's known blindness (a marginal-greedy selector recovers none of the three XOR operands), and the variance-sort tripwire. The bands have an explicit update procedure rather than being an add-only ratchet.
- Each benchmark run now writes a manifest beside its results, and the report checks the run back against it: seeds beyond the declared set are reported as optional stopping, undeclared arms and scenarios are named, a pre-registration whose hash no longer matches is flagged as not having bound the run, and a differing environment marks the timings (never the quality metrics) as incomparable. A run without a manifest is reported as undeclared rather than as clean.
- Benchmark cells now persist WHICH columns each arm selected, not only how many, along with the scenario's declared relevant set. That makes two questions answerable that a downstream score cannot answer: selection stability across seeds (Nogueira-Brown, size-corrected, so a random selector scores ~0 instead of the ~0.4 pairwise Jaccard would report) and support recovery against declared truth. Selections too wide to store are marked as omitted rather than dropped, so an analysis can tell "selected nothing" from "nobody wrote it down".
- The benchmark report now carries a pooled posterior over each arm's advantage, on normalized skill so one region of practical equivalence means the same thing at a 50% base rate and at a 1% one. The random-effects fit is exact quadrature rather than sampling -- flat prior on the pooled effect, half-Cauchy on the between-scenario spread -- so it reports the heterogeneity itself, which answers whether one number is a fair summary of every bed. A `P(|mu| < r)` curve accompanies it, so the ROPE width is read off the posterior rather than argued about.
- The feature-selection benchmark can now say how large an effect its own null results rule out. `_power.py` estimates `tau`, the seed-to-seed spread of the paired difference against `all-features`, from executed cells rather than from an assumed pilot, and reports both the seeds an effect needs and the effect a given number of seeds resolves. Measured on the confirmatory run, the pre-registered `R = 20` resolves 0.013 AUC on the median contrast and 0.031 on the p90 one, so the Phase 0 kill criterion licenses "no arm gained more than one to three AUC points" and not "no arm gained". Recorded in `docs/BENCHMARK_POWER.md` and cross-referenced from the pre-registration.
- `run_synth_control.py` runs the pre-registered roster against the nine known-truth adversarial beds, the control point that separates "selection does not pay on real data" from "selection does not pay for a strong model" -- on these beds an oracle subset exists, so the achievable gap over `all-features` is measured rather than assumed.

- A checksummed local cache for the real-data feature-selection benchmark beds (`_realdata_cache`), so that leg runs offline and reproducibly instead of depending on OpenML being reachable at run time.
- Live training-progress widget for notebooks (`mlframe.training.callbacks.TrainingProgressWidget`), attached by passing `progress_widget=True` to any `UniversalCallback` subclass (LightGBM / XGBoost / CatBoost). One tab per METRIC, one curve per eval dataset (train / validation / test / any shard the booster registered), the running optimum marked with a star on the held-out curve, own-process RAM on a secondary axis against the same iteration axis, and a two-step "stop training" button whose request flows through the existing `stop_flag` the training loop already polls -- so a misclick cannot end a multi-hour fit and stopping needs no new path into the booster. Metric and dataset subsets are selectable; tabs appear for metrics the booster registers late. Per-node importance (PageRank / HITS / centralities) remains networkx; only these batched pairwise scores are provided here.
- LENKOR composite-similarity metric learning (`mlframe.core.composite_similarity`): `fit_composite_similarity` / `combine_block_similarities` learn a metric as a coordinate-descent-tuned deformed (linear/sqrt) weighted combination of per-attribute-block similarity matrices, optimizing a leave-one-out kNN target functional (Dyakonov's ECML-PKDD-2011-winning technique) — for blending heterogeneous precomputed similarity views, distinct from Mahalanobis metric learning on raw features.
- Fuzzy-partition (POSP) membership encoding (`mlframe.feature_engineering.fuzzy_partition_encode` / `fuzzy_partition_fit` / `fuzzy_partition_transform`): fuzzification of a numeric column into `n_sets` interpretable soft-membership features whose rows sum to 1 (Ruspini partition), `triangular` (exact tents) or `gaussian` (normalized RBFs), numba njit, leakage-safe fit/transform recipe. A smooth alternative to hard one-hot binning: on smooth nonlinear targets a linear model on the soft memberships beats hard `KBinsDiscretizer` one-hot at the same number of bins.
- Per-graph spectral descriptor (`mlframe.feature_engineering.graph_spectral_features`): a compact permutation-invariant (isospectral) fingerprint of a whole graph from its edge list - n_components, algebraic connectivity (Fiedler λ2), spectral radius, graph/Laplacian energy, a bipartiteness signal (largest normalized-Laplacian eigenvalue), triangle/edge spectral moments, and the smallest normalized-Laplacian eigenvalues - for tabular graph-classification where each sample is a graph. Complements the per-node `graph_structural_features`.
- Friedman & Popescu H-statistic (`mlframe.inspection.friedman_h_statistic` / `pairwise_interaction_strength`): model-agnostic measure of how much of a feature pair's joint effect on a trained model is non-additive interaction (H = sqrt of the interaction share of the centred joint partial dependence, in [0,1]). Built on the suite's existing PDP machinery; distinct from sklearn (which has partial dependence but no interaction statistic). High-H pairs are the ones worth an explicit engineered interaction feature.

Each persists what it needs onto the trained bundle's `metadata` and replays identically at predict time (stateless config-replay for most; a fitted entity-lookup for target encoding; a fitted `FittedLatentInteractionSvd` object for the SVD embedding).

### Changed

- Composite discovery's candidate loop no longer holds every base's (screen rows x features) float and prebinned copies at once: a base context keeps its dropped columns and dedup mask, the copies are gathered when its first transform is scored and dropped after its last, and the bin estimator never gathers the float plane (it reads only codes). The lazy polars prebin path, previously switched off by the default near-collinear dedup, now dedups from a row-block Gram (`discovery/_lazy_dedup.py`) with exact float64 re-checks for borderline and non-finite pairs, and its MI(y) baseline aggregates over the deduped columns like the eager path. Specs are byte-identical; candidate-loop peak 182 -> 104 MB at 70k x 80 with 4 bases, 1176 -> 247 MB at 70k x 200 with 16 bases.
- `honest_rmse_gate_sample_n` defaults to 30_000 (was 20_000), the honest-OOF selector's cap: both draw with the same seeded generator, so equal caps give identical samples and the honest RMSE gate reuses honest-OOF's fitted predictions at any frame size, where above 20k screen rows it refit every spec on a smaller sample.
- Interaction bases become composite targets. Discovery found products (and sums, differences) of two features whose MI with y beats both, but only reported them in `interaction_bases_`; now `a__mul__b` / `a__add__b` / `a__sub__b` are screened as base candidates before the main screen and pass every gate like any base. The column exists in no user frame: every base reader (discovery, the suite's target build, the wrapper at predict time, a reloaded suite) recomputes it from its parents (`composite._synthetic_bases`), and a serving spec records the recipe (`base_recipes`, built by `serving_base_from_columns`). On y = f0*f1 + 3 sin(2 f2) the honest-holdout RMSE gain goes from 0.08-0.13 to 0.20-0.24 (raw ~0.53), and the suite-trained composite beats the raw model on fresh rows. `div` interactions stay report-only (their divisor floor is fitted on train rows).
- `data_signature` on a polars frame is 4.6x faster (1896 -> 410 ms at 200k x 500), with byte-identical output: the schema is read once, the sample is gathered as one frame, and the sample and row-order windows are encoded a dtype group at a time (`encode_polars_frame`). The suite's discovery phase hands the signature its cache key already computed to the discovery fit, which takes it for the same frame, target and features.
- Composite post-processing re-applies each fitted pre-pipeline to a frame once per phase (a phase-scoped `memo_transform`, used by the wrapper's inner routing and the pre-pipeline shim): one val frame went through one pipeline 7 times in a suite run, now 3 (training, the per-model hook, the phase). `CompositeTargetEstimator.predict_with_pre_clip` returns `predict` and `predict_pre_clip` from one inner predict with identical clip counters, and the wrap pass uses it.
- The suite's model cache reuses a `.dump` only when it was trained on the same hyperparameters, targets, rows and sample weights. It was keyed by model name and checked only the feature schema, so a rerun into the same directory with a new label, split or learning rate silently served the old model. Each dump now records a training fingerprint (`training/_model_cache_fingerprint.py`); a mismatch, or a dump saved before this change, is retrained once.
- Every registry-transform `fit` / `forward` / `inverse` call in `composite/` and `core/` goes through `call_transform`, which forwards `groups` / `sample_weight` exactly when the transform takes them and fails loudly when a grouped transform gets none. The tiny-model CV, the auto-chain CV and the WAIC tie-break now pass a grouped spec its groups (it raised before any fold ran and dropped out of the rerank, also when too few groups forced a plain KFold split), and the external-holdout OOF passes the component's own group column.
- Stacked composite discovery (`fit_stacked`, `fit_stacked_on_residual`) gathers a polars frame's train rows by position, in `train_idx` order like their targets. The boolean-mask filter returned frame order, so an unsorted train index paired every row with another row's target (off by up to 23.8 in the test).
- The `logratio` inverse clips `T_hat` to `median_t +/- soft_cap_k * mad_eff` widened to the training T range (new params `t_train_min` / `t_train_max`; serving export and the provenance formula share `logratio_t_band`). Rows with y near zero have log-ratios beyond ten MADs, and the old band reconstructed even those training rows wrong (0.025 off on a target crossing zero). Params saved before keep the MAD band.
- `median_residual` and `quantile_residual` grow their bin count with the training rows (like n^0.3, from 100 / 200 rows per bin, capped at 200 bins; `composite._quantile_edges.bins_for_rows`). A fixed 10-20 bins left the step function's bias flat as data grew. On a saturating relation the downstream composite RMSE improves 1.4-3% at 20k-100k rows and is unchanged at 2k.
- `monotonic_residual` makes its knot values monotone by weighted isotonic regression instead of a cumulative max, which lifted every dip in the noisy knot medians. On ~200-row groups `monotonic_residual_grouped` placed identical groups 0.075 sd above the pooled fit; now 0.025.
- The composite MoE gate says once, at INFO, when it cannot deploy because the configured `group_column` is not among the features. An extractor's `group_field` is dropped from the features as bookkeeping, and the enabled gate was then a silent no-op; keep the column among the features to enable it.
- Composite discovery's leak-correlation filter recomputes in float64 every column whose float32 |corr| lands within 1e-4 of `forbidden_base_corr_threshold`, and caps |corr| at 1. In float32 a near-copy of y (true |corr| 1 - 1.3e-9) scored 1.00000018, above any threshold, so the filter's own advice to raise the threshold could not keep a legitimate lag base; the default 0.99999 sat inside float32 rounding error.
- `rolling_quantile_ratio_grouped` under recurrence continuation seeds a group it never saw with the ungrouped series' tail, as `rolling_quantile_ratio` does. It used an empty window, so the first k-1 rows of an unseen group were scaled by the median of a truncated window (up to 1.8 off in the test's reconstruction).
- `score_interaction_pairs` / `discover_interaction_bases` take their MI scores on the `train_mask` rows only, and a mask of the wrong length raises. The mask used to reach only the divide-by-zero floor, so a caller passing train and test rows together got interaction pairs chosen by MI that read the test targets. Discovery itself passes train rows only and is unaffected.
- The composite MoE gate keeps the lag failsafe unless an expert's advantage is real. It chose per group on as little as one row with no margin, so its choice followed each group's noise: experts 10% noisier than lag won half the groups, and on fresh rows the gate served 5% worse than plain lag, while its "never worse than lag" guarantee held only on the rows it chose on. A non-lag expert now has to beat lag by 2 standard errors of the paired per-row squared-error difference, in a group of at least 20 rows (`moe_gate_min_gain_z=2.0`, `moe_gate_min_group_rows=20`; `MoESelectionGate(min_gain_z=..., min_group_rows=...)`). On the same noise the gate now serves lag's RMSE, and an expert that really is better still wins most groups (0.70 of lag's RMSE in the measurement).
- The ICE custom eval-metric skips the LEARN set once an eval set is present (`skip_largest_set`, on by default for the calibrated CatBoost classifier): CatBoost evaluates a custom metric on both sets, but only the eval value drives early stopping and model selection. One call cost 107.8 ms at 498k rows; a 200k-row fit went 7.1s -> 3.2s at the same chosen iteration. Skipping by array size alone would have zeroed a large eval set's metric and broken early stopping, so the skip keys on the largest set seen, never on a run with a single set.
- The startup memory line states the interpreter's age, RSS and private commit: a suite started in a notebook inherits whatever earlier cells committed, and "private commit 61.7 GB" before loading a 242 MB frame reads as a startup leak until the line says the process is hours old.

- Composite targets: a spec whose honest-holdout RMSE gain is <= `min_honest_gain_to_train` (new, default 0.001 = 0.1% of baseline RMSE) is no longer trained. `max_total_composite_targets` only picked the best 25, so a run where few specs help shipped specs that lose to raw y: one production run trained 12 with gain <= 0 (~4 min each) and none of its 25 composites beat raw.
- Composite log/cbrt/Yeo-Johnson/Box-Cox/signed-power targets predict with a smearing correction (mean of the inverse over 32 training-residual quantiles), so they estimate the conditional mean of y instead of the inverse of the mean of T (the geometric mean for log). Discovery's y-scale gates, honest RMSE gate, OOF select and tiny rerank score specs the same way. Opt out by setting `estimator.smearing = False` before `fit`.
- Adversarial validation is fitted once per run per feature set instead of once per target (it does not depend on the target; ~15 s x 32 targets in a production log).
- The heartbeat stops when the suite returns and restarts with the next suite call; in a notebook it kept logging every 5 min for hours after the run.
- Charts on heavy-tailed data switch to asinh axes (bins equal-width in asinh) instead of linear axes that crushed the bulk into one bar: y-vs-T distributions (now two panels with a verdict and an explanation of y and T), split target/prediction overlays, residual histogram, perfplot heatmap and sample trace, error-bias panels. The perfplot sample rows sit at evenly spaced quantiles of y instead of a random draw; the three regression report figures share one width; composite y-scale charts carry the same header as raw-target charts.
- The "member gate source=val-coarse" note is logged once per process at INFO instead of a WARNING per ensemble.

- Adversarial fold selection no longer skips on large frames. Above `max_union_rows` (default now 400 000) each of its five folds fits the train-vs-test classifier on a stratified subsample of that many rows while still predicting every held-out row, so every train row keeps an honest OOF score; `build_test_like_validation_fold(max_fit_rows=...)` exposes the cap, `0` restores full-size fits. At the production ratio the selected fold matches full-size fits (precision 0.701 vs 0.700 on a drifted bed).
- Row-wise extreme columns: the fit-reference scorer compresses each reference to its distinct values (one binary search instead of two), scores columns contiguously on threads (nogil kernel, not numba's parallel layer) and fits the reference on threads: 13.9 s -> 3.7 s on 500k x 85, bit-identical to the previous kernel (kept as `_extremality_vs_reference_njit_v1`).
- The feature-distribution analyzer converts only a polars frame's numeric/bool columns to pandas and counts categorical/string columns in polars (a 498k x 109 frame spent 3.4 s converting a 232k-distinct text column for a distinct count).
- Composite discovery auto-chain runs on `tiny_model_sample_n` rows (it is tiny-model CV, like the rerank), shares one binned LightGBM dataset per fold across all candidates, and gives each base's fits its share of the cores; the WAIC tiebreak scores specs on threads. Identical selections; 59 s -> 45 s for a three-base auto-chain step, 139 s -> 105 s for a 300k-row discovery.
- Category drift that the shared train+val category domain already handles (`align_polars_categorical_dicts=True`, cardinality < 100) is logged at INFO as handled instead of a WARNING that claimed XGB/CB may crash and asked for a manual `__UNSEEN__` bucket; higher-cardinality drift keeps its WARNING without the crash claim unless alignment is off.
- The "extreme-AR skip did NOT fire" input dump is a WARNING only when the skip was applicable (group-aware split, bounded-only zoo) but lacked a per-group lag-1 or had it for another target; on non-grouped runs it is DEBUG.
- `[JIT prewarm]` logs `total=` and attributes every block (metric kernels, GPU metric kernels, ranking, feature selection, baselines, heavy imports); the per-group line used to cover only the last three and read 0.0 s for a 64 s step.

- Composite-discovery cache keys (`data_signature`) no longer depend on the installed pandas / polars / numpy. The key is built from mlframe's own canonical encoding of the data (logical type tokens, NaN/NA/None as one null, datetimes as UTC nanoseconds whatever the stored resolution, ints by value whatever their width, strings as UTF-8 whatever their dtype) instead of `str(dtype)`, `hash_pandas_object` and polars `hash_rows`. pandas and polars frames of the same data now share keys. One-time change: every existing discovery-cache entry misses once and is recomputed.

- MRMR CPU conditional-MI redundancy loop: the serial-vs-parallel threshold `_CMI_PARALLEL_MIN_CANDS` lowered 32 -> 8 (override `MLFRAME_CMI_PARALLEL_MIN_CANDS`). At the default 30k screen-subsample size the `prange` loop beats the serial loop 2.4-7.8x for every candidate count `p>=4`, so small candidate pools no longer run single-core. Both branches are exact CMI (selection-equivalent).

- MRMR GPU-resident FE (`MLFRAME_FE_GPU_STRICT`) now has an AUTO size-gated default: on fits at/above `MLFRAME_FE_GPU_STRICT_AUTO_MIN_N` rows (default 100 000, the production regime) with a usable CUDA device, STRICT engages automatically (~2.5x faster FE and measured selection-equivalent to the CPU path at that scale). Below the threshold, or with no GPU, the exact CPU path runs unchanged (byte-identical legacy). Set `MLFRAME_FE_GPU_STRICT=0` to pin the CPU path at any n, or `=1` to force STRICT. The small-n divergence that keeps STRICT gated below the threshold is finite-sample MI-estimation variance (features with near-tied relevance), which fades as n grows — verified converged across scenarios by ~50k; the 100k default sits comfortably above that.

### Removed

- `CompositeTargetEstimator` no longer accepts `moe_gate_enabled`, `moe_shrink_rtol`, `moe_tie_rtol`, `moe_min_group_rows` or `moe_failsafe`. ### Fixed

- Serialising the cached LightGBM fold construction was not enough: a fold training on a SUBSET of its rows went through `LGBMRegressor.fit`, which builds its dataset inside `fit` with no serialisation, and a production kernel died there with an access violation after the first fix. Masked folds now build their dataset through the native API under the same lock, cached by the exact rows they train on. Predictions are bit-identical to the wrapper's, and the safe path is faster than the unprotected one was (23.4 s against 27.2 s at 16 threads) because the seed repeats of one spec reuse the binned rows.
- `greedy_backward_elimination`, `iterative_zero_importance_pruning` and `stochastic_bandit_selection` crashed on a stratified splitter -- the first thing a classification user reaches for -- because each called `cv.split(X)` without the target. `KFold` ignores `y`, so every existing test passed.
- The guard that stops a wrapper arm being scored on its own objective never fired: its table was keyed `rfecv_lgbm` and `rfecv_logit` while the arm is named `rfecv`, so every real arm read as "not a wrapper". It is now keyed by the roster's own names, with a test that every key is one.
- Composite discovery built LightGBM fold datasets from several rerank threads at once. LightGBM's binning is not safe to enter concurrently, and a production Jupyter kernel died with a Windows access violation plus a heap corruption (0xc0000374) with 16 threads in `Booster.update` and three more inside a dataset construction. Construction is now serialised process-wide; training stays parallel (measured: no cost at 16 threads, while serialising training too would double the rerank).
- The base-free sentinel a unary composite spec carries was treated as a missing base column, so every such spec logged "column '' is in none of the train/val/test frames ... cannot be trained" although it trains fine. The placeholder is now returned directly, which also skips a scan of all three split frames per spec.
- Three of the eleven new beds were wrong on their first construction and looked right in the source, which is why each now has a test asserting the MEASURED property rather than the spec that asked for it. The M-bias collider came out correlated 0.35 with the target instead of 0.00 and uncorrelated with the cause, because the second latent silently overwrote the first's reflection. The proxy-attenuation bed had the proxy predicting WORSE than the column it exists to dominate, because the target was driven by that column directly. And two beds handed their answer key to anything sorting by variance, caught by the tripwire added hours earlier.
- A latent edge into a column that is also that latent's reflection now has a stated precedence -- the reflection builds it, the edge documents it -- rather than the derived layer silently rebuilding the column and discarding the loading. That is what turned a bed made entirely of an asymmetry between two reflections into a symmetric one.

- Several numba kernels in the MRMR redundancy loop now run with `nogil=True`, giving real (not illusory) speedup on the `threading` joblib backend; a related `shuffle_arr_lcg` state-chaining overflow bug (int boxing losing its dtype across calls) is also fixed.
- `MLFRAME_FE_GPU_STRICT`'s AUTO gate now considers column count as well as row count (previously a wide-but-under-the-row-threshold fit stayed on the slower CPU path unnecessarily), and a related CMI CUDA-eligibility check no longer silently re-approves a call its caller had already declined.
- `score_prospective_pairs`'s usability-admission gate had a missing clause that meant one of its three accept conditions was computed but never actually consulted; restored (with an adversarial test proving it changes real selection outcomes) and the gate's supporting computations are now batched instead of per-pair, eliminating one of the largest CPU hotspots in production profiles.
- `kernel_tuning_cache`'s default (non-sweep) lookup path no longer logs a misleading "sweep starting" banner or spawns an unusable background thread on every cache miss; a related backend-lookup bug that ignored input size when matching a cached region is also fixed.
- MRMR's stratified screen-subsampler now falls back safely (with a warning) instead of silently scanning at full size for very high-cardinality targets; `prewarm_numba_cache` gained an opt-in flag (`MLFRAME_NUMBA_WARMUP_SKIP_PARALLEL=1`) to skip warming parallel kernel variants a run won't reach; a stale test-helper crash that had been masking 22 real MRMR sensor tests behind a spurious `ValueError` is fixed.

## [0.9.0]

### Added

- `train_mlframe_models_suite` orchestration for end-to-end multi-model training, calibration, feature selection, and reporting.
- Target types beyond regression/binary: multiclass, multilabel, quantile regression, and Learning-to-Rank.
- Composite-target discovery: auto-detect dominant-base composite targets, fit a transform, and predict on the original y-scale, with honest holdout/out-of-fold de-biasing of the winner selection.
- Feature-selection suite: MRMR (with categorical-interaction FE), RFECV (stability selection, knockoffs, permutation/SHAP importance, checkpoint resume), BorutaShap, ShapProxiedFS, and hybrid selectors — all reachable and configurable from the suite.
- Feature-engineering `feature_engineering.transformer` subpackage: row-attention aggregates, orthogonal-polynomial basis families (Hermite/Legendre/Chebyshev/Laguerre), univariate/pair/adaptive-arity FE, and an `fe_auto` meta knob that collapses the many FE flags into one.
- Feature-handling stack: text-vs-categorical detection, TF-IDF/hashing text encoding, embedding providers (incl. HuggingFace), leakage-safe target encoders, and a two-tier feature cache.
- Reporting backends (matplotlib and plotly), calibration and multi-target diagnostic panels, and pre-training dummy-baseline reports.
- Pre-training baseline diagnostics: dominant-feature discovery, init_score baselines, and composite-target recommendations.
- Feature/label drift detection and reporting, with opt-in auto-action.
- Typed (Pydantic) training/reporting/feature configuration surfaces.
- Optional GPU acceleration (cupy/CUDA) for feature-selection MI and SHAP kernels, auto-dispatched by hardware.
- Python 3.14 support.

### Changed

- **BREAKING:** repackaged from a flat layout into `src/mlframe/` sub-packages; update imports accordingly.
- Polars-native fast paths for CatBoost, XGBoost, and HistGradientBoosting (no dict→string round-trip), with unified categorical handling and auto-skip of redundant encoding.
- Corrective mechanisms (honest holdout selection, stratified FE subsampling, cluster-medoid RFECV pre-reduction, calibrated permutation-null gates) now default ON; opt out to restore legacy behaviour.
- Composite-target ensemble default changed to `nnls_stack`; discovery sub-phases parallelised across cores.
- BorutaShap is now sklearn-clone-able (works inside `GridSearchCV`/`Pipeline`).
- Extensive numba/GPU kernel performance tuning across feature selection, feature engineering, calibration, and metrics, dispatched per-host via a kernel-tuning cache (see git history).

### Fixed

- Corrected statistical methodology in several info-theory selectors: conditional (stratified) permutation null, add-one p-value estimator, KSG neighbour-count convention, and noise-floor quantile sample size.
- Numerous Polars fast-path robustness fixes: nullable/Categorical handling, category drift across train/val/test splits, global string-cache leaks, and stale `cat_features` state.
- MLP defaults no longer strangle linear signal; stabilised early stopping, eval-set normalisation, and clone-safety.
- Matplotlib figure-leak and redundant-plot fixes reducing wall time on plot-heavy fits.
- Metadata pickle failures with duplicate mlframe installs, and artifact leakage to CWD when `data_dir=""`.
- Many production bug fixes surfaced by combinatorial/metamorphic fuzzing and multi-agent audits (see git history).

### Removed

- `Normalizer_l2` preprocessing helper.
- `ensure_installed` runtime dependency-installation from library modules.
