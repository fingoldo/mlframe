# Predict path + artifact persistence audit (2026-09-20)

Scope: the two serving entry points (`predict_mlframe_models_suite` on a disk bundle, `predict_from_models` on in-memory models), the shared pre-pipeline / extension replay helpers, the save/load bundle round-trip, and the fit/transform contract of `training/pipeline/` as consumed at predict time. `training/composite/` is excluded except where the generic predict path loads a composite artifact. Findings favour silent train/serve divergence over crashes: everything below either changes a served number without raising, or drops a model/row out of a served ensemble without telling the caller. The dominant theme is that the two entry points have drifted apart - `predict_from_models` has accumulated several correctness steps (column reordering, categorical dtype/Enum-domain coercion, GBM-safe name sanitisation, all-models-failed escalation) that `predict_mlframe_models_suite`, the path a serving process actually uses, never got. The second theme is fitted state that exists at fit time but is not in the stamped metadata, so predict silently recomputes it batch-relative.
