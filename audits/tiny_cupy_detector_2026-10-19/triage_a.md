# Triage A: 42 baselined cupy-loop keys (read-only)

Policy used for the classes. FALSE_POSITIVE means the cupy calls are unreachable in a default host run (env flag off, host arrays, numpy module object, or a branch on a loop-invariant condition); the gate is named so a STRICT run can be compared. REAL means the GPU call is unconditional in a GPU-only function, or sits behind a residency test on device inputs. CHUNK means the loop runs a handful of iterations over large vectorised work. Size-aware gates (`_cmi_gpu_enabled` -> `fe_gpu_strict_enabled(n, p)`, documented as AUTO at scale) can open at production size, so the FALSE_POSITIVE labels below hold for small and default runs.

Repeating false-positive shapes:
1. A host-mode function calls a helper whose cupy branch is behind a config gate (`_cmi_gpu_enabled`, `_gate_cands_resident()`, `fe_gpu_strict_resident_enabled()`). The detector counts the helper's cupy calls and ignores the gate. This is the largest group (about 13 keys).
2. An `xp` or `cp` parameter that every caller binds to numpy, so the "cupy" calls are numpy calls (keys 34, 36).
3. An env flag whose default returns early before the cupy loop (key 31).
4. A prewarp or spec branch in a callee that skips the cupy quantiser for every survivor the caller builds (key 19).
