## FALSE_POSITIVE shapes the detector could recognise

1. Env-forced GPU arm in a dispatcher: the cupy branch runs only under `if forced == "cuda"` (keys 9, 10, 37). Every caller of the dispatcher is flagged, so the detector could skip callees whose cupy calls sit under an env-equality guard that defaults to off.
2. Default-off feature-flag arm: a loop-invariant `if x is not None` on a value set only by an opt-in flag, with the cupy-resident table used only in that arm (keys 21, 23).
3. Host-only flag at the call site: a `host_only=True` argument keeps the callee on the CPU, but the callee's cupy branch is still counted (keys 24, 22).
4. Early GPU return before the loop: the function tries cupy, returns on success, and the flagged loop is the fallback. The cupy calls are not inside the loop body (keys 39, 41).
5. Nested sibling closure: a `_cpu` closure's loop is attributed the cupy calls of a sibling `_gpu` closure in the same enclosing function (key 40). Scoping cupy calls to the closure that contains them would remove this.
