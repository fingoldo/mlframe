# Config, defaults and public API contracts — audit 2026-09-20

Scope: `src/mlframe/config.py`, `src/mlframe/training/configs.py` and the sibling `*_config*` modules, the public entry point `train_mlframe_models_suite` (and its kwargs), the predict entry points in `src/mlframe/inference/predict.py`, the sklearn-facing estimators, and every `MLFRAME_*` env-var switch under `src/` — excluding `src/mlframe/training/composite/`. The audit favoured defaults that silently degrade results over ones that error. Every claim below was proven from source or reproduced with a snippet against the installed interpreter; unproven suspicions were dropped. The dominant pattern found is not a broken algorithm but **contract drift**: config fields that are declared, documented and validated but read nowhere; docstrings whose stated default is the opposite of the code default; and one default-ON step that mutates shipped regression predictions while both its own class docstring and the suite's public docstring call it opt-in/OFF.
