# Performance audit - wall-clock cost and caching (2026-09-20)

Scope: the whole package EXCEPT `src/mlframe/training/composite/` (separate audit). Everything below was measured on this box (Windows 10, `D:/ProgramData/anaconda3/python.exe`, GTX 1050 Ti, numba.cuda + cupy both present).

What was measured: (a) process startup - `python -X importtime` and wall-clock `perf_counter` around `import mlframe.<subpackage>`, plus a 4-worker `joblib.Parallel(backend="loky")` job whose task body imports the FE module, i.e. exactly what loky does when it unpickles a `delayed()` bound to that module; (b) a full `MRMR().fit` under `cProfile` on a synthetic `n=20000 x p=60` float frame with a 3-driver binary target (`max_runtime_mins=1.0`, 71.0 s wall) to locate fit-side hotspots and verify the memoisation in the conditional-gate / orth-basis FE stages actually hits; (c) targeted `perf_counter` A/Bs on synthetic pandas frames for the incremental-`pd.concat` and per-column-permutation patterns found by grep; (d) grep-proof for caches with no live caller.

Headline: the fit path of `feature_selection` is in very good shape - the cProfile top line is `_plugin_mi_classif_batch_njit` at 17.16 s tottime / 589 calls (24% of the fit), i.e. real kernel work, and the memoised closures around it (`_baseline_cache`, `_zmap_cache`, `_DY_DEVICE_CACHE`, `_OPERAND_TABLE_CACHE`) were each inspected and do hit. The wins left are all on the **import/startup** side, and they are large: a loky FE worker spends **36.4 s importing mlframe before it does any work**.

Checked and found **clean** (no finding raised, recorded so the next audit does not re-walk them):

- `data_valuation/_knn_shapley.py:119` `Parallel(backend="threading")` genuinely scales - n_jobs 1/2/4/8 -> 0.978/0.595/0.466/0.359 s at `n_train=4000, n_val=2048` (2.7x at 8), so it is not GIL-bound.
- `_conditional_gate_fe.py:679` `_baseline` is memoised per operand set and `:787` `_add`/`_flush` batch to a 512-column budget; the cProfile call counts (430 baseline calls for 781 queued specs) confirm the memo hits.
- `_fe_auto_escalation.py:215` `key = id(fit_fn)` keys on the module-level `_POLY_BASES[basis]["fit"]` object, which is stable - the cache hits.
- `batch_mi_noise_gate_gpu.py:388/432` and `_gpu_resident_materialise.py:390/432` id()-keyed caches all carry a co-validating weakref, so id-recycle cannot false-hit.
- `boruta_shap/_shadow_stats.py:163` already has a same-dtype 2-D fast path ahead of the per-column `.apply`.
- `feature_selection/filters/stability.py:206` nested-joblib oversubscription risk is inert: `n_jobs` defaults to 1, so no outer thread pool wraps the inner estimator's own pools.
- `_phase_train_one_target_pre_screen.py:33` is correctly gated by `ctx._pre_screen_done` to run once per suite, not once per target.
- `feature_engineering/panel_pivot.py:95` already pivots all value columns in one call (bench note in place).

- **Disposition**: PARTIAL - PRF-01, PRF-02, PRF-07 RESOLVED, the remaining 4 are TODO.
