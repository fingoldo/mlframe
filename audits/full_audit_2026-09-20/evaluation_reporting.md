# Evaluation and reporting audit (numbers and verdicts)

Scope: `src/mlframe/evaluation/`, `src/mlframe/reporting/` (diagnostics dispatch, catalog, auto-dispatch, report assembly), `src/mlframe/training/reporting/`, `src/mlframe/training/evaluation.py`, `src/mlframe/inspection/`, `src/mlframe/data_valuation/`. Chart rendering aesthetics (axes, colours, layout) were audited separately and are excluded here. The bias of this pass is towards diagnostics that print a confident number that is wrong, rather than ones that crash: a crashed panel is visible in the log, a mis-scaled threshold or an unranked "top-N" is not. Sixteen findings follow. Three are verdict-level (a gate whose scale does not match the statistic it gates, a flag that fires on a selection extremum with no multiplicity correction, a "top-K by importance" list built from frame order), several are truthfulness-of-accounting issues (a memoisation that never hits but is documented as saving seconds, a catalogue that cites a test which does not exist, budget skips that never reach the metrics dict), and the rest are statistical claims the code does not compute. EVR-01 was verified by running the code; the rest are proven from the source lines quoted.

| Med | EVR-09 | `importance_vs_generalization_correlation` is documented as a correlation of importance **rank** against the delta but is computed on the raw gain importances; and when either series is degenerate the function returns `0.0`, which is exactly the value the docstring reads as confirming the source finding. | `src/mlframe/evaluation/adversarial_feature_audit.py:72` `"(Pearson correlation between adversarial importance rank and ``private_auc_delta_when_dropped``"`; `:147-152` `imp_vals = np.array([a["adversarial_importance"] ...])` ... `else: correlation = 0.0` | LightGBM gain importances are extremely heavy-tailed; a Pearson correlation on raw gains is dominated by the single top feature and is not the rank correlation the docstring names. | Med | EVR-10 | `weighted_<metric>` silently degrades to an unweighted mean when class supports could not be derived, and both `macro_`/`weighted_` aggregates are applied indiscriminately to every scalar in the per-class block, including p-values and degrees of freedom. | `src/mlframe/training/reporting/_reporting_probabilistic.py:704` `metrics[f"weighted_{key}"] = float((arr * w).sum() / w_total) if w_total > 0 else float(arr.mean())`; weights default at `:696` `wts.append(_supports.get(cid, 1))` (populated only when `_yt_all is not None and _yt_all.ndim == 1`); key set at `:684` `_all_keys.add(k)` for every numeric key, which includes `HL_p`, `HL_dof`, `Spiegelhalter_p`, `base_rate`. | A reader compares two multiclass models on `weighted_MCC` believing it is prevalence-weighted; on a run where the target could not be cast to a 1-D int array it is the macro mean, reported under the same key with no marker. | Med | EVR-11 | `CVDeltaHistory` pools the *baseline's* fold scores on every `triage_cv_delta` call. | Med | EVR-12 | The Friedman-Popescu H² is clamped into `[0, 1]`; the raw ratio genuinely exceeds 1 when strong main effects sit on a weak joint PD surface, so a degenerate pair is reported as maximal interaction. | `src/mlframe/inspection/interaction.py:117` `h2 = min(max(numer / denom, 0.0), 1.0)`; docstring at `:11` states `H = sqrt(H²) ∈ [0, 1]` as a property, not a clamp. | A pair whose joint partial dependence is nearly flat while each feature has a large additive effect produces `numer/denom > 1`, is clamped to `H = 1.0`, and lands at the top of the `interaction_strength` heatmap - the reader engineers an explicit interaction feature for a pair the model treats additively. | Return `nan` (or flag the entry) when the raw ratio exceeds 1 or when `denom` is small relative to `sum(c_i**2) + sum(c_j**2)`, and say in the docstring that the bound is a convention, not an identity. |

| EVR-01 | RESOLVED | The cache is keyed on the arrays the CALLER holds plus the trimmed row count, instead of on views each entry point had just built, so the second diagnostic hits. Pinned by `tests/reporting/test_diagnostics_prep_cache_hits.py` (one entry and the same sub-frame object for two calls). |
| EVR-02 | RESOLVED | The verdict is relative to the honest mean's own magnitude (2% by default, `leak_tolerance` for an absolute gate), with the fold-score spread standing in when the honest mean is zero; the band used is reported as `leak_tolerance` and a signed-rank `leak_pvalue` accompanies it as consistency evidence.
