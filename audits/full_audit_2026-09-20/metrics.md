# Metrics & calibration audit - 2026-09-20

Scope: `src/mlframe/metrics/**` (core, classification, regression, ranking, calibration kernels, `_ice_metric.py`, numba kernels), `src/mlframe/calibration/**` and `src/mlframe/training/metrics_registry.py`. The audit deliberately favoured metrics that silently report the WRONG NUMBER over metrics that crash. The headline result is that **the same (y_true, y_pred) produces three different ICE values** depending on which of the three "bit-identical" ICE paths runs - the batched per-class kernel that backs the CatBoost/LightGBM `eval_metric`, `fast_ice_only`, and `fast_calibration_report` - because the batched kernel bins to the bin CENTRE instead of the per-bin mean prediction, and the report defaults to a base-rate-dependent binning strategy the other two never use. Every numeric claim below was reproduced with a runnable snippet against the installed package; where a finding is analytic (no counter-example run) that is stated.

| Sev | ID | Finding | Evidence (file:line + quote) | Failure scenario | Suggested fix |
|---|---|---|---|---|---|
| CRITICAL | MET-01 | The batched per-class ICE kernel - the DEFAULT fastpath of `compute_probabilistic_multiclass_error`, i.e. the CatBoost/LGB `ICE` eval metric - sets each bin's predicted frequency to the BIN CENTRE, while the reference binner uses the per-bin MEAN prediction and explicitly documents the centre as wrong. Its docstring claims bit-exactness. It also mixes widths: the assignment multiplier is `(nbins-1)/span` but the centre is computed with width `span/nbins`. | `metrics/classification/_ice_kernel.py:134` `freqs_pred[ptr] = min_val + (b + 0.5) * span / nbins`; contrast `metrics/calibration/_calibration_plot.py:281` `freqs_predicted = pockets_pred_sum[idx] / hits` and its :217 note "The bin centre is wrong-width and biases the reliability x-positions (and the downstream calibration_mae)"; false claim at `_ice_kernel.py:52` "Bit-exact equivalent of looping ``fast_ice_only`` per class". | n=5000, `p~Beta(2,5)`, `y~Bernoulli(p)`, nbins=10: `fast_ice_only` = **-0.147748**, batched kernel = **-0.091652** (abs gap 0.0561, 38% relative). | HIGH | MET-02 | `fast_calibration_report` bins with `binning_strategy="auto"` (quantile when base rate < 10%, uniform otherwise) while `fast_ice_only` and the batched kernel always bin uniform - yet `fast_ice_only` documents itself as bit-exact vs the report. | HIGH | MET-03 | ICE replaces a NaN in each LOSS term with 0.0 - the best possible value for a lower-is-better metric - so a model whose Brier/calibration is not computable outranks one whose is. | `metrics/calibration/_calibration_metrics.py:481-485` `brier_term = 0.0 if np.isnan(brier_loss) else brier_loss * brier_loss_weight` ... `base_loss = brier_term + mae_term + std_term + cov_term` | `fast_brier_score_loss` returns NaN for ANY probability outside [0,1] (`_core_brier.py:49`). | HIGH | MET-04 | `ICE.evaluate` returns the literal `0` as its skip sentinel regardless of `self.higher_is_better`, and discards CatBoost's `weight` argument entirely although the protocol supplies it. | `metrics/_ice_metric.py:412` `output_weight = 1  # weight is not used`; :416 `return 0, output_weight`; :420 `return 0, output_weight` | For the normal lower-is-better wiring, `0` is the BEST achievable ICE: if the eval set exceeds `max_arr_size`, every iteration scores 0, early stopping never sees an improvement and the model is kept at iteration 1. With `higher_is_better=True` the same sentinel is the worst value. Separately, a fit with `sample_weight` reports an unweighted ICE while the trainer believes it is weighted. | Return a direction-aware sentinel (`+inf`/`-inf` per `higher_is_better`) or skip via CatBoost's own mechanism; either honour `weight` in the metric or raise when a non-uniform weight vector arrives. |
| MEDIUM | MET-05 | The uniform binner maps scores with `multiplier = (nbins - 1) / span`, so bin width is `span/(nbins-1)` and the LAST bin captures only the exact maximum - the grid is not the equal-width grid the docstring promises, and `calibration_coverage` is computed against the nominal `nbins`. | `metrics/calibration/_calibration_plot.py:255` `multiplier = (nbins - 1) / span`; :241 docstring "bucket predictions into ``nbins`` equal-width pockets over the observed prediction range" | n=200 uniform scores: nbins=10 gives hits `[20 25 16 28 17 25 18 21 29 1]` - the last pocket holds a single row whose `freqs_true` is 0 or 1, contributing a near-1.0 gap to CMAEW. nbins=2 puts ALL 200 rows in ONE bin (`populated=1`) so CMAEW is computed from a single point and coverage reports 50%. | Use `multiplier = nbins / span` with the existing `ind >= nbins` clamp for the max value; re-baseline the CMAEW/coverage expectations. |
| MEDIUM | MET-06 | Two RMSLE implementations in the same repo disagree on the negatives rule: `metrics.scoring.rmsle_loss` CLIPS negatives to 0 (keeping them in the denominator), `metrics.regression.fast_rmsle` SKIPS them (shrinking the denominator to `used`). | `metrics/scoring.py:96` `np.sqrt(np.mean(np.power(np.log1p(np.clip(y_true, 0, None)) - np.log1p(np.clip(y_pred, 0, None)), 2)))` vs `metrics/regression/_regression_extras.py:66-73` `if yt < 0.0 or yp < 0.0: neg += 1; continue` ... `return sqrt(s / used), neg` | A target with 10% negative rows scored by the scorer (`rmsle_score`) and by the registry metric `rmsle` returns two different numbers; the skipping variant also averages over a subset, so a model that pushes more rows negative is rewarded with a smaller denominator. | MEDIUM | MET-07 | `estimate_calibration_quality_binned` reports `"CRPS"` and `"R2"` computed on the ~20 BINNED pockets, not on the samples, while `crps`'s own docstring advertises per-observation CRPS; the pocket mean is also unweighted although the last pocket absorbs the remainder. | `calibration/quality.py:89-93` "Computes mean Continuous Ranked Probability Score of true binary outcomes versus predicted probabilities"; :313 `fname: (f(y_true, y_pred) if f is fast_brier_score_loss else f(pockets_true, pockets_predicted))`; :247 `if i == nbins - 1: r = s` | With `crps_ensemble` fed two length-20 vectors the result degenerates to the mean absolute reliability-curve gap, reported to the operator under the name "CRPS" - roughly an order of magnitude below a real per-sample CRPS on the same data. n=199, nbins=20: pockets hold 9 rows each except the last with 28, all weighted equally in that mean. | Rename the binned entries (e.g. `CRPS_curve`, `R2_curve`) or compute CRPS on the raw pairs; weight the pocket aggregation by `data[:, 2]` (count). |
| MEDIUM | MET-08 | The DEFAULT headline ECE debiases the SQUARED gap and then takes a square root, `sqrt(max(g^2 - Var, 0))`. Because `sqrt` is concave and the term is clamped at 0, the estimator is biased DOWNWARD and hard-zeroes any bin whose true gap is below the per-bin noise scale. | `metrics/calibration/_calibration_metrics.py:232-235` `corrected = gap * gap - var_acc` ... `if corrected < 0.0: corrected = 0.0` ... `ece += w * np.sqrt(corrected)`; default wired at `_classification_report.py:224` `ece_debiased: bool = True` | Analytic + arithmetic: a bin with `acc = 0.5`, `n_b = 50` has `Var = 0.0051`, so every true gap below `sqrt(0.0051) = 0.0714` is reported as exactly 0. A model miscalibrated by 5 percentage points in every bin (n=500, nbins=10) reports headline ECE 0.000 - "perfectly calibrated". | Debias on the squared scale and report `sqrt` of the SUM (a debiased L2 calibration error), or keep the plug-in ECE as the headline and expose the debiased value beside it with the zero-floor documented. |
| MEDIUM | MET-09 | PSI / KL / JS bin via `np.histogram`, which silently drops non-finite rows, and then renormalise to 1 - so a change in the NaN rate is invisible and the remaining mass is rescaled as if nothing moved. | `metrics/_drift.py:89-91` `counts, _ = np.histogram(x, bins=edges); return counts.astype(np.float64)`; :148-149 `q = _bin_counts(tgt, edges); q /= q.sum() if q.sum() > 0 else 1.0` | Verified: `np.histogram([1, 2, nan, nan], bins=[-inf, 1.5, inf])` returns `[1 1]` - the two NaNs vanish. | LOW | MET-10 | `compute_mean_aucs_per_group` averages per-group AUCs with equal weight regardless of group size, and the report renders that number beside the pooled AUC without saying so. | `metrics/_auc_per_group.py:212-213` `mean_roc_auc = np.mean(group_roc_aucs[valid_roc]) if np.any(valid_roc) else np.nan` | One 4-row group whose AUC is 1.0 by luck offsets a 10,000-row group at 0.60 exactly one-for-one; the bracketed `[mean_group_roc_auc]` in the chart title (`_calibration_plot.py:157`) then reads better than the model is. | Offer a support-weighted mean (or return both) and label the title token as the unweighted per-group mean. |
| LOW | MET-11 | Quantile losses return 0.0 on empty input - the BEST value for a lower-is-better metric. | `metrics/quantile.py:58-59` `if n == 0: return 0.0` (pinball); :115-116 (Winkler); :100-101 (coverage) | An empty holdout slice (aggressive outlier filtering / an empty group in a per-group loop) scores pinball 0.0 and Winkler 0.0 and wins any `min()` model/threshold selection over every model with real data. | Return `np.nan` on `n == 0`, matching `fast_rmsle` / `fast_brier_score_loss` elsewhere in the package. |
| LOW | MET-12 | `fast_roc_auc` does not normalise labels (`tps += y_true[i]`, `fps += 1 - y_true[i]`), while its sibling `fast_roc_curve` explicitly does (`y_true == 1`). | `metrics/_core_auc_brier.py:768-769` `tps += y_true[i]` / `fps += 1 - y_true[i]`; contrast :688 `y_true = np.ascontiguousarray(np.asarray(y_true) == 1, dtype=np.float64)` | Verified n=1000: with {0,1} labels `fast_roc_auc` = 0.93123 = sklearn; with the same data relabelled {-1,1} it returns **nan** while sklearn still returns 0.93123. | LOW | MET-13 | `fast_log_loss`'s clipping eps defaults to the machine eps of `y_pred`'s DTYPE, so the same predictions scored as float32 and float64 give different log losses. | `metrics/_log_loss_and_separation.py:169-171` `if eps is None: eps = float(np.finfo(y_pred.dtype).eps)` | A float32-predicting model (many NN/booster paths) is clipped at 1.19e-7 and a float64 model at 2.22e-16; a single confidently-wrong row moves LL by ~`(16.2 - 9.0)/n` between the two arms. ## Dispositions

| ID | Status | Note |
|---|---|---|
| MET-01 | RESOLVED | Both batched kernels accumulate `pockets_pred_sum` and score a bin at its MEAN prediction, as the serial reference does; the "bit-exact" docstring claim now names the test that holds it. Pinned by `tests/metrics/test_ice_kernel_parity.py`. |
| MET-02 | RESOLVED | `fast_ice_only` takes `binning_strategy` and defaults to `"auto"`, the report's own default; `ICE.evaluate` only takes the uniform-only batched fastpath when `resolve_binning_strategy` returns `"uniform"` for every scored class. Pinned by `tests/metrics/test_ice_binning_consistency.py`. |
| MET-03 | RESOLVED | A NaN in any LOSS term returns the finite worst value `ICE_UNCOMPUTABLE = 1e6` instead of 0.0 (CatBoost rejects a non-finite custom metric value, so the sentinel cannot be `inf`). Reward terms keep the 0-substitution, where 0 is the worst. Pinned by `tests/metrics/test_ice_uncomputable_sentinel.py`. |
| MET-04 | PARTIAL | The skip sentinel is direction-aware (`-ICE_UNCOMPUTABLE` when `higher_is_better`), and a non-uniform `weight` vector is announced once per fit instead of being silently dropped. Raising instead was tried and reverted: it killed fairness / inverse-frequency weighted CatBoost fits (`tests/training/feature_selection/test_bizvalue_fairness_weights.py`), which are a supported path. **Open**: the ICE kernels still score every row equally, so a weighted fit early-stops on an unweighted number - making them weight-aware is the remaining work. Pinned by `tests/metrics/test_ice_skip_largest_set.py` and `tests/metrics/test_ice_sample_weights.py`. |
