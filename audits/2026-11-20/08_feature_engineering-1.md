## Checked, no finding

- `_oof.py:158-174`: per-fold standardiser and PLS/importance/SHAP/NCA projection refit use only `train_idx` rows, so the outer validation fold does not leak into the projection.
- `_baseline_oof.py:37-53` (`kfold_splits`): group-aware GroupKFold is used when at least two groups exist, with a warning and a shuffled-KFold fallback otherwise. The inner fold partition covers all rows.
- `_residual_oof.py:19-51`: the aux OOF for each outer fold uses only that fold's complement rows, which avoids the cross-fold leak its docstring describes.
- `_utils.py:162-199` (`validate_numeric_input`): rejects non-finite cells, bool and non-numeric dtypes, sparse input and d > 32768 before any math runs, as documented.
- `_aggregation.py:227-234`: the degenerate-softmax fallback to uniform 1/k is applied consistently to all rows that are non-finite or sum to zero.
- `_row_attention_ann.py:219-223`: the pynndescent `query` return order (indices, distances) is mapped to `(labels, distances)` correctly.
- `anomaly_score_features.py:58`: the disagreement std `|s1 - s2| / 2` is the correct population std for two values.
- `_key_bank.py:288-301`: the cache write goes to a UUID temp directory and is renamed atomically onto the content-addressed directory, and a loser of the race cleans up its temp.

Not verified: possible `fastmath=True` interaction with the `np.isfinite` guards in `_kernels_njit.py:44` and `:54`. This would need a compiled-kernel test and is not reported as a finding.
