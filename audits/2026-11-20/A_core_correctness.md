### F01 - Single-slot content-hash memo returns a stale digest when id(X) is reused

- **Severity**: High
- **Location**: `src/mlframe/feature_selection/filters/_mrmr_fingerprints.py:579` (`_full_x_content_hash`, numpy/pandas branch) and `:615` (`_full_named_frame_hash`, pandas/polars branch); consumed by `_fit_cache_key` in `_mrmr_fit_impl/_fit_impl_stages/_fit_cache.py:121`.
- **Problem**: The memo that short-circuits the full blake2b digest is keyed on `(id(X), shape, _content_array_signature(X))`. `_content_array_signature` samples only 1024 strided positions. The full-content hash exists precisely because two frames can agree on those sampled cells (the docstring names a column-wise outlier clip as the case). When the earlier frame is freed and CPython reuses its address for a new frame of the same shape, the memo key matches and the function returns the old frame's digest without hashing the new bytes. The memo was added as an intra-fit optimisation but its key cannot distinguish a recycled id from the same object.
- **Failure scenario**: Loop: `fit(X1)` where X1 is 5000x30 float64. Then `del X1`; build `X2 = winsorise(X1_copy)` that changes only extreme cells outside the 1024 sampled positions, same shape and column names. CPython reuses the id of the freed frame. `_full_named_frame_hash(X2)` (or the numpy branch) finds `id_shape` equal and returns X1's digest. `_fit_cache_key` then builds the same key as the X1 fit (the `_x_sig` is also strided and equal), and `MRMR.fit(X2)` replays X1's `support_` and `selected` columns without scoring X2. No exception, no log line.
- **Suggested fix**: Do not key the memo on id. Hold a `weakref.ref(X)` in the slot and compare `ref() is X` (the pattern `_HASH_MEMO` and `_RESIDENT_CODES_HANDOFF` already use), or drop the memo and always hash. Add a regression test: two frames of equal shape where the first is freed and the second differs in one unsampled cell; assert the keys differ.
- **Disposition**: FIXED 2026-11-20 - the single-slot memo holds a weak reference to X and a hit needs it to resolve to the very object (`_x_hash_memo_hit` / `_x_hash_memo_store` in `_mrmr_fingerprints.py`); sensor `test_memo_slot_of_another_object_with_the_exact_key_is_a_miss` fails on the old code.

### F02 - Prefer-engineered substitution drops the add-one budget ceiling, so the child gain is deflated against the raw parent path

- **Severity**: Medium
- **Location**: `src/mlframe/feature_selection/filters/_confirm_predictor.py:467` (`_sub_gain = _child_gain * _child_conf`), contrasted with `_confirm_predictor_helpers.py:370-372` (`_conf_for_gain = _confirm_one_predic_add_one_disabled_ceiling(...)`) and `_confirm_predictor_helpers.py:421-427`.
- **Problem**: The normal confirmed path multiplies the gain by a budget-aware confidence: the add-one p-value ceiling `budget/(budget+1)` is divided out, so a clean null keeps 1.0. The comment there says explicitly that without this a clean signal is deflated about 25% at the default `full_npermutations=3`. The substitution path (a confirmed engineered child that wins a near-tie against its raw parent) multiplies by the raw `_child_conf` with no ceiling correction. The two paths therefore score the same kind of confirmed candidate on different scales, and the substitute is the one that gets deflated.
- **Failure scenario**: `full_npermutations=3`, add-one enabled, so the ceiling is 0.75. A genuine engineered child has expected gain 0.0105 with `min_relevance_gain=0.01`, and a clean-null confidence of 0.75 (the ceiling). Substitution stores `_sub_gain = 0.0105 * 0.75 = 0.0079`, which fails `_best_gain_for_gate >= _abs_floor`. The gate breaks the selection loop (`_screen_predictors_steps.py`, else branch). The raw parent was already added to `added_candidates`, so neither feature is selected and screening stops, while the same child through the normal path would have passed.
- **Suggested fix**: Route the substitution through `_confirm_one_predic_add_one_disabled_ceiling(full_npermutations, child_conf, child_conf)` the same way the normal path does, and add a test that a clean-null child substitution with `full_npermutations=3` passes the gate when its expected gain is above the floor.
- **Disposition**: OPEN

### F03 - SU-normalised marginal relevance is compared against an MI-unit maxT floor

- **Severity**: Medium
- **Location**: `src/mlframe/feature_selection/filters/evaluation.py:669-670` (`direct_gain = _su_normalize_relevance(...)`, `cached_MIs[X] = direct_gain`); consumed in `_screen_predictors_gate.py:199-212`; floor built in `_permutation_null.py:310-460` (raw MI histograms).
- **Problem**: With `mi_normalization='su'` (opt-in; default is `"none"`), `cached_MIs[X]` holds the SU-scaled relevance `2*MI/(H(X)+H(Y))`. The gate reads that value as the candidate's "corrected marginal MI", subtracts the nat-unit Miller-Madow term `(k_x-1)(k_y-1)/(2n)` from it, and compares it to `fdr_gain_floor`, which `pooled_permutation_null_gain_floor` computes from raw MI maxima. The statistic and the null are in different units, so the maxT test is not the one the comment describes.
- **Failure scenario**: `mi_normalization='su'`, the raw-MI maxT floor is 0.02 nats. A pure-noise column with raw MI 0.004 nats and a low-entropy pair (H(X)+H(Y)=0.2, so SU factor 10) has SU 0.04 and passes the 0.02 floor it should fail. A genuine weak signal with raw MI 0.03 nats and H(X)+H(Y)=3.0 (SU factor 0.67) has SU 0.02 and fails the same floor it should pass. The floor is then neither a chance ceiling nor scale-consistent for SU-mode fits.
- **Suggested fix**: In the SU branch, compare the raw MI (store it alongside, or divide the floor by the same SU factor per candidate), and apply the Miller-Madow term in the same units as the floor. Add a test pinning both the SU and the MI scale for the same fixture.
- **Disposition**: OPEN

### F04 - maxT FDR gate silently passes a candidate whose marginal MI is missing from the cache

- **Severity**: Low
- **Location**: `src/mlframe/feature_selection/filters/_screen_predictors_gate.py:199-201` (`_cand_marg_raw = cached_MIs.get(best_candidate, None)`; `if _cand_marg_raw is not None:` ... `_fdr_pass` stays `True`).
- **Problem**: The FDR floor exists to reject chance-max noise on wide pools. When the lookup misses, the branch is skipped and `_fdr_pass` defaults to `True`, so the floor is bypassed with no log line, warning or counter. A miss is not expected for normal flow, but the cache is seeded across rounds and by the cross-round `cached_confident_MIs` branch, which does not write `cached_MIs[X]` (`evaluation.py` around line 562), so the invariant is not enforced anywhere.
- **Failure scenario**: A round-2 candidate that re-enters through `cached_confident_MIs` with no `cached_MIs` entry (for example after a cache reset at a DCD commit or a changed `seed_caches` path). On a wide pool of 400 columns of pure noise, the best noise column clears the abs and relative floors and is accepted, with the maxT floor reporting 0.02 nats but never consulted. Nothing in the log shows the bypass.
- **Suggested fix**: Treat a missing marginal on an order-1 candidate with a non-zero floor as a fail-closed case, or compute the marginal on demand (`cached_MIs` is cheap to fill). At minimum log a `log_throttle` warning when the floor is active and the lookup misses, and add a test that asserts the lookup never misses for a candidate that reached the gate.
- **Disposition**: OPEN

### F05 - Miller-Madow correction of the conditional gain uses nominal bin counts, while the FDR path in the same gate moved to occupied-level counts

- **Severity**: Low
- **Location**: `src/mlframe/feature_selection/filters/_screen_predictors_gate.py:136-145` (abs floor: `(_nbins_x_eff - 1) * (_nbins_y - 1)` with `factors_nbins`), `:165-173` (relative floor, same nominal count); compare `:203-210` (FDR path uses `_occupied_levels`, with a comment that says a nominal correction "let a pure-noise column with a heavy-tailed occupancy clear it").
- **Problem**: The same gate corrects the same candidate's MI two ways. The absolute and relative floors subtract a Miller-Madow term built from the nominal number of bins, which over-corrects sparse heavy-tailed columns (the `_permutation_null.py` Idea-#9 comment records the same defect for the floor). The FDR branch was fixed to use occupied levels for this reason, but the abs/rel branches were not. A candidate can therefore be rejected by the abs floor on a bias that the FDR path has already decided is not real.
- **Failure scenario**: Binary target, n=2000, `min_relevance_gain=0.003`. A column with 16 nominal bins and 8 occupied bins and a true conditional gain of 0.0030 nats: nominal correction gives bias `15*1/4000 = 0.00375` and corrected gain -0.00075 (rejected). Occupied correction gives bias `7/4000 = 0.00175` and corrected gain 0.00125, which is still below the floor here. Use gain 0.0060: nominal gives 0.00225 (accepted), occupied gives 0.00425 (accepted). Narrowing the gap so the decision flips needs a specific gain between the two corrected values, so the defect is real but its selection effect is limited to a narrow band.
- **Suggested fix**: Use the same occupied-level correction in the abs and relative branches (compute `_occupied_levels` once per candidate and reuse it), and state the convention in one place. Add a test with a sparse heavy-tailed column that sits in the flip band.
- **Disposition**: OPEN
