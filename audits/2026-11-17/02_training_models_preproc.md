# Audit 02: training, models, preprocessing (MRMR excluded)

Scope was targeted, not exhaustive. I swept for broad `except`, non-atomic writes, process-global caches and fit/transform leakage across about 230k LOC, then read the hit paths.

| ID | file:line | finding | disposition | reason/test |
|----|-----------|---------|-------------|-------------|
| A1 | src/mlframe/training/baselines/_dummy_baseline_compute.py:~113 | `_to_pandas_for_baseline` cached the pandas view under `id(X)` and validated a hit only by columns and shape. After GC a new frame with the same schema and row count reuses the id, and the old frame's view was returned. Dummy baselines were then computed on the wrong data, with no error. The comment claiming polars frames cannot be weak-referenced is false. | RESOLVED | Each cache entry now stores a weakref to X (or a pinning closure if X is not weak-referenceable), and a hit requires `ref() is X`. Test: tests/training/test_to_pandas_baseline_cache_id_recycle.py |
| A2 | src/mlframe/training/ranking/_ranker_suite_train_helpers.py:~501 | The ranker `*_metadata.json` was written with `open(..., "wb")` and the serialisation ran after the truncate. A serialisation error or a crash left an empty or partial file and destroyed the previous good one. Model artefacts in the same function already use `atomic_write_bytes`. | RESOLVED | The write now goes through `atomic_write_bytes`. Test: tests/training/test_ranker_metadata_json_atomic.py |
| A3 | src/mlframe/training/pipeline/_event_proximity_decay_composite_fe.py:94, _ma_crossover_composite_fe.py:121, _nearest_past_join_composite_fe.py:94 | The per-split `except Exception` keeps the unmodified frame for the failed split only.
