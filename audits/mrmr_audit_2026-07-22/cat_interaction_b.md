# cat_interaction_b — temporal / grouped-aggregate / interaction-seeder FE cluster

## Scope

Thirteen files under `src/mlframe/feature_selection/filters/`, all pure-CPU/optional-CUDA feature-engineering
families feeding MRMR's FE pipeline: leak-safe temporal expanding/rolling/lag aggregates (`_temporal_agg_fe.py`
+ `_temporal_agg_fe_rolling.py`), two interaction *seeders* that widen the pair/triplet candidate pool via a
surrogate model (`_surrogate_interaction_seeder.py` GBM split-co-occurrence, `_gradient_interaction_seeder.py`
mixed-second-partial energy), a semi-supervised unlabeled-pool augmentation wrapper for the orth-poly basis
family (`_semi_supervised_fe.py`), single/composite-key grouped aggregation families (`_grouped_agg_fe.py`,
`_composite_group_agg_fe.py`), quantile-cell and distribution-distance families (`_grouped_quantile_fe.py`,
`_group_distance_fe.py`, `_binned_numeric_agg_fe.py` + its GPU-resident twin `_binned_numeric_agg_resident.py`),
and closed-form arithmetic FE (`_numeric_decompose_fe.py` rounding/digit-extraction, `_ratio_delta_fe.py`
ratio/grouped-delta/lagged-diff). Confirmed by direct inspection: **no DB/network/UI surface exists anywhere in
this cluster** — every file is pure numpy/pandas(+optional cupy/numba) arithmetic; no eval/exec/subprocess/
os.system/pickle/yaml.load anywhere (`grep` came back empty except one docstring mention of "pickled fitted
state", not an actual pickle call). GPU code exists only in `_binned_numeric_agg_fe.py` (a small STRICT-resident
cheap-MI probe) and `_binned_numeric_agg_resident.py` (the full device-born OOF-matrix + MI-gate twin); the
other eleven files are CPU-only by design, confirmed via grep for `cupy`/`cp.`/`resident_operand`/GPU env vars
(zero hits). mypy (`--cache-dir=.mlframe_mypy_cache_shared --ignore-missing-imports`) is clean on all 13 files —
no errors. Three prior-audit findings against files in this cluster were verified against current code:
`_temporal_agg_fe.py`'s look-ahead leak (FE-F1), the raw-`.astype(str)` entity-key int/float drift (FE-F2), and
the ns-precision float64 cast (FE-F5) are all **fixed** (the leak-safe merge-by-timestamp code, `group_key_strings`
routing, and int64 time axis are present in the current file). `_grouped_quantile_fe.py`'s small-group OOF
fallback y-leak (FE-F3) is also **fixed** (fold-local `fold_global_edges` now fit train-only). The dead two-dot
`from .._grouped_agg_fe import ...` in `_composite_group_agg_fe.py` (prior c7c finding) is **still open**. Five
new P1 bugs were found and confirmed by direct execution (not hand-waved): a hard crash on a documented-valid
rolling stat, a systematically-wrong out-of-distribution fallback value for two default-adjacent stats spanning
two files, a silent-exception-swallow inconsistent with its sibling proposer, a source-column-naming footgun
that silently orphans recipes for selected features, and a complete absence of entity-scoping in the lagged-diff
family (unlike its near-identical Layer-92 sibling).

## Proposals

- **Fix the count/nunique fallback class-wide (CAT_INTERACTION_B-2):** replace the whole-population `count`/`nunique` global fallback with a scale-consistent estimate — e.g. the median (or mean) PER-GROUP count/nunique across all fit-time groups — in both `_grouped_agg_fe._global_value_for_stat` and `_composite_group_agg_fe._global_value_for_stat`. This is a one-line change per file (swap `finite.size` / `np.unique(finite).size` for a per-group-scale aggregate already computable from the `agg_series`/`mean_series` groupby result at fit time) and removes a default-on out-of-distribution artifact.
- **Add an entity_cols parameter to lagged_diff (CAT_INTERACTION_B-5):** mirror `_temporal_agg_fe.generate_lag_features`'s per-entity ring-buffer pattern (or simply `groupby(entity_cols)` before the time-sort) so `lagged_diff` is safe on panel data by default; keep the current global behavior as an explicit opt-out for genuinely single-series data.
- **Harden `_parse_engineered_name` (CAT_INTERACTION_B-4):** rsplit-based parsing anchored on the KNOWN suffix pattern (`__round_...`/`__digit_...`) rather than a first-`"__"` split — e.g. `name.rsplit("__", 1)` combined with validating the prefix, or carry the source column name through the pipeline explicitly instead of re-deriving it from the string, which would make the recipe-building step immune to source-name collisions entirely.
- **Unconditional exception logging in `_gradient_interaction_seeder.py` (CAT_INTERACTION_B-3):** change both `if verbose: logger.warning/info(...)` sites to unconditional `logger.debug(..., exc_info=True)` (matching the file's OWN pattern elsewhere, e.g. `_resolve_grad_threshold`'s `logger.debug` on cache-unavailable) or `logger.warning(..., exc_info=True)` unconditionally (matching the sibling GBM seeder's `apply_surrogate_gbm_seeder`), so a real failure always leaves a trace regardless of the caller's verbosity setting.
- **Add a `"median"` code to the rolling njit kernel or drop it from the accepted-stats filter (CAT_INTERACTION_B-1):** either extend `_EXPANDING_STAT_CODE`/`_rolling_stat_past_only_njit` with a median branch (a per-cell median needs a different accumulator shape than the raw-moment ones — likely routed through the existing `_reduce`/pandas fallback path instead of the fast njit kernel), or remove `"median"` from the accepted-stats set in `generate_rolling_window_agg_features` and raise a clear `ValueError` up front instead of a bare `KeyError` deep in the call stack.
- **Small-group signed fallback for group-distance (CAT_INTERACTION_B-9):** consider a signed-but-shrunk estimate for below-`_MIN_GROUP_SIZE` groups (e.g. shrink the raw z toward 0 by a Bayesian/James-Stein factor proportional to group size) rather than a hard 0.0, so small-group anomalies are down-weighted rather than fully masked.
