# GPU infra cluster A -- pairwise-MI GPU backends, friend-graph, noise-gate, DCD batched SU

This cluster covers the GPU dispatch stack for pairwise feature-feature MI (`batch_pair_mi_gpu.py` +
its two carved-out kernel siblings `_batch_pair_mi_cuda_kernels.py` / `_batch_pair_mi_cuda_shared_fused.py`),
the friend-graph diagnostic's GPU node/edge-stats twin (`friend_graph_gpu.py`) and its CPU orchestrator
(`friend_graph.py`), the batched FE-candidate MI + permutation noise-gate GPU backends
(`batch_mi_noise_gate_gpu.py` + `_batch_mi_noise_gate_kernels.py` + `_batch_mi_noise_gate_tuning.py`), and
the batched pairwise symmetric-uncertainty precompute for Dynamic Cluster Discovery (`_dcd_pair_su_batch.py`).
All three GPU-dispatch families follow the same architecture: a numba.cuda kernel + a cupy kernel, each
required to be bit-identical (or selection-equivalent to ~1e-9/1 ULP) to a CPU njit reference, chosen per-host
via `kernel_tuning_cache.get_or_tune`, with `force_backend` overrides and VRAM pre-flight guards. The
2026-07-20 audit's `c4_gpu_infra.md` covered `batch_pair_mi_gpu.py` and `friend_graph_gpu.py` directly and its
`gpu_residency.md` companion covered the wider GPU-residency architecture; both P0s it found there
(`MLFRAME_DISABLE_GPU` silently ignored in `dispatch_batch_pair_mi` / `dispatch_friend_graph_stats`) are
**confirmed fixed** in commit `741926f8c` (verified via `git show`). This pass focuses on what that fix
didn't reach, code paths added/changed since, and the full checklist applied systematically to every file.

| GPU_INFRA_A-12 | P2 | thread_safety | `batch_mi_noise_gate_gpu.py:352-353,371-396,402-432` (`_DY_DEVICE_CACHE`/`_DY_DEVICE_CACHE_CUPY`) | The module-level `OrderedDict` device-shuffle caches (`_resident_y_all_device`/`_resident_y_all_device_cupy`) perform a non-atomic `get` -> `move_to_end` -> `popitem(last=False)` sequence with no lock. ## Proposals

- **Broaden the two remaining narrow `except` clauses** (GPU_INFRA_A-1): change `friend_graph_gpu.py:749` and `batch_mi_noise_gate_gpu.py:857` from `except (ValueError, RuntimeError)` to `except Exception`, matching `batch_pair_mi_gpu.py`'s already-fixed pattern, and wrap `friend_graph_gpu.py`'s `force_backend="cuda"` call (line 735-736) in the same try/except so a direct caller degrades to `None` (CPU fallback) instead of crashing. Add a regression test that monkeypatches the cuda kernel launch to raise a bare `Exception` subclass (not `RuntimeError`) and asserts the dispatcher returns `None`/falls back rather than propagating.
- **Guard `n_samples == 0`** (GPU_INFRA_A-2) at the top of `batch_pair_mi_cuda_row_chunked` and `batch_pair_mi_cuda_shared_fused`, mirroring `batch_pair_mi_cupy`'s `if n_samples == 0: return np.zeros(n_pairs, dtype=np.float64)` -- cheapest, highest-confidence fix on this list (a 2-line early return in each function), plus one unit test per function pinning it.
- **Add the same `gpu_globally_disabled()` self-check** to `dispatch_batch_mi_with_noise_gate_gpu` (GPU_INFRA_A-3) that `dispatch_batch_pair_mi`/`dispatch_friend_graph_stats` already have, closing the one remaining cluster dispatcher without defense-in-depth against `MLFRAME_DISABLE_GPU` -- cheap, and removes the asymmetry the prior audit's fix pass otherwise left behind.
- **Wire centrality into the rendered friend-graph plot** (GPU_INFRA_A-4): add `centrality`/`low_centrality` to `node_hovertext` and encode `low_centrality` membership via marker opacity/border in `friend_graph_to_figurespec`, per the already-open prior proposal.
- **Add a direct unit test file for `_batch_mi_noise_gate_tuning.py`** (GPU_INFRA_A-9): mirror `test_ktc_dispatch_no_sweep_on_default.py`'s pattern for the sibling KTC modules -- exercise `_batch_mi_noise_gate_fallback_choice`/`_batch_mi_noise_gate_backend_choice` with no-cupy / no-tuned-cache-entry stubs.
- **Add host-side code/nbins validation to `_batch_joint_entropy_pairs`** (GPU_INFRA_A-11), matching the `ValueError`-on-violation pattern the CUDA kernels in this same cluster already use, so a malformed input fails loudly on CPU too instead of relying on `categorize_dataset`'s contract holding by convention alone.
- **Consider a lock (or convert to a simple size-capped dict without strict LRU ordering) for `_DY_DEVICE_CACHE`/`_DY_DEVICE_CACHE_CUPY`** (GPU_INFRA_A-12) if concurrent multi-fit-per-process usage is a real deployment shape; otherwise, document the single-fit-per-process assumption explicitly in the cache's docstring so a future caller doesn't assume it's safe under threaded multi-fit use.
