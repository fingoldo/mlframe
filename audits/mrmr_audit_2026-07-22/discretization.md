# Discretization cluster audit (2026-07-22)

Scope: `discretization/__init__.py` (1331 LOC), `discretization/_kernels.py` (290 LOC), `discretization/_discretization_edges.py` (363 LOC),
`discretization/_discretization_dataset.py` (509 LOC), `supervised_binning.py` (579 LOC), `_mdlp_validated_split.py` (671 LOC), `_adaptive_nbins.py`
(886 LOC). Together this cluster is the whole numeric-to-ordinal pipeline `MRMR.fit` depends on: unsupervised uniform/quantile binning (CPU njit +
CUDA/CuPy twins, incl. a VRAM-constrained row-chunked GPU fallback), the native Knuth/Bayesian-Blocks edge builders, the per-feature adaptive
nbins dispatcher (`sturges`/`fd`/`qs`/`knuth`/`blocks`/`mdlp`/`mdlp_validated`/`optimal_joint`/`mah`), and three generations of Fayyad-Irani MDLP
(classic in-sample MDL, in-sample significance-gated, genuine out-of-sample-validated). This slice was already the subject of a 2026-07-20
16-agent audit (`c5_discretization.md`, 10 findings) whose P0/P1s were fixed same-day in commits `741926f8c` (B-1..B-11) and `6bca572d7`
(B-12..B-15); this pass verified each prior finding's current status and looked specifically for gaps the 2026-07-20 pass and the perf-critique
sweep did not cover: a GPU-fallback sibling that never received the B-12 NaN-parity fix, an unguarded O(N²) default, and a duplicate-row
safeguard applied to two of three sibling MDLP variants but not the third.

### Confirmed already-fixed (verified this pass, not restated)

* **B-1..B-11** (batch of 10 confirmed bugs incl. the P0 all-NaN-column njit quantile-edge crash swallowed by `prange`, `discretization/_discretization_edges.py:331-344`) — fixed in commit `741926f8c`; `get_binning_edges`'s empty-`arr_finite` branch now returns `np.zeros(1)` instead of calling `np.percentile` on an empty array. Verified present in current code.
* **B-12** (`discretize_2d_array_cuda`'s uniform/quantile branches not NaN-aware, unlike CPU) — fixed in commit `6bca572d7` via `cp.nanmin`/`cp.nanmax`/host `np.nanpercentile`/dedicated-NaN-code routing. Verified present in current code and covered by `tests/feature_selection/gpu/test_discretize_2d_array_cuda_nan_parity.py` (scattered-NaN case only — see DISCRETIZATION-1 for the un-fixed row-chunked sibling this same commit missed).
* **B-13** (`mdlp_bin_edges` + both `_mdlp_validated_split.py` siblings dropping NaN from `x` but not `y` before the `int64` cast) — fixed in commit `6bca572d7` in all three call sites: `supervised_binning.py:200-206`, `_mdlp_validated_split.py:392-397` (`mdlp_bin_edges_validated`), `_mdlp_validated_split.py:607-612` (`mdlp_bin_edges_oos_validated`). Verified present in current code (all three now fold `y`'s finiteness into the mask before casting).

## Proposals

* **Extend the B-12 fix to the row-chunked GPU path** (closes DISCRETIZATION-1): swap `cp.min`/`cp.max` → `cp.nanmin`/`cp.nanmax` in the `uniform` branch's two chunk loops, add the same `cp.where(cp.isnan(d_chunk), float(n_bins), out_f)` NaN-code routing, and route the `quantile` branch's subsample percentile through host `np.nanpercentile` when the subsample contains NaN — mirrors the already-landed fix in the non-chunked sibling almost line-for-line. Add a GPU test forcing the row-chunked path (small VRAM budget monkeypatch, as the existing dispatch tests already do) with a NaN-bearing column for both methods.
* **Flip the Bayesian Blocks default to a safe cap** (closes DISCRETIZATION-2): change `subsample_threshold`'s effective default from `0` to something like `2000` (or auto-derive from N, e.g. `min(N, 5000)`) at the `per_feature_edges` dispatch layer specifically (leave the lower-level functions' explicit-`0`-means-disabled contract intact for callers who genuinely want exact BB on a small column) — per CLAUDE.md's "enable corrective mechanisms by default," the already-known-safe value used in every internal benchmark should be the value real callers get without having to discover the `bb_subsample_threshold` kwarg exists.
* **Add a duplicate-row regression test for `mdlp_bin_edges_oos_validated`** (resolves DISCRETIZATION-3 either way): reuse the exact fixture from `test_duplicate_rows_do_not_over_split_pure_noise` (pure-noise x/y at 0/10/50/90% exact-row duplication) against `mdlp_bin_edges_oos_validated`; if it over-splits like the pre-fix siblings did, wire in `_dedupe_xy` there too (its call site already dedupes `x_train_raw`/`y_train_raw` right before the recursion starts, same shape as the other two callers); if it turns out the OOS accept test is structurally immune, add a one-line comment explaining why so the next reader doesn't have to re-derive it.
* **`get_binning_edges` return-type annotation**: add `-> np.ndarray` now that all three branches (`uniform`/`quantile`/raise) are confirmed consistent.
* **Retire `quantize_dig`** (or fix its tie-break to match `quantize_search`) given it has zero real callers and a docstring claiming an equivalence that is false — either delete it (grep confirms only `_legacy.py`'s re-export and `_prewarm.py`'s warmup reference it) or make the two bit-identical and correct the docstring.
