# GPU Infra B — resident FE candidate-generation, radix-select, materialise/discretize, KTC tuners

This cluster is the "matrix-native GPU residency" replatform for the pairwise FE candidate search: `_gpu_resident_fe.py`
(gate helpers, candidate-op catalog, resident-codes/deferred-host-fill handoff, fused-generation + grand-fusion
histogram RawKernels) and its Tier-E carve siblings — `_gpu_resident_basis.py` (device port of the orth-FE
prewarp/Clenshaw-basis evaluation + basis routing + the grand-fusion pair-MI dispatcher, still ~1.6k LOC and the
largest file in the cluster), `_gpu_resident_select.py` + `_gpu_resident_select_kernels.py` (the sort-free
rank-exact radix-select order-statistic API and its RawKernel zoo: base/bsearch/v3 f32 variants, the fused f64
select+interp v1/v2/v3, and the coalesced tiled-transpose kernels for f32/f64/int8/int16), `_gpu_resident_materialise.py`
(the chunk `fe_materialise` RawKernels, the operand-table residency caches, the pinned-D2H staging buffer, and the
resident-codes-handoff producer entry points), `_gpu_resident_discretize.py` (fused per-column binning +
`_gpu_resident_discretize_codes`), `_gpu_resident_rank_bin.py` (the argsort-based RANK binner used only by the
STRICT-resident conditional-gate MI), and three `kernel_tuning_cache`-integration siblings
(`_gpu_resident_k_chunk_ktc.py`, `_gpu_resident_histgate_ktc.py`, `_gpu_resident_radix_ktc.py`) that replace
hardcoded launch-configuration constants with per-host sweeps. Every kernel in this cluster carries an explicit
bit-identity/selection-equivalence claim against a CPU or cupy reference and (where reachable) a matching parity
test; the module docstrings are unusually rich with dated bench numbers and rejected-attempt notes, which made
cross-referencing against the 2026-07-20 and 2026-07-21 audits straightforward — neither of those audits'
16/39 agents named any of these 10 files directly (`gpu_residency.md` and `c4_gpu_infra.md` discuss
`_gpu_resident_fe.py`/`_gpu_resident_basis.py` only at the "this whole prototype is dead/unwired" level, and
`mrmr_crit_numstat.md` only in a caller cross-check aside), so effort went into the checklist angles those audits
did not apply here rather than re-litigating settled ground.

mypy (`--cache-dir=.mlframe_mypy_cache_shared`) is clean on all 10 files. No SQL/HTTP/UI/network surface exists
anywhere in this cluster (confirmed by reading every file in full — pure numpy/cupy/CUDA-C kernels plus
`kernel_tuning_cache`/`logging` calls); angle 9 is N/A. No `eval`/`exec`/`subprocess`/`os.system`/pickle-of-untrusted-data
anywhere. Bare `except Exception: pass` with no logging occurs exactly once in the whole cluster
(`_gpu_resident_basis.py:249`, `# nosec B110` + inline rationale, a best-effort optional radix fallback where a
miss just means "take the `cp.percentile` fallback", never a wrong answer) — consistent with the project convention
the 2026-07-20 audit already found clean across this general area.

| GPU_INFRA_B-1 | P1 | bug (concurrency) | `_gpu_resident_materialise.py:673,833` | `gpu_materialise_discretize_codes_host` and `gpu_discretize_codes_host` both call `clear_resident_codes_handoff()` with **no argument** at entry — the blanket, whole-dict-clear form — instead of the targeted per-host-array form the same module's own `_stash_*`/`take_resident_codes`/`clear_resident_codes_handoff(host)` API and its regression test (`test_con9_targeted_clear_preserves_other_entry`) were specifically built to support. ## Proposals

- **Fix GPU_INFRA_B-1 the cheap way**: change the two entry-point calls in `_gpu_resident_materialise.py` from `clear_resident_codes_handoff()` to a form that only ever targets THIS call's own about-to-be-produced `out` array (which doesn't exist yet at the point of the call) — the real fix is to drop the defensive blanket-clear entirely (the module docstring already says "each chunk's dispatch should already have consumed/cleared its own", i.e. it's meant as a dead-man's-switch, not a normal-path event) and instead rely on the bounded-FIFO eviction (`_RESIDENT_CODES_HANDOFF_MAX`/`_DEFERRED_HOST_FILL_MAX = 8`) to age out any truly-abandoned entry. Add a regression test that runs two interleaved (threaded, mocked) producer→consumer sequences and asserts neither thread's deferred fill is dropped by the other's entry-point call — extending `test_con9_targeted_clear_preserves_other_entry`'s pattern to the actual production call sites, not just the primitive.
- **GPU_INFRA_B-3**: bump `_RADIX_STATIC_SHARED_BYTES`'s comment/formula to explicitly account for v3's 4 extra shared scalars (trivial: add `8 + 3*4` for `scount`/`cand_ok`/`have_cand`/`overflowed`), so the "worst case" claim is true by inspection rather than true by accident of the current MAXR/device-limit headroom.
- **GPU_INFRA_B-4**: fix the "nbins<=255" comments to "nbins<=128" (signed int8), and add a one-line assertion in `gpu_discretize_codes_host`/`gpu_materialise_discretize_codes_host` (`assert np.iinfo(np.dtype(dtype)).max >= nbins - 1` when `dtype` is an integer type) so a future direct caller gets an immediate `AssertionError` instead of silent wraparound.
- **GPU_INFRA_B-6**: copy `test_gpu_k_chunk_vram_fraction_ktc.py`'s pattern (tuner-spec-registered smoke test + fallback-choice sanity + a CPU-only "no cupy -> safe default" check) to `_gpu_resident_histgate_ktc.py` and `_gpu_resident_radix_ktc.py` — cheap, and closes the exact gap the 2026-07-18 in-file bug (dead sweep-probe override) shows this file class is prone to.
- **GPU_INFRA_B-7**: add a small `test_gpu_resident_transpose_kernels.py` that round-trips `_transpose_to_cm`/`_transpose_cm_to_rm`/`transpose_codes_to_cm` against `cp.ascontiguousarray(x.T)` at K/n shapes deliberately NOT multiples of 32 (e.g. K=1, K=33, n=1, n=1000003) for f32/f64/int8/int16, skipped when no CUDA device is present.
- **GPU_INFRA_B-2 / GPU_INFRA_B-5**: when the next FE-perf-loop wave picks this cluster back up (per the LOC-budget exempt-list's own stated plan), fold in a decision on the confirmed-dead grand-fusion/pair-candidate-MI prototype (delete, or add an explicit `# UNREACHED FROM PRODUCTION` marker per the prior audit's proposal) rather than carrying it forward silently split across two files; fixing the `base_seed=np.uint64(0)` hardcode at the same time is a 3-line change if the code survives.
- **Nice-to-have**: `_gpu_resident_select.py`'s `_RADIX_INTERP_CACHE`/`_COMBO_IDX_CACHE`/`_QLEVELS_CACHE`/`_BIN_BOUNDARIES_CACHE`-style module dicts are all keyed on small, cheap-to-recompute geometry (n, nbins) and are safe under the GIL for correctness (worst case is redundant compute on a race, never a wrong answer, since values are pure functions of the key) — no action needed, but worth a one-line comment on each cache saying so explicitly, matching the care already taken in `_gpu_resident_materialise.py`'s cache docstrings (which spell out exactly this reasoning for the OrderedDict caches).
