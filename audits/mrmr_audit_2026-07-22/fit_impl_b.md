# fit_impl_b — audit of `_mrmr_fit_impl/_fit_impl_core.py` (second half, lines ~4700-9344)

## Scope

`_fit_impl_core.py` (9344 LOC total) holds the entire body of `MRMR._fit_impl` — the fit-time orchestration that
runs the screen/FE outer loop, then a long chain of post-selection "protection"/"rescue"/"drop" passes that
reconcile the greedy MI screen's raw support against everything the FE stages engineered (raw-retention,
adaptive-Fourier/hinge/orth-basis/missingness/cat-FE protection blocks, masked-raw and monotone-twin drops,
DCD post-selection cluster discovery, the p>=n false-positive-control cap, usability-aware pure-form/raw
retention, and the final support/`n_features_`/`mrmr_gains_` bookkeeping) before handing back to the small
`_finalise.py` empty-support fallback. This report covers lines ~4700-9344: the cross-stage engineered dedup,
the full outer screen/FE `while True` loop, every post-selection raw-vs-engineered reconciliation pass, the
p>=n cap, usability-aware retention, and fit-end bookkeeping (fit cache store, UAED elbow, alignment, roster
reconciliation). The sibling `fit_impl_a` agent covers lines 1-4700 plus the small `_mrmr_fit_impl/` helper
files (`_finalise.py`, `_fe_stage_temporal_agg.py`, `_eng_dedup_batch_corr.py`, `_helpers.py`).

Cross-referenced against `audits/mrmr_audit_2026-07-20/` (16-agent audit, 143 findings — only `gpu_residency.md`
and `test_coverage.md` cite this file directly, both by old line numbers predating several refactors) and
`_benchmarks/mrmr_critique_2026_07/` (7-agent critique whose `_TRACKER.md` disposes ST-1/ST-4/ND-2/ND-3/ND-4/P-1..11
against this file). `git log -p` / direct reads confirm ST-1 (UAED elbow raw/engineered lockstep trim, now at
line 9271-9308), ST-4 (`ran_out_of_time_` OR-in for a screen-level timeout, line 9206-9212), and ND-3 (the
`fe_raw_tail_subsume_min_corr=0.85` near-complete-proxy gate replacing the old blanket 0.6 threshold, line 7600)
are genuinely fixed and match their disposed description. `mrmr_crit_selection.md`'s "verified-correct" note that
`H(y)` and the MI kernels agree on natural-log units still holds (line ~5811, `-(p*np.log(p)).sum()`, nats).
`test_coverage.md`'s example of raw-operand-readd gates with no exception logging (old lines ~6619/7477/8470) is
fixed: the current `_rr_raw_is_significant`, `_pcr_raw_is_significant`, and `_eb_operand_is_signal` closures all
wrap their estimator call in `except Exception as e: logger.debug(...)`. mypy is clean on this file
(`python -m mypy --cache-dir=.mlframe_mypy_cache_shared _fit_impl_core.py` → `Success: no issues found`). No
SQL/HTTP/UI surface exists in this file (confirmed: no DB/network calls; the only string-building is internal
log messages and Python identifiers, not markup); no `eval`/`exec`/`os.system`/`subprocess`/`pickle.load`/
`yaml.load` anywhere in the audited range (grep-confirmed).

## Proposals

- **Decompose `_fit_impl` incrementally, closure-by-closure, the same way `_finalise.py` / `_fe_stage_temporal_agg.py` / `_eng_dedup_batch_corr.py` were carved out.** Start with the post-selection reconciliation passes (raw-retention, hinge/orth-basis/cat-FE protection, masked-raw rescue, monotone-twin drop, DCD post-selection discovery) — each is already a self-contained `if <gate>: try: ... except: logger.warning(...)` block reading a well-defined set of locals (`data, cols, nbins, selected_vars, X, engineered_recipes, ...`) and could become a `_post_selection_raw_reconcile.py` sibling taking those as explicit parameters, exactly like the existing carve-outs. This would make e.g. `_rr_raw_is_significant` and `_heldout_incr_over_selected` independently unit-testable for the first time.
- **Re-run the p>=n cap once more, immediately before `self.support_ = np.array(selected_vars, ...)` is frozen (line 8532) and again after the two late retention passes (8791-8946, 9084-9170).** A one-line re-application of `_pgn_raw_budget`/`_pgn_ceiling` at each of those points (trim by ascending relevance, same as the existing cap) would restore the documented invariant end-to-end instead of only at the single midpoint it currently guards. Ship a regression test with a wider p (e.g. p=600, n=100) and several genuinely-marginal-but-real linear raw signals designed to survive `retain_usable_raw_columns`'s CV-MAE gate, to force the two late passes to actually add columns and prove (or disprove) the overshoot.
- **Replace the three `(idx % 3) == 0` stride splits with a seeded shuffle-then-stride (or a seeded `np.random.default_rng(self.random_seed).permutation(n)` fold assignment).** Cheap (one extra permutation array reused by all three gates) and removes the sorted/grouped-input bias while keeping the split reproducible under `random_seed`. Add a regression test that sorts a synthetic fixture by group/time before fitting and asserts the same rescue verdict as the shuffled-order baseline.
- **Regenerate the 7 stale `"suppressed in _fit_impl_core.py:<N>"` debug messages to drop the hardcoded line number entirely** (rely on `logger.debug(..., exc_info=True)` or a `%(lineno)d` log-record field instead) so they cannot drift again on the next edit.
- **Fold `_y_for_eng_mi`'s qcut into the same shared `_y_discrete` cache** the P-3 fix already introduced for the four discrete-structural operators, retiring one more of the originally-estimated ~15 redundant re-binning sites.
- **Add a debug-level log line to the handful of fully-silent `except Exception:` sites that guard non-trivial diagnostic construction** (`self.dcd_`, `self.cluster_hierarchy_`, `self._engineered_continuous_` reset) — one-line `logger.debug("... failed (%s)", e)` each, mirroring the pattern already used at the fixed raw-operand-readd gates, so a genuine internal bug in these paths leaves a trace instead of silently reading as "feature disabled."
