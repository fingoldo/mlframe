# info_theory_a — audit report (2026-07-22)

**Scope:** `src/mlframe/feature_selection/filters/info_theory/{__init__.py, _batch_kernels.py, _cmi_cuda.py, _cmi_cuda_ktc.py, _class_encoding.py, _class_mi_kernels.py, _entropy_kernels.py, _group_mi.py, _state_and_dispatch.py}`.

This cluster is the low-level information-theory kernel layer MRMR's greedy loop is built on: `_class_encoding.py` melts ordinal-encoded columns into dense joint-class histograms (`merge_vars` + its pruned 2-var twins); `_entropy_kernels.py` reduces those histograms to Shannon / Miller-Madow / Chao-Shen entropy, MI, SU, and conditional-MI (CMI); `_class_mi_kernels.py` does the same from pre-computed class arrays for the permutation-null hot path (incl. a sample-weighted MI variant); `_state_and_dispatch.py` holds every `threading.local` toggle (SU/JMIM/BUR/MM/Chao-Shen/group-MI/RelaxMRMR/PID/CMI-perm/CPT) plus the two Python-level dispatchers that read them; `_group_mi.py` is the group-blocked `I(X;Y|G)` estimator for panel/leakage-safe relevance; `_batch_kernels.py` holds the `prange`-parallel batched pair/triple MI + permutation-null kernels and the FE-candidate MI+noise-gate kernel pair (v1/v2, KTC-dispatched); `_cmi_cuda.py` + `_cmi_cuda_ktc.py` are the batched CUDA CMI kernel, its multi-layer residency caches, and its KTC-measured CPU/CUDA crossover. `__init__.py` is a pure re-export facade. Overall the cluster is unusually well-documented (every non-obvious optimization carries a bench citation and a bit-identity argument) and the July-20 audit's `c3_info_theory.md` found this code largely clean; this pass focused on what that pass didn't systematically check per-file (concurrency of the newer resident caches, cap/dtype edge cases, dead parameters, LOC) and re-verified the open items it did find.

| INFO_THEORY_A-1 | P1 | concurrency/cpu_gpu_parity | `_cmi_cuda.py:341-480` | `_resident_factors_device`'s whole-`factors_data` device cache (the "XC RESIDENT MATRIX", 2026-07-12) validates a cache hit by `id()` + weakref-liveness ONLY, unlike its sibling `_resident_upload` (y/z cache, same file) which folds in a content hash specifically to catch "same id, different bytes". Since 2026-07-04 (`d9f7f5f3`, critique P-1) `factors_data` is an ALIASED array that `fleuret.py`'s permutation-confidence path mutates in place (shuffle a column, score, restore) rather than a private copy, and `evaluate_candidates` dispatches across a `backend="threading"` joblib pool (real OS threads, `n_jobs=-1` by default) that all share that one array by reference. ## Test coverage note

Direct kernel coverage is good: `merge_vars`/`joint_freqs_2var`/`joint_entropy_2var` have dedicated identity/overflow tests (`test_joint_freqs_2var.py`, `test_joint_entropy_2var.py`, `test_merge_vars_counter_overflow.py`), the class-MI kernels have weighted/MM/CS tests (`test_cat_fe_weighted_and_bootstrap.py`, `test_mrmr_critique_nf2_mm_redundancy.py`, `test_biz_val_filters_mrmr_chao_shen.py`), `_group_mi.py` has `test_group_mi_kernel.py` + biz-value coverage, and the CMI CUDA residency machinery has a dedicated file per cache (`test_cmi_forder_view.py`-style template, `test_cmi_cuda_xc_resident.py`). Gaps found: no test exercises `n_classes_y` anywhere near the `MAX_JOINT_CARDINALITY` cap (INFO_THEORY_A-2), none exercises `classes_dtype=int16` overflow at `nbins>32767` (INFO_THEORY_A-3), and — the one that matters most — no test exercises a *live* (non-GC'd) content mutation of a cached-identity `factors_data` for either resident cache (INFO_THEORY_A-1/A-9), only the GC'd-and-recycled-id case.

## Security / SQL / HTTP / UI applicability

Confirmed N/A for this cluster: no DB/network/UI surface, no `eval`/`exec`/`subprocess`/`os.system`, no `pickle`/`yaml.load` of untrusted data (the only pickle-related comments are "safe to pickle any consumer" design notes — no live CUDA context is ever put on an instance). No string-interpolation into generated HTML/markdown/code. The one attacker-controlled-size angle (INFO_THEORY_A-2/3, cardinality-driven unbounded allocation / dtype overflow) is called out above under efficiency/edge-case rather than security, since these kernels only ever see the caller's own already-discretized data, not external/untrusted input.

## Proposals

- **Close INFO_THEORY_A-1/A-9 together**: fold a cheap content-fingerprint (mirroring `_resident_upload`'s `hash(arr.tobytes())`, or a cheaper per-column checksum given the matrix is large) into `_resident_factors_device`'s cache key, and add a `threading.Lock` around `_CMI_RESIDENT_CACHE` access to match its two siblings. A regression test would construct two threads — one repeatedly shuffling+restoring a column of a shared int32 matrix, one repeatedly calling `_resident_factors_device`/`conditional_mi_batched_dispatch` on it — and assert the returned CMI never disagrees with a serial reference beyond the documented ~1e-9 parity bound across many iterations.
- **INFO_THEORY_A-2**: extend `MAX_JOINT_CARDINALITY`'s check to `nb_a * nb_b * n_classes_y` (and the triple kernel's `n_dense_upper_bound * n_classes_y`), or document/assert an explicit cap on `n_classes_y` at the FE/screening call sites that feed these kernels.
- **INFO_THEORY_A-3**: either assert `factors_nbins.max() < 32768` at the `batch_mi_with_noise_gate*` entry point (raise a clear `ValueError` instead of silently truncating) or auto-widen `classes_dtype` to int32 when any column's cardinality would not fit int16.
- **INFO_THEORY_A-4**: either wire `min_occupancy` through `merge_vars`'s per-variable `freqs` construction (filter `freqs < min_occupancy` before the dense-remap, mirroring `entropy`'s semantics) or drop the parameter and document `entropy(freqs, min_occupancy=...)` as the only place that knob lives.
- **INFO_THEORY_A-5**: prune the unused `dtype` parameter from the ~9 listed functions (a mechanical, behavior-preserving cleanup — numba doesn't care, and removing it shrinks every call site) or add a one-line docstring note ("kept for call-site signature parity with `merge_vars`-based siblings, unused here") so a future reader doesn't assume it does something.
- **INFO_THEORY_A-6**: when next touched, carve `_cmi_cuda.py`'s residency-cache section (F-order view / y-z resident / XC resident matrix, ~420 lines) into a sibling `_cmi_cuda_residency.py`, and `_batch_kernels.py`'s FE noise-gate kernel pair + KTC selector (~490 lines) into `_batch_fe_noise_gate.py`, re-exported from the facade — both are self-contained enough to split cleanly before either grows further.
- **INFO_THEORY_A-7/A-8**: add `logger.debug("...: %s", exc)` to the four remaining bare excepts (mirrors the fix already applied elsewhere in this same file per the repo's own logging-discipline convention) — a small, mechanical, already-scoped fix, low risk.
