# GPU Infra Cluster C — usability-aware GPU/resident scorers, resident MI kernels, `_gpu_strict_fe`, `_fe_gpu_batch`, and GPU dispatch/launch/teardown infra

This cluster covers three related layers of the MRMR GPU-acceleration stack: (1) the gated cupy twins for the
usability-aware selection pass (`_usability_gpu.py`, the regression/classification GPU-resident greedy twins,
the njit-fused pair-combo MI pool and its resident/KTC siblings); (2) resident-GPU MI primitives used by the
FE-gate candidate scoring path (`_resident_bincount.py`, `_resident_raw_mi.py`, `_resident_candidate_mi[.py|_ktc.py]`);
and (3) shared GPU dispatch/orchestration infrastructure — the `_gpu_strict_fe` subpackage (STRICT-resident
FE entry points, the dead `ResidentFEState` scaffold, the residency-audit harness), the `_fe_gpu_batch`
subpackage (single/multi-GPU FE-batch MI executor, CP-SAT device packer, device profiling), and the
standalone `_gpu_policy.py` / `_gpu_hw_launch.py` / `_gpu_teardown_guard.py` / `_kernel_tuning.py` /
`_fe_gpu_vram.py` / `_fe_gpu_strict.py` singletons. All 25 files are well under the 800-900 LOC guideline
(largest is `_usability_njit_pool.py` at 785 LOC); every file passed a clean `mypy` spot-check with zero
issues. Documentation density and CPU/GPU-parity discipline in this cluster are unusually high (nearly every
resident kernel carries an explicit bit-identity/selection-equivalence argument and a `bench-attempt-rejected`
trail), which made it possible to find several NEW, non-obvious issues by tracing invariants the docstrings
themselves assert rather than by pattern-matching for missing try/except blocks. Angle 9 (SQL/HTTP/UI best
practices) is confirmed N/A: this is pure computational/dispatch code with no DB, network, or browser-facing
surface anywhere in these 25 files (the only "artifact" produced is log lines via the stdlib `logging` module).

| GPU_INFRA_C-2 | P1 | thread-safety | `_gpu_teardown_guard.py:60-70` (`install_cuda_teardown_guard`) | The idempotency guard is a bare `if _installed: return` / `_installed = True` with no lock, sharing single module-level `_prev_unraisablehook`/`_prev_excepthook` slots. | GPU_INFRA_C-4 | P1 | correctness / documentation-fidelity | `_resident_bincount.py:10-17` (`resident_bincount`) | The docstring states out-of-range indices are "undefined behaviour (same as feeding cupy.bincount a bad minlength)" — but the two failure modes are not equivalent. `cupy.bincount` raises a loud `ValueError` immediately on any negative index. `resident_bincount`'s `cupyx.scatter_add` does no bounds checking at all: a negative index silently wraps (Python/numpy fancy-indexing semantics: `-1` scatters into `out[nc-1]`) producing a plausible-looking but silently WRONG histogram/MI count instead of crashing, and an index `>= nc` is genuine unchecked GPU out-of-bounds writes (cupy disables device-side bounds checks by default) — i.e. potential memory corruption, not merely "a bad answer". This is a real defense-in-depth regression traded for the sync-avoidance win, understated by the docstring's comparison. | New. |

## Proposals

- **Make `_fe_gpu_strict`'s AUTO-fit-shape state thread-local.** Replace the bare `_AUTO_FIT_N`/`_AUTO_FIT_P`
  module globals with a `threading.local()` (or pass shape explicitly through the FE-step call chain) so
  concurrent `.fit()` calls — already a real pattern via `stability.py`'s `backend="threading"` bootstrap
  loop — never see each other's shape. Add a regression test that runs two `MRMR().fit()` calls with very
  different (n, p) on two threads concurrently and asserts each fit's STRICT-engage decision matches what it
  would get running alone (this would fail today).
- **Add a lock to `install_cuda_teardown_guard`** (or convert the `_prev_*` capture + hook-install into one
  atomic critical section) so the guard's own "idempotent" docstring claim is actually true under concurrent
  invocation, closing the latent self-recursion risk in GPU_INFRA_C-2 before any future caller relies on
  multi-thread safety the current single import-time call site happens to provide only incidentally.
- **Add a dedicated parity test for `best_existing_op_mi_resident`**, mirroring
  `test_device_born_gate_grid_parity.py`'s pattern for its sibling `gate_grid_mi_resident` in the same file,
  and consider tightening `_resident_candidate_mi_ktc.py`'s sweep tolerance (or adding a SEPARATE tight-tolerance
  correctness gate distinct from the loose wall-clock ranking) so a genuinely broken resident kernel cannot be
  crowned "fastest" by a 5e-2-tolerant sweep alone.
- **Add a debug/test-mode bounds assert to `resident_bincount`** (e.g. `assert x.min() >= 0 and x.max() < nc`
  under a cheap opt-in flag, or at minimum fix the docstring's misleading equivalence claim to accurately
  describe the harsher UB) so an upstream off-by-one fails loudly in CI instead of silently corrupting a
  histogram/MI value in production.
- **Fix the two stale docstrings** (`_usability_pool_resident.py`'s "NOT WIRED" header, `_gpu_strict_fe/_entry.py`
  + `_state.py`'s "zero production callers" claim) now that both have been independently reconfirmed stale by
  this wave's audits, so a future reader doesn't have to re-derive the correction a third time.
- **Route `_fe_gpu_batch/_devices.py`'s `_visible_device_ids()` through `_gpu_policy.gpu_globally_disabled()`**
  instead of its own inline duplicate, closing one more instance of the pattern the prior audit flagged.
