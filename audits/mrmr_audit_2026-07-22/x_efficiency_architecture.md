# Cross-cutting efficiency & architecture-hygiene audit — MRMR module (2026-07-22)

This is the repo-wide pass over `src/mlframe/feature_selection/filters/` (145,511 LOC across ~290 files) that
the 26 per-cluster agents in this same wave could not perform individually: a `wc -l` census against the
CLAUDE.md ~800-900 LOC carve guideline (cross-checked against the *enforced* 1000-LOC CI gate and its exempt
list), a scan for duplicated/drifted logic between `_resident`/GPU-twin files and their CPU siblings that spans
cluster boundaries, a search for O(n²)-class loops, full-frame `.copy()` waste, and unsound cache-invalidation
patterns that recur *across* files rather than within one, and a disposition check on the 2026-07-20 audit's
GPU-residency roadmap (10 proposals) and its 96 P2 findings. Note: the task brief references "27 cluster
reports"; only 26 exist in `audits/mrmr_audit_2026-07-22/` (verified via directory listing) — all 26 were read
in full. The single highest-value discovery this pass made is that an entire 13-file, 5,542-LOC subpackage
(`_orthogonal_univariate_fe/`, which contains the *default-on* production entry point for univariate
orthogonal-basis FE) was not claimed as primary scope by any of the 26 clusters and received zero real audit
coverage — plausibly *because* its own module docstring falsely claims it is opt-in-only dead weight, a doc-drift
bug this pass also independently re-discovered four other times in sibling files.

## Duplicated/drifted logic across `_resident`/GPU-twin pairs

34 files in this module carry `resident` in their name. The 26 cluster reports already found and disposed most
drifted pairs (restated here only as a consolidated index, not re-litigated):

- **Confirmed drifted but currently unreachable (dormant)**: `_usability_njit_pool`'s njit "sign" unary maps NaN to `-1.0` while its cupy twin `_gpu_apply_unary` and plain `np.sign` both preserve NaN (`gpu_infra_c.md` GPU_INFRA_C-8) — masked today because the sole caller pre-scrubs NaN before either path is reached.
- **New this pass** (X_EFFICIENCY_ARCHITECTURE-3 above): `_orthogonal_univariate_fe/_orth_gpu_resident.py` silently drops the semi-supervised unlabeled-pool augmentation the CPU sibling applies — found specifically because this subpackage fell outside every cluster's claimed scope, confirming the value of a cross-cutting pass that isn't bound by the same file-ownership boundaries the parallel agents used.
