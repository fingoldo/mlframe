# Clustering / Stability Selection / Dynamic Cluster Discovery (DCD) -- 2026-07-22 re-audit

This slice covers MRMR's clustering and stability-selection machinery: bootstrap stability wrappers
around a fitted estimator (`stability.py`'s `StabilityMRMR`, `_stability_fe.py`'s `stability_select_fe`
/ `StabilityFESelector`), two opt-in academic stability-selection variants (`_stability_cluster.py`'s
Faletto-Bien cluster stability selection and Shah-Samworth complementary-pairs selection), a post-fit
selection-confidence report (`_mrmr_stability_report.py`), a read-only post-hoc hierarchical clusterer
over DCD anchors (`_cluster_hierarchy.py`), unsupervised correlated-feature-cluster aggregation into
denoised FE recipes (`_cluster_aggregate.py`), two standalone train/test and resampling stability
filters (`_ks_stability.py`, `_monotonic_stability.py`), and the in-greedy-loop Dynamic Cluster
Discovery engine itself (the `_dynamic_cluster_discovery` subpackage: state/discovery in `__init__.py`,
pairwise SU/VI metrics + pruning predicate in `_dcd_metrics.py`, the anchor-swap accept/commit
machinery in `_dcd_swap.py`, its parallel permutation-null kernels in `_dcd_swap_null.py`, the batched
member-relevance kernel in `_dcd_member_rank_batch.py`, and the auto-tau bimodality calibrator in
`_dcd_tau_auto.py`). This is the second audit pass on this cluster; the 2026-07-20 audit
(`c6_clustering_stability.md`, 10 findings) already covered most of this same file set -- this pass
cross-references every one of those findings against the current code and git history, confirms three
are already fixed, confirms the rest are still open (restated briefly, not re-litigated), and adds new
findings from applying the full checklist (efficiency, dead code, diagnostics accuracy, LOC budget) that
the prior pass did not raise.

**Prior-audit fixes verified in git history**: B-4 (`_mrmr_stability_report.py`'s bootstrap seed falling
back only to the deprecated `random_seed` alias) fixed in `741926f8c`; B-14 (`StabilityMRMR`'s
per-bootstrap fit had no try/except) and B-15 (`stability_select_fe`'s per-bootstrap fit had no
try/except) both fixed in `6bca572d7` -- read the current code for both and confirmed the fix mirrors
`_stability_cluster.py`'s n_success/n_failed pattern with a regression test at
`tests/feature_selection/stability/test_stability_cluster_effective_bootstraps.py` (which itself only
covers `_stability_cluster.py`'s two functions, not `stability.py`/`_stability_fe.py` directly --
`test_stability_mrmr_and_fe_effective_bootstraps.py` covers those, confirmed present).

**Security / SQL / HTTP / UI (checklist item 7/9)**: confirmed N/A for the whole cluster. No
pickle/dill/yaml.load of untrusted data (the only pickle references are docstring notes that these
sklearn estimators survive pickling, not deserialization of external input), no eval/exec/subprocess/
os.system, no network or DB calls, no path construction from caller-controlled strings. No file writes.
`_mrmr_stability_report.py`'s `_format_report` interpolates feature names into a plain-text report
string returned to the caller (never written to disk, executed, or rendered as HTML/markdown) --
no injection surface. `os.environ.get` is used read-only for two feature-flag env vars
(`_stability_cluster.py`'s `MLFRAME_CRIT_DTYPE_RELAXED`, `MLFRAME_STABILITY_CLUSTER_MAX_FEATURES`), not
attacker-influenced in any realistic deployment of this library. GPU: confirmed this entire cluster has
zero CUDA/cupy/numba.cuda code paths (grepped); DCD's only "parallel" kernels are CPU `numba.njit(parallel=True)`
+ `prange` (`_dcd_swap_null.py`, `_dcd_member_rank_batch.py`), so CPU/GPU parity is not applicable here.

| CLUSTERING_STABILITY-5 | P2 | edge_case | `_dcd_tau_auto.py:205-266` | `_calibrate_tau_auto`'s pair count floor `n_pairs_eff = max(20, min(n_pairs, n_cols*(n_cols-1)//2))` combined with the `len(su_scores) < 10` early-fallback means that for any `n_cols` in `{4, 5}` (i.e. `C(n_cols,2)` in `{6, 10}` with the latter borderline on any non-finite score), `tau_cluster='auto'` calibration silently and unconditionally falls back to the 0.7 default -- a plausible small-p production scenario (a heavily SIS-screened pool). ## Proposals

- **Extend the "raise on 100% bootstrap failure" contract** (closes CLUSTERING_STABILITY-1) to `cluster_stability_selection`, `complementary_pairs_stability`, and `stability_select_fe`, mirroring `StabilityMRMR`'s post-B-14 `RuntimeError`. Add a regression test analogous to `test_stability_cluster_effective_bootstraps.py` that forces every bootstrap to fail and asserts a loud `RuntimeError` rather than a silently-empty result.
- **Reuse `Xc` by position in `_discover_clusters`** (closes CLUSTERING_STABILITY-3): build a `{col_idx: position_in_pool}` dict once, slice `Xc[:, [pos_map[m] for m in members]]` instead of re-calling `_continuous_cols` per cluster, and replace the scattered `pool.index(...)` calls with dict lookups.
- **Populate `_calibrate_tau_auto`'s diagnostics before every return path** (helps CLUSTERING_STABILITY-5): set `n_pairs_sampled`/`n_pairs_finite` immediately after the sweep completes, before the `len(su_scores) < 10` fallback check, so the surfaced `tau_calibration` diagnostic always reflects what was actually attempted even when calibration ultimately falls back to the default.
- **Give `_binarize_aggregate` a dedicated NaN bin** (closes CLUSTERING_STABILITY-6) mirroring the discretization module's `n_bins`-as-NaN-code convention, plus a unit test pinning the behavior directly (not relying on every call site pre-sanitizing).
- **Split `_dcd_swap.py`** (closes CLUSTERING_STABILITY-7): carve `commit_swap` (and its `EngineeredRecipe`-building sub-block) into a new `_dcd_swap_commit.py` sibling, re-exported from `_dynamic_cluster_discovery/__init__.py` exactly as `_dcd_metrics.py`/`_dcd_tau_auto.py` already are, bringing both the parent package and `_dcd_swap.py` back under the ~800-900 LOC guideline.
- **Remove the unreachable `raise ValueError` in `run_cluster_aggregate_step`** (closes CLUSTERING_STABILITY-4) or replace it with an `assert False, "unreachable: methods is never empty here"` so a future reader isn't misled about a live guard.
