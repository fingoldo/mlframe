# Cross-cutting audit: Security, API design, Packaging, SQL/HTTP/UI applicability (2026-07-22)

This is a cross-cutting pass over the entire MRMR module (`src/mlframe/feature_selection/filters/`, ~300
files, all subpackages) rather than a per-file review — the 25 companion cluster reports in this same
audit wave already did the file-by-file work. This report (a) runs the specific security greps the audit
brief calls out across the whole tree and reports the SQL/HTTP/UI surface verdict explicitly, (b) checks
`pyproject.toml`/vendored-code packaging and licensing discipline, (c) audits the small set of real
sklearn-estimator classes in this module (`MRMR`, `GroupAwareMRMR`, `StabilityMRMR`, `StabilityFESelector`,
`MRMRTreeRescued`) for CROSS-FILE consistency of estimator-contract compliance, parameter validation, and
error-message quality, and (d) synthesizes the module-level-mutable-cache thread-safety findings that the
25 cluster reports found piecemeal into one architectural view. Individual per-file bugs already reported
by a cluster are cross-referenced, not re-litigated; only genuinely new cross-file findings get a full row.

- `requests.`/`urllib`/`http.client`/`socket.`: **zero hits** — no HTTP client code anywhere in the module. The vendored InfoNet's model-checkpoint fetch is a manually-run `gdown` command printed in an error message (`_neural_mi.py:236`), never executed by mlframe itself.

This corroborates (rather than duplicates) every individual cluster report's own "N/A" conclusion for this angle; this pass's contribution is running the exhaustive grep across files outside any single cluster's assignment and stating the tree-wide verdict explicitly, as the brief requires.

## Packaging (`pyproject.toml`) — dependency pinning & licensing discipline

Overall verdict: **exceptionally disciplined** for a project of this size. Positive observations (not findings):
- Every version floor/cap on ~90 declared dependencies (core + all extras) carries an inline comment naming the concrete reason (a CVE/GHSA/PYSEC advisory, a wheel-availability gap, an ABI break, a real reproduced crash) — nothing is a bare guess.
- `[tool.deptry]`/`[tool.bandit]`/`[tool.codespell]`/`[tool.importlinter]` configs are all live, reasoned, and specific (no blanket suppressions without a documented cause).
- `license = "MIT"` + `license-files = ["LICENSE"]` is correctly declared at the project level (`LICENSE` exists at repo root, confirmed).
- Security-motivated transitive floors exist for at least 6 named CVE/GHSA/PYSEC advisories (setuptools, pillow, cryptography, aiohttp, starlette, tornado) purely to raise a transitive resolution above a patched version — a genuinely proactive practice.

The one real gap is X_SECURITY_API_PACKAGING-5 above (unpinned git dependencies for the two first-party sibling packages). The vendored-code licensing gap (X_SECURITY_API_PACKAGING-6) is the other packaging-adjacent item, already tracked elsewhere.

## Cross-file sklearn-estimator-contract audit

Five real sklearn-estimator classes exist in this module: `MRMR` (`mrmr/_mrmr_class.py`), `GroupAwareMRMR` (`group_aware.py`), `StabilityMRMR` (`stability.py`), `StabilityFESelector` (`_stability_fe.py`), and `MRMRTreeRescued` (`_mrmr_tree_rescue.py`, a thin `MRMR` subclass that inherits its parent's contract compliance for free — no issues found there).

- **`__init__` hygiene**: all five correctly store constructor arguments unmodified with zero validation logic inside `__init__` itself (validation deferred to `fit()`), matching the sklearn convention (`clone()`/`get_params()`/`set_params()` round-trip safety). `MRMR.__init__`'s use of `store_params_in_object(obj=self, params=get_parent_func_args())` as a bulk-assignment helper is mechanically equivalent to ~300 individual `self.x = x` lines and does not itself violate the convention (the live regression it is currently causing, CORE_CLASS-1 in `core_class.md`, is a dependency-version bug, not a contract-design bug, and is not re-flagged here).
- **Parameter validation completeness**: wildly inconsistent across the five classes (see X_SECURITY_API_PACKAGING-3) — `StabilityMRMR` is the strongest example in the whole module (explicit, actionable per-field `ValueError`s), `GroupAwareMRMR` has none for its own continuous knobs, `MRMR` defers to a large ad hoc `_validate_string_params`/`_validate_inputs` pass (extensively covered by other clusters, not re-audited here).
- **`get_feature_names_out`**: inconsistent (X_SECURITY_API_PACKAGING-1) — present on 2 of 4 transformer-contract classes.
- **Estimator-wrapping design**: `StabilityMRMR`/`GroupAwareMRMR` both accept an arbitrary `estimator=` instance (clone-and-refit design, works with any compatible selector); `StabilityFESelector` instead hardcodes MRMR via `_resolve_mrmr_cls()` and takes a raw `base_mrmr_params: dict` — a legitimate alternate design (it needs MRMR-specific recipe-replay internals `stability_select_fe` provides), but it means "wrap any selector" is not a uniform capability across the three stability/grouping wrappers in this module, worth a docstring note for anyone assuming interchangeability. Not raised as a numbered finding (design choice, not a bug), noted here for completeness of the cross-file contract review.
- **`__sklearn_tags__`/`_more_tags`**: none of the five classes override sklearn 1.6+'s tags mechanism; they all inherit the default from `BaseEstimator`+mixins. No concrete failure was found or reproduced from this (the module's own `sklearn_matrix` pytest marker already pins cross-version sklearn-surface contracts), so this is noted only as a "checked, no issue found" item, not a finding — flagging a tags mismatch without a reproduced failure would be exactly the kind of hand-waved hypothesis the project's own review conventions warn against.

## Proposals

1. **Add `get_feature_names_out()` to `StabilityMRMR` and `StabilityFESelector`** (closes X_SECURITY_API_PACKAGING-1): both already know their exact output column set post-fit (`self.feature_names_in_[self.support_]` / `out.columns` from the last `transform()`); expose it the same way `MRMR`/`GroupAwareMRMR` already do. Add a regression test that wraps each in a `Pipeline`, calls `.set_output(transform="pandas")`, and asserts `pipeline.get_feature_names_out()` succeeds and returns the expected names — this would fail today on both classes.
2. **Introduce one shared, correctly-locked bounded-cache utility** (closes X_SECURITY_API_PACKAGING-2) — e.g. a small `_thread_safe_bounded_cache.py` (or a `pyutilz` addition, given the pattern recurs identically across GPU-residency, FE-gate, and info-theory files that don't otherwise share code) implementing the "get-or-compute, evict-oldest-above-N, single lock" idiom once, then migrate the >=13 identified call sites to it one at a time, prioritizing `_oracle_scorer_select.py`'s `_ROWS_CACHE` (already empirically proven to crash under contention) and `MRMR.clear_fit_cache()` (public API, documented as a between-fits maintenance call, currently the only unlocked mutator of an otherwise lock-protected cache). A single stress test harness (many threads, forced-tight eviction budget, assert zero `KeyError`/`RuntimeError`) parametrized over all migrated sites would give this fix-wave one shared regression test instead of 13 bespoke ones.
3. **Pin `pyutilz`/`py-ci-shared` to a specific commit or tag** (closes X_SECURITY_API_PACKAGING-5) in `pyproject.toml` (`git+https://github.com/fingoldo/pyutilz.git@<tag-or-sha>`), bumped deliberately alongside a changelog entry when a new pyutilz feature is needed — this converts today's "whatever `master` is at install time" into a reviewable, revertible dependency bump and would have caught this session's `CORE_CLASS-1` regression (a same-day, unreviewed-by-mlframe default-argument flip) before it ever reached a real `MRMR.fit()` call.
4. **Add validation to `GroupAwareMRMR.fit()`** (closes X_SECURITY_API_PACKAGING-3): `if not (0.0 < self.corr_threshold <= 1.0): raise ValueError(...)`, `if not (0.0 <= self.min_reduction < 1.0): raise ValueError(...)`, mirroring `StabilityMRMR`'s message style (name the class, name the param, show the got-value).
5. **Converge `CatFEConfig` onto the `_MRMRSubConfig` pydantic pattern** (closes X_SECURITY_API_PACKAGING-4), or at minimum backfill its missing field-level range checks per CAT_INTERACTION_A-9's list, so the module has one validation idiom (or two deliberately-scoped ones with a documented reason) rather than an accidental split between "new code gets rigorous pydantic bounds" and "old code gets whatever `__post_init__` happened to check."
