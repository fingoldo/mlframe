# FE redundancy / synergy cluster audit (2026-07-22)

## Scope

This cluster covers 20 files (9,657 LOC total) implementing: joint-synergy pair/combo detection that
recovers zero-marginal (XOR-like) interactions the marginal MRMR screen misses (`_fe_synergy_screen.py`,
`_fe_synergy_exhaustive.py`); a DPI-based early-stop that proves the current FE selection has already
captured all the information the raw observables carry (`_fe_sufficient_summary.py`); an O(p) interaction-
propensity pre-rank that keeps the synergy sweep tractable on wide frames (`_fe_interaction_prerank.py` +
`_fe_interaction_prerank_kernels.py`); a CPU edge-binning MI twin for GPU/CPU parity (`_fe_edge_mi.py`); the
raw-vs-engineered conditional-redundancy drop that removes a raw operand fully subsumed by a surviving
engineered child (`_fe_raw_redundancy_anchors.py` / `_helpers.py` / `_drop.py`); the engineered-vs-engineered
CMI redundancy gate and its permutation/analytic null (`_fe_cmi_redundancy_null.py`, `_fe_cmi_redundancy_gate.py`);
usability-aware retention of pure single-pair forms a cross-mix trapped (`_fe_pure_form_retention.py`); three+one
extra FE families -- rare-category, conditional residual, RankGauss, conditional dispersion
(`_extra_fe_families.py`, `_extra_fe_families_dispersion.py`, `_extra_fe_families_dispersion_resident.py`); the
meta FE-flag recommender (`_meta_fe_recommender.py`); the pairwise-modular residue detector + its GPU-resident
twin (`_pairwise_modular_fe.py`, `_pairwise_modular_resident.py`); and the row-argmax / conditional-gate
detectors, production + experimental-prototype (`_conditional_gate_fe.py`, `_conditional_gate_fe_proto.py`).

Overall impression: this is a mature, heavily-fought-over corner of the codebase. Nearly every function
carries a dated rationale comment citing a measured bug/regression and its fix, dozens of `bench-attempt-
rejected` notes are honored, GPU-resident twins consistently fall back to the exact host path on any fault,
and mypy is clean across all 20 files (`python -m mypy --ignore-missing-imports` — 0 errors). No P0s found.
Three P1s (below) are genuinely new; the rest of the material is either already-fixed prior findings
(confirmed via current-code inspection, not restated) or new P2 polish.

## Proposals

1. **Fix FE_REDUNDANCY_SYNERGY-1 the same way the CUDA branch already does it**: add a `batch_pair_mi_njit_prange`-backed KTC entry (`kernel_tuning_cache`, axes `n_samples, n_pairs`) mirroring `measured_pairs_per_second`, and route the CPU-only `decide_exhaustive_sweep` branch through it instead of the hardcoded `2.0e3`. Small, mechanical, directly closes the docstring's own "NEVER hardcoded" claim.
2. **Fix FE_REDUNDANCY_SYNERGY-2** by hoisting `_all_relevant_raws = set().union(*_sub_parents.values())` once per `ei` (right after the dict comprehension that builds `_sub_parents`) and iterating that instead of `raw_name_set`; bit-identical result (the excluded raw names never had a candidate anyway), pure algorithmic-complexity fix.
3. **Fix FE_REDUNDANCY_SYNERGY-3** by protecting `_Y_DENSE_MEMO`'s read-evict-write sequence with a `threading.Lock()` (cheap — this path is not a hot per-candidate loop, it fires once per `apply_cmi_redundancy_gate` call) or by switching to `collections.OrderedDict`'s own thread-unsafe-but-atomic-per-op pattern replaced with an explicit lock; alternatively cap the memo more simply via a `functools.lru_cache`-style wrapper that is itself GIL-atomic per call (still needs a lock for the size-based eviction, since that's the actual race). A regression test would need two threads racing on `apply_cmi_redundancy_gate` with >8 distinct fingerprints to reproduce the `RuntimeError` deterministically (or mock `_Y_DENSE_MEMO` with an injected sleep to widen the race window).
4. **One grep-driven pass** to fix FE_REDUNDANCY_SYNERGY-9's six stale self-referential log-line-number strings (trivial, no logic change) — matches the "grep ALL instances, fix one pass" house convention, and this cluster's own comments (2026-06-13 etc.) show the team already does this style of sweep for other classes of bug.
5. **Consolidate the bare unlogged GPU-strict-flag probes** (FE_REDUNDANCY_SYNERGY-11/-12, 7 sites total across `_conditional_gate_fe.py` + `_pairwise_modular_fe.py`, plus the 3 remaining in `_meta_fe_recommender.py` from FE_REDUNDANCY_SYNERGY-13) into one shared `_probe_flag(fn, default=False)` helper that always does `except Exception as e: logger.debug(...); return default` — "fix once fixes many" per the house convention, rather than patching each site independently a second time.
6. **Add the `test_raw_redundancy_anchors_direct.py` test** already proposed in `test_coverage.md` (call `build_raw_redundancy_anchors()` directly on a small synthetic fixture; assert all 4 early-return branches; compare `gate_resident=True` vs `False` outputs on identical input) — this is the single highest-value coverage gap in this cluster given the file's size (347 LOC) and complexity (dual host/GPU-resident binning, 4 short-circuit branches).
7. **Reconcile FE_REDUNDANCY_SYNERGY-6's two occupancy-floor formulas** to one shared helper (`_min_rows_for_occupancy(n_cells, kt, min_rows_per_cell)`) called from both `_pair_mm_mi_njit`/`joint_synergy_mi` and `detect_synergy_combos`, so a future edit to the floor's rationale only needs to change one place.
8. **Escalate-stage batching** (`_pairwise_modular_fe.escalate_modulus`): the fine-grid modulus refinement scores each of the ~15 candidate moduli via a separate `_residue_mi` call rather than the batched `_residue_grid_mi` the cheap-scan stage already uses. Low priority (bounded to `top_k<=4` responded hits per fit, so ~60-120 calls worst case) but a trivial follow-on now that the grouping-by-effective-nbins logic already exists in `_residue_grid_mi`.
