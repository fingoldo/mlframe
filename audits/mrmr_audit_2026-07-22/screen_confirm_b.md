# SCREEN_CONFIRM_B — Permutation-testing kernels & maxT noise floors (2026-07-22)

Scope: `permutation.py` (CPU `mi_direct` + its njit permutation kernels: joblib-worker `parallel_mi`,
`parallel_mi_prange(_with_null)`, Besag-Clifford sequential test, the analytic-large-n-null fast path),
`_permutation_null.py` (Westfall-Young maxT gain-floor family for order-1/2/3 candidate pools, CPU njit +
shuffle-gen), its two resident-GPU twins (`_permutation_null_resident.py`, order-1;
`_permutation_null_pair_resident.py`, order-2) plus their KTC crossovers
(`_permutation_null_resident_ktc.py`, `_permutation_null_shufflegen_ktc.py`), and `_conditional_permutation.py`
(Berrett/Wang/Barber/Samworth 2020 conditional permutation test, a D10 research knob). Together these
implement every "is this MI/gain real or chance?" primitive MRMR's screening and confirmation stages consume:
per-candidate permutation p-values/null-means, the pool-wide maxT chance-ceiling floors, and the
conditional-independence test. This is a re-audit of a cluster the 2026-07-20 audit (`c2_screen_confirm.md`)
and the 2026-07 numstat/selection critiques (`mrmr_crit_numstat.md`, `mrmr_crit_selection.md`) already covered
heavily (N-F1/N-F5/N-F7/N-F8/S-F1, all DONE or DOC per the critique tracker) — this pass cross-references those
dispositions against the CURRENT code and hunts for gaps the prior passes' own stated scope excluded
(the numstat critique explicitly scoped to the four `compute_relevance_score` call sites it named; it never
examined the large-n analytic-null branch or `_conditional_permutation.py`).

Angle #9 (SQL/HTTP/UI applicability) confirmed N/A: these seven files are pure numeric kernels over in-memory
numpy/cupy arrays — no DB/network/subprocess/eval/exec/pickle/yaml.load/UI surface exists anywhere in this
cluster. No generated HTML/markdown/log message embeds an untrusted string (log messages interpolate only
`type(exc).__name__`/`repr(exc)` and numeric candidate identifiers, never raw feature names or user-supplied
strings that could later render as markup).

## Proposals

- **Single-estimator-consistency test for `mi_direct`'s plain confidence contract**: extend
  `test_mrmr_critique_nf1_mm_null.py` (or a new `test_mi_direct_mm_confidence_path.py`) with an end-to-end
  `mi_direct(..., npermutations=64, parallelism="inner")` call under `set_mi_miller_madow(True)`, asserting the
  reported `confidence` differs from the plug-in-computed reference by less than the plug-in-vs-MM bias gap —
  would fail today (SCREEN_CONFIRM_B-1) and catch any regression once fixed. Thread `use_mm=(use_mi_miller_madow()
  and not _use_su)` / `use_cs=(...)` into `parallel_mi`, `parallel_mi_prange`, and both Besag-Clifford kernels,
  mirroring the existing `parallel_mi_prange_with_null` signature.
- **Gate the analytic-null fast path on MM/CS, or apply the correction inside it**: add
  `not use_mi_miller_madow() and not use_mi_chao_shen()` to `_analytic_ok`'s condition (falls through to the
  exact permutation path unchanged, matching the existing SU/sparsity fall-through pattern), OR — better,
  since the analytic null mean IS the MM bias term — have the analytic branch return `_ax_mi - _ax_nm` as
  `original_mi` (unconditionally, not just on the non-significant branch) whenever MM is active, restoring
  continuity with the sub-threshold path. Ship a regression test at `n` straddling `analytic_null_min_n()`
  (e.g. 24,999 vs 25,001 rows, same underlying distribution) asserting the reported relevance doesn't jump.
- **Implement (or remove the claim of) nearest-stratum borrowing in `conditional_permutation_test`**: either
  implement Berrett et al.'s actual local-permutation fallback for singleton strata (borrow the nearest
  non-singleton stratum's index pool for the shuffle), or rewrite the docstring to accurately describe the
  current behavior (silently excludes singleton-stratum rows from permutation) and add an explicit
  `min_stratum_size`/coarsening knob so `evaluation.py`'s `z_comp` composite doesn't silently degrade CPT power
  as `selected_vars` grows. Ship a biz_value test with `nbins_z` swept from low to `n`-scale cardinality showing
  the test's power (P(reject | true synergy)) degrading, to make the current limitation visible/monitorable
  even before a fix lands.
- **Route `mi_direct`'s internal `prefer_gpu` gate through `gpu_globally_disabled()`**, and additionally pass
  `prefer_gpu=False` explicitly from `_confirm_predictor.py`'s plain-`mi_direct` fallback branch (belt-and-braces:
  the dispatcher-level fix per `_gpu_policy.py`'s own architectural intent, PLUS the caller no longer needs to
  trust a callee it already decided not to use). Add a regression test setting `MLFRAME_DISABLE_GPU=1` with
  `full_npermutations>=32` and asserting no `mi_direct_gpu` call occurs (spy/monkeypatch), mirroring
  `test_noise_gate_gpu_optout_regression.py`'s existing pattern for the noise-gate dispatcher.
- **Add a circuit breaker + WARNING log to the order-1 resident maxT floor**, mirroring
  `_permutation_null_pair_resident.py`'s `_PAIR_MAXT_GPU_FAILED` pattern exactly (a module-level
  `_ORDER1_MAXT_GPU_FAILED` flag + `trip_/reset_order1_maxt_gpu_circuit_breaker()`), and have
  `pooled_permutation_null_gain_floor`'s own `except Exception` blocks log at WARNING with `exc_info=True`
  before falling back, instead of leaving that entirely to (currently nonexistent) caller-side wrapping.
- **Split `permutation.py`** before it crosses the 1000-LOC backstop: move the three Besag-Clifford kernels +
  `shuffle_arr_lcg`/`_shuffle_arr_lcg_kernel` to a new `_permutation_besag_clifford.py` sibling, re-exported from
  `permutation.py` for backward compatibility (per the monolith-split convention: AST-audit the sibling for any
  unresolved parent-module name before commit).
