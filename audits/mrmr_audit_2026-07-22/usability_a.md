# Usability-aware selection bridge, estimator/composition zoo, and low-level infra (cluster `usability_a`)

This cluster covers the "utility zoo" tier of the MRMR filters package: alternative MI estimators
(`estimators.py`, dead from `MRMR.fit`'s perspective), non-polynomial FE bases (`bases.py`), two
standalone cascaded/validated pair-FE helpers (`composition.py`), shared constants/pure-Python
helpers (`_internals.py`), the legacy monolith re-export shim (`_legacy.py`), Boruta-style
all-relevant selection (`_boruta.py`), Windows-loky-safety + fit-constant-memmap helpers
(`_joblib_safe.py`), the accuracy-caveat warning registry (`_param_accuracy_warnings.py`), the
linear/universal usability-list wiring layer (`_usability_lists.py`) and its heavyweight
candidate-pool-builder + CV-greedy engine (`_usability_aware_selection.py`), two more standalone
selection primitives (`_per_fold_majority_accept.py`, `_null_importance.py`), numba prewarm/utility
shims (`_prewarm.py`, `_numba_utils.py`, `_numba_warmup.py`), the package facade (`__init__.py`),
and a 22-line BC shim (`pre_screen.py`). Confirmed via `git log` that none of these 17 files have
been touched since the 2026-07-20 audit (composition.py/estimators.py/bases.py/_boruta.py/
_joblib_safe.py/_param_accuracy_warnings.py line numbers below are byte-identical to that audit's
citations), so every item the 2026-07-20 `c8_usability_wrappers.md` report already raised for these
files is still open exactly as described there -- flagged below with a one-line pointer rather than
restated. New effort went into the files that report didn't cover at all (`_joblib_safe.py`'s
`run_in_big_stack_thread` / prewarm / numba-utils / `__init__.py` / `_boruta.py` edge cases /
`_null_importance.py` / `_per_fold_majority_accept.py`) and into re-verifying the previously-flagged
items empirically rather than by inspection alone. `mypy` (`--cache-dir=.mlframe_mypy_cache_shared
--ignore-missing-imports`) is clean across all 17 files -- zero errors. Confirmed no DB/network/UI
surface exists anywhere in this cluster (checklist item 9 N/A): no SQL, no HTTP client/server code,
no browser-facing HTML/report generation; the closest thing is log messages built from feature names
via safe `%`-style logging (no f-string/`.format()` injection risk found).

## Angle-by-angle notes (no separate finding rows; folded in for completeness)

- **CPU/GPU parity**: `_usability_aware_selection.py`'s gated GPU paths (`_GPU_USABILITY()`, `gpu_abscorr`, `gpu_abscorr_batch`, the resident pair-combo table) are all guarded with a documented fallback-to-exact-CPU-path on any exception, and the file's own comments carefully distinguish "byte-identical default" vs. "selection-equivalent under `_seleq`" -- consistent with the 2026-07-20 and 2026-07-22 GPU-residency reports' verdicts on this design; no new parity gap found in the code owned by this cluster. `bases.py`/`estimators.py`/`composition.py`/`_boruta.py`/`_null_importance.py`/`_per_fold_majority_accept.py` have no GPU twin at all -- N/A.
- **Reproducibility/RNG**: `estimators.py`'s KSG permutation test seeds correctly per-permutation (`rng.integers` then per-worker `np.random.default_rng(seed)`); `_boruta.py`'s shadow shuffle uses one `Generator` seeded from `random_state`; `_usability_lists.py`'s `seed = int(getattr(mrmr, "random_seed", None) or 0)` was checked against the B-4-style "reads only the deprecated alias" bug pattern found elsewhere in the 2026-07-20 audit -- **verified NOT a bug here**: `build_usability_lists` runs exclusively inside `_fit_impl_core`, which itself runs inside `_mrmr_class.py`'s `fit()` scoped window (lines ~3712-3716) that deliberately writes the *resolved* effective seed onto `self.random_seed` for exactly this kind of cross-file read, then restores the original in `finally`. No false positive reported.
- **Security**: no `eval`/`exec`/`subprocess`/`os.system`/`yaml.load` anywhere in these 17 files; the only "unpickling" language is a docstring note (`_internals.sanitize` converts numba `typed.Dict` back to plain Python so the result CAN BE pickled, not that it deserializes untrusted input). `_joblib_safe.py`'s temp-file paths are built entirely from `tempfile.mkstemp` (no user-controlled path component) -- no traversal risk.
- **`_legacy.py` / `__init__.py` / `_numba_utils.py` / `_numba_warmup.py` / `pre_screen.py`**: no bugs found. These are thin, well-tested infra shims; `_prewarm.py`'s idempotency-guard design (flag set before the sweep runs) is deliberately pinned by `test_prewarm.py::test_regression_module_level_guard_short_circuits_second_call`, and `_prewarm.__all__`'s narrower surface than its actual exports is likewise deliberately pinned by `test_public_api` -- both initially looked like bugs on inspection but are confirmed-intentional, tested behavior once cross-checked against the test suite (not reported as findings).
- **`_per_fold_majority_accept.py`**: no bugs found; validates empty/mismatched-shape inputs explicitly (an uncommonly disciplined choice compared to several siblings in this cluster).

## Proposals

- **(bug-fix)** Bound `_FIT_MEMMAP_CACHE` and actually delete the backing files: either `atexit.register` an unlink-all-cached-paths cleanup, or switch to `tempfile.TemporaryDirectory` for the whole process and let its own cleanup fire, or add a simple LRU cap (e.g. keep the last N distinct fit-constant matrices) so a long-running process doesn't accumulate unbounded disk usage. Ship a regression test that asserts a resource sweep of >K distinct-content fits does not leave more than K files behind.
- **(edge_case)** Add an explicit `if n_iterations < 1: raise ValueError(...)` to `boruta_select` and `if n_shuffles < 1: raise ValueError(...)` to `null_importance_filter`, each with a regression test pinning the clear message (replacing the current scipy/numpy internal-error leakage).
- **(coverage_gap)** Add a direct unit test for `run_in_big_stack_thread`: (1) a function that raises propagates the same exception type/message to the caller thread; (2) a function that returns a value round-trips it; (3) on the current (Windows) host, `_NEEDS_BIG_STACK` is True and the big-stack thread path actually engages (not just the pass-through).
- **(hardening)** Give `compose_pair_fe` a cheap `len(set(feature_names)) == len(feature_names)` guard (raise or dedupe-with-suffix) so a duplicate-named input can't silently alias two columns' MI scores.
- **(residency_step)** Consider giving `_usability_aware_selection.py` the same flat-sibling split (`_usability_aware_selection.py` + `_usability_pool_build.py`) the repo's monolith-split convention calls for once it crosses 900 lines, splitting along the pool-build / greedy-selection seam noted above.
