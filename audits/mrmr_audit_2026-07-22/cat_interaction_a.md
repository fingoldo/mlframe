# cat_interaction_a — Categorical interaction-information FE (cat_interactions cluster)

## Scope

This cluster is the "cat-FE" pipeline for `MRMR`: for every pair (and, opt-in, k-way tuple) of categorical/pre-discretized
columns it computes the Jakulin Interaction Information `II(Xi,Xj;Y) = I(Xi,Xj;Y) - I(Xi;Y) - I(Xj;Y)`, keeps synergistic
survivors, and materialises them as new ordinal/target-encoded columns with replay recipes for `MRMR.transform`.
`cat_interactions.py` is the thin orchestrator/re-export facade; the actual `run_cat_interaction_step` body, the njit
pair-search/marginal-screen kernels, Miller-Madow bias correction, UCB1-bandit and fixed-budget permutation confirmation
(CPU prange + cupy + conditional/IPF nulls), post-screen refinement (bootstrap CI, anti-redundancy, K-fold stability,
k-way greedy expansion + coordinate-ascent), and the weighted-kernel/target-encoding helpers each live in their own
sibling module (a monolith-split done specifically to stay under the repo's ~800-900 LOC guideline). Two smaller,
independent sibling families also live in this slice: `_cat_pair_fe.py`/`_cat_triple_fe.py` (Layer 89/94 "hybrid" cat×cat
and cat×cat×cat synergy crosses, opt-in via `fe_cat_pair_enable`/`fe_cat_triple_enable`, simpler point-estimate-only
design, no permutation testing) and the K-fold target-encoding / count-frequency / cat×numeric-residual encoders
(`_target_encoding_fe.py`, `_target_encoding_order_stats.py`, `_count_freq_interaction_fe.py`) that are Layer-33/34
production-grade leak-safe OOF encoders unrelated to the II-synergy machinery. `cat_fe_state.py` holds the
`CatFEConfig`/`CatFEState` dataclasses.

Cross-referenced against `audits/mrmr_audit_2026-07-20/c7c_cat_interaction_fe.md` (9 findings) and
`_benchmarks/mrmr_critique_2026_07/` (FE-F4). Most of the prior `B-19` sample-weight gap (`_cat_interactions_step.py:348`
in the old file layout) has been fixed since 2026-07-20 (commit `6a09aa8b0`, "Fix B-19: cat-FE downstream
confirmation/rerank steps now honour sample weights") for MM re-rank, anti-redundancy re-rank, K-fold stability, bootstrap
CI, k-way expansion/coordinate-ascent, Westfall-Young, and the fixed-budget permutation path's default joint-independence
null. `FE-F4` (naive target-encoding leak in `_compute_target_encoding`) is fixed (commit `bf7023e3a`). The prior
K-fold-target-encoding statistic (multi-class expected-class-index semantics) test gap is still open (no new test found).
The prior k-way-XOR biz_value test gap is now closed (`test_cat_interactions.py` has a genuine 3-way-XOR
`max_kway_order=3` recovery test). This report's new findings focus on: (a) a deeper, still-open root cause behind the
weight-propagation bug that the 2026-07-20 fix's own commit message did not identify, (b) a GPU-off-switch gap matching
the already-known `B-1`/`B-2` bug class in files the prior GPU-residency review did not cover, and (c) the parts of the
checklist (module-size, parameter-validation completeness, cross-family duplication, doc/impl mismatches) the prior audit
did not systematically apply to this cluster.

## Proposals

- **Fix the CAT_INTERACTION_A-1 root cause**: add a weighted variant of `_marginal_screen_njit` (or route it through `compute_mi_from_classes_weighted`/`weighted_class_freqs`, already used everywhere else in this cluster) and call it whenever `use_weights` is true in `run_cat_interaction_step`, so `marginal_mi_full` is weighted consistently with the joint-MI kernel it's differenced against. Ship a regression test per CAT_INTERACTION_A-10's fixture design (non-zero, asymmetric marginal MI) that fails pre-fix and passes post-fix.
- **Close CAT_INTERACTION_A-2**: thread `from ._gpu_policy import gpu_globally_disabled` into `_perm_kernel_dispatch_use_gpu` and the pair-search `cfg.backend in ("gpu", "auto")` branches in `_cat_interactions_step.py`, matching the pattern already used elsewhere in the filters package (`_fe_gpu_strict.py`, `_usability_gpu.py`, the now-fixed `batch_pair_mi_gpu.py`/`friend_graph_gpu.py`).
- **Close the remaining B-19 sub-gap** (bandit-UCB1 unweighted, CAT_INTERACTION_A-3): either implement a weighted `_bulk_shuffle_and_compute_three_mis` variant (mirroring `_count_nfailed_joint_indep_weighted_serial`'s approach), or — as a cheap interim fix — auto-fall-back `perm_budget_strategy` to `"fixed"` whenever `weights is not None`, and promote the existing warning from `if weights is not None and verbose` to an unconditional `warnings.warn` (or at least `logger.warning` without the verbose gate) so silently-dropped weighting is visible by default.
- **De-duplicate the OOF K-fold encoder implementations**: `_cat_pair_fe._kfold_target_encode_codes`, `_target_encoding_fe.kfold_target_encode_fit`, and `_cat_target_encoding_and_weighted._compute_target_encoding` are three structurally-similar-but-independently-written K-fold OOF mean-of-y encoders in this same file cluster; converging on one validated, shared primitive (with the `n_folds >= 2` guard applied uniformly) would close CAT_INTERACTION_A-8 and reduce future-maintenance drift risk (three copies to keep in sync on any leak-safety fix, as already happened once with `FE-F4`).
- **Add the missing `CatFEConfig.__post_init__` range checks** (CAT_INTERACTION_A-9): `0 < bootstrap_ci_alpha < 1`, `0 < bootstrap_sample_frac <= 1`, `streaming_cache_kl_threshold > 0`, `target_encoding_smoothing >= 0`, `numeric_nbins >= 2`.
- **Split `_cat_confirm_permutation.py`** (CAT_INTERACTION_A-4): carve `_compute_westfall_young_corrected_p` + `_apply_fwer_correction` (~160 LOC, no dependency on the rest of the file besides `merge_vars`/`compute_mi_from_classes*`) into a new `_cat_confirm_fwer.py` sibling, re-exported the same way every other split in this cluster already is.
- **Document or reconcile the two cat-cross FE families** (CAT_INTERACTION_A-6): at minimum, cross-reference the two pipelines' docstrings so a user enabling both understands the overlap risk; ideally, either lift the Layer-89/94 path onto the same permutation-confirmation primitives `cat_interactions.py` already has (they're already siblings in this same package), or have one pipeline skip pairs/triples the other has already materialised in the same `fit()` call (both run inside the same `_fit_impl_core.py` code path and could cheaply consult each other's `appended` column lists).
- **Fix or correct the `cat_num_interaction_fit` docstring** (CAT_INTERACTION_A-7): either implement the claimed y-stratified fold assignment for binary targets, or (cheaper and arguably more honest, since num-residual leakage is about `num_col` not `y`) simply remove the false "stratified" claim from the docstring.
