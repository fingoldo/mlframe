# MI-greedy FE constructors + engineered-recipes replay package — audit report

Cluster scope: the generic MI-greedy / CMI-greedy feature constructors (`_mi_greedy_fe.py`, `_mi_greedy_cmi_fe.py`),
their GPU-batched MI/CMI scoring backends (`_fe_batched_mi.py`, `_fe_batched_mi_cmi.py`), the CPU FE-batcher
(`_fe_cpu_batch.py`), and the full `engineered_recipes/` package (the `EngineeredRecipe` frozen dataclass, the
`apply_recipe` dispatcher, and the per-kind builder/replay submodules: unary_binary [+ its GPU-resident twin],
factorize, hermite/cluster/target-encoding, orthogonal-basis/spline/Fourier, categorical encoding, missingness/
pairwise-ratio/mi-greedy-transform, grouped/temporal, and the name-simplification display helper). Together these
implement Layer 26 (marginal-MI-greedy) and Layer 60 (CMI-greedy) generic transform search, plus the leak-safe,
X-only "recipe" replay contract that lets `MRMR.transform()` reproduce every surviving engineered column on unseen
data without ever referencing `y`. The code is unusually heavily documented (dozens of dated bug-fix / bench-reject
notes inline) and mypy-clean; most prior-audit findings that touch this cluster are already fixed.

Angle 9 (SQL/HTTP/UI): confirmed N/A for the whole cluster — pure numpy/pandas/cupy computation, no DB/network/UI
surface, no generated HTML/report meant for a browser, no telemetry call, no file path built from a column name or
other user-controlled string. Angle 7 (security): no `eval`/`exec`/`subprocess`/`os.system`/`pickle.load`/`yaml.load`
anywhere in the cluster (grep-verified). mypy (`--cache-dir=.mlframe_mypy_cache_shared --ignore-missing-imports`) is
clean on all 18 assigned files (`Success: no issues found`).

## Proposals

1. **Thread `random_state`/`seed` through `greedy_cmi_fe_construct`** (MI_GREEDY_RECIPES-1 fix): add a `seed: int = 0` (or `rng: np.random.Generator | None`) parameter, default to today's `0xC011` only when unset so existing pinned tests stay green, and have `_fit_impl_core.py`'s call site pass `self.random_seed`. Add a regression test asserting two `MRMR.fit()` calls with different `random_state` (same X/y) produce different noise-floor permutation draws (currently identical).

2. **Guard the continuous-`y` truncation precondition** (MI_GREEDY_RECIPES-2 fix): factor the `_fit_impl_core.py` `<=32-unique -> int cast, else qcut(q=10)` binning logic into a shared helper (it is duplicated twice already, at `_y_for_mig`/`_y_for_cmi`) and call it from *inside* `greedy_mi_fe_construct`/`greedy_cmi_fe_construct` themselves rather than relying on every caller to pre-bin. Add a unit test that calls `greedy_cmi_fe_construct` directly with a raw continuous target confined to `[0,1)` and asserts the constructor does NOT silently collapse it to one class.

3. **Propagate EN-1 to `_grouped_recipes.py`** (MI_GREEDY_RECIPES-3 fix): add the same `canonical_group_token(k)` call the `_encoding_recipes.py` builders now use, in all five `_grouped_recipes.py` builders' key-cleaning comprehensions. Low risk (idempotent on already-canonical strings), closes the same footgun class.

4. **Fix or accept-and-test the `greater`/`less`/`equal` GPU dtype divergence** (MI_GREEDY_RECIPES-4): either cast the GPU path to match the CPU `int`-typed output (`.astype(cp.int64)` or equivalent) or, if the float output is intentional (e.g. avoids a dtype-churn re-upcast elsewhere in the resident pipeline), update `test_recipe_unary_binary_gpu_parity.py` to assert dtype equality (not just value equality after a `float64` cast) so the divergence is a pinned, deliberate contract rather than an untested accident.

5. **Direct unit test for `_cpu_col_chunk`** (MI_GREEDY_RECIPES-7): a small test forcing `max_cols_per_chunk=2` (or monkeypatching `_available_ram_bytes` to a tight budget) on a `K=10` candidate matrix, asserting `cpu_fe_batch_mi`'s multi-chunk loop produces the same MI vector as the single-call path (chunk-invariance).

6. **Consider draining the `_mi_greedy_cmi_fe.py` LOC exemption** (MI_GREEDY_RECIPES-5): the file's RawKernel sources (`_ENT_NNZ_SRC` + getters, ~120 LOC) and the `_factorize_dense_njit`/`_combine_factorize_njit`/`_renumber_joint`/`_renumber_joint_gpu` family (~330 LOC) are both self-contained, already-tested (`test_mi_greedy_fused_joint_entropy.py`, `test_renumber_joint_fused_combine.py`) blocks that could carve cleanly into `_mi_greedy_cmi_kernels.py` / `_mi_greedy_cmi_renumber.py` siblings once the "actively churning" perf-loop this file is mid-rewrite of settles, per the exempt-list's own stated plan.

7. **`assert`-free invariant check** (MI_GREEDY_RECIPES-8): replace the bare `assert` in `build_cluster_aggregate_recipe` with an explicit `if not isinstance(...): raise TypeError(...)` so the guard survives `-O`.
