# fit_impl_a — `_mrmr_fit_impl` fit-orchestration cluster

**Files owned:** `_fit_impl_core.py` (9344 LOC — deep-read lines 1-720, 3380-3420, 3660-3920 (via the caller in `mrmr/_mrmr_class.py`), 4530-5045, 5240-5533, 6560-7090, 6859-7090, 8455-8480, 8630-9344; the remaining ~3800 lines (the ~15 near-identical alternate-scorer/FE-family blocks between ~720-3395 and ~5045-6560) were TOC-scanned + structurally spot-checked rather than read line-by-line, since they are mechanically repetitive `fe_decide_on_subsample(...)` call sites, each ~60-100 LOC, differing only in the imported scorer function and local-variable prefix), `__init__.py` (26 LOC, full read), `_helpers.py` (440 LOC, full read), `_finalise.py` (325 LOC, full read), `_eng_dedup_batch_corr.py` (96 LOC, full read), `_fe_stage_temporal_agg.py` (112 LOC, full read).

This cluster is the literal body of `MRMR._fit_impl` — the ~9.3k-line orchestration function that runs the fit-cache/skip-retraining shortcut, ~45 independently-gated FE families (hybrid orthogonal-polynomial, MI-greedy, k-fold target encoding, count/frequency/cat-num interaction, missingness, ratio/log-ratio/grouped-delta, grouped-aggregation, temporal-aggregation, cluster-basis, bootstrap-MI, adaptive-arity, 12 alternate-scorer variants, ...), the cross-stage engineered-column near-duplicate dedup, discretization/categorize handoff, the greedy MRMR screen, a dozen post-selection "protection"/rescue passes (hinge, orth-basis-univariate, adaptive-Fourier, raw-redundancy-drop, usability-aware retention, empty-support fallback), and the final `support_`/`mrmr_gains_`/fit-cache bookkeeping. The five sibling files are Tier-E carve-outs (`_finalise.py`, `_fe_stage_temporal_agg.py`), a batched numba correlation kernel used by the cross-stage dedup (`_eng_dedup_batch_corr.py`), and small free helpers (`_helpers.py`, `__init__.py` facade). No DB/network/UI surface exists anywhere in this cluster — confirmed by grep (no `subprocess`/`eval`/`exec`/`os.system`/`pickle.load`/`yaml.load` in any of the six files) — so SQL/HTTP/UI best-practice angles are N/A; the only "generated artifact" risk is log messages interpolating feature names, which is safe (Python `%s` logging, no shell/HTML/SQL context). The code quality throughout is unusually high for a file this size: nearly every non-obvious branch carries a dated rationale comment citing the regression fixture it exists to fix, and mypy is clean on all six files (`Success: no issues found in 6 source files`).

## Proposals

1. **Concrete next carve candidate for `_fit_impl_core.py`.** The ~12 alternate-scorer FE dispatch blocks (`cmim`/`jmim`/`tc`/`ksg`/`copula`/`dcor`/`hsic`/`lasso`/`elasticnet`/`auto`/`ensemble`/`meta`, roughly lines 2062-2726 plus the earlier `plug_in`/hybrid pair block ~520-590) are structurally identical ~80-100 line bodies: bin `y` the same way, build the same kwargs, call `fe_decide_on_subsample(hybrid_orth_mi_<X>_fe_with_recipes, X, y, cols=..., degrees=..., basis=..., top_k=..., shared_subsample_idx=...)`, diff the appended columns, log. This is exactly the "self-contained, compute-and-assign, no early exit, explicit local threading" shape the maintainers' own carve criteria (`test_no_file_over_1k_loc.py` comment) call safely verbatim-extractable — and `_dispatch_default_scorer` in `_helpers.py` already proves the "route by scorer name" pattern works cleanly outside the main function. Replacing the ~12 blocks with one data-driven loop over a `(scorer_name, import_path, function_name)` table could plausibly collapse 1200-1500 lines without touching the genuinely control-flow-entangled parts of `_fit_impl`.
2. **The `_fe_live` memory-reclaim del-list is a manual, unenforced invariant.** Lines 5312-5357 hand-list all ~47 per-family intermediate `X_<abbrev>` variable names for an explicit `del` before `categorize_dataset` allocates its int-code matrix (verified currently *complete* — every `X_xxx, ... = ...` assignment in the file cross-checked against the del-list, all 47 match). Nothing enforces this stays in sync: a future FE family added without a matching `del` line would silently reintroduce the exact peak-RSS problem this block exists to prevent, with no test catching the gap. A cheap guard: assert at the end of that block that no local matching `^X_[a-z_]+$` other than the canonical `X` survives in `locals()`.
3. **`_mrmr_instance_state_size_bytes`'s generic `vars(instance)` walk (`_helpers.py`) is a good pattern** — it self-corrects as new fit-time state is added, unlike a hand-maintained attribute allowlist that silently drifts stale (the docstring documents exactly this prior bug). No action needed; noting it as a positive example other caches in the module could copy (e.g. any per-instance byte-estimator that still uses a hardcoded attribute list would benefit from the same treatment).
4. **`fe_decide_on_subsample`'s CLOSED-FORM-only correctness boundary is documented but not machine-checked.** The docstring in `_helpers.py` explains at length why it must never be used for OOF/data-dependent families (e.g. `binned_numeric_agg`), relying entirely on future authors reading the docstring before wiring in a new family. A cheap tripwire: a `_CLOSED_FORM_SAFE = frozenset({...})` allowlist of function names this wrapper is known-safe for, with a `warnings.warn` (not a hard fail, to stay permissive) when called with an unrecognised callable, would catch a future author accidentally routing an OOF family through the subsample-then-replay shortcut.
