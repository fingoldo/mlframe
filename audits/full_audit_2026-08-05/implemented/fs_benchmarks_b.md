## Nature of the code in scope

This cluster is almost entirely **exploratory/one-off benchmark and A/B-decision scripts** (the `bench_*`, `round2_*`/`round3_*`/`round4_*`/`round5_*`, and campaign scripts), not production library code. They are read by a human to make a ship/keep/reject call and are not imported by the production `mlframe.feature_selection` package. This shapes the findings: the review still applies all seven dimensions, but the P0/P1 bar (data corruption, wrong production model behaviour) rarely applies directly — most defects found are self-contained to the benchmark's own conclusions (an invalid speed number, a silently-dropped diagnostic row) or are code-quality/hygiene issues. One finding (FS_BENCHMARKS_B-1) is flagged P1 specifically because the same bug **pattern** (aliased in-place mutation of a pandas-backed array) is exactly the class of silent-corruption bug that would be a P0 if it ever migrated into a production hot path, and the benchmark's own conclusion is provably invalid because of it.

## Narrative

**FS_BENCHMARKS_B-1 (P1) — aliased in-place mutation silently corrupts the benchmark's own timing fixture.**
`bench_mrmr_fe_path_micro.py`'s `bench_e8_tonumeric_vs_asarray` compares an "old" `df.apply(pd.to_numeric).fillna(0.0).to_numpy()` path against a "new" `np.asarray(df, dtype=float)` + in-place NaN scrub, both timed via `_best_of(fn, n_iter)` which calls `fn()` repeatedly (1 warm-up + `n_iter` timed calls) against the *same* closured `df`. I verified empirically (`np.shares_memory(np.asarray(df, dtype=float), df.values)` returns `True` when `df`'s backing block already has `dtype=float64`, which is exactly this fixture's case since it is built from `rng.standard_normal((n, p))`) that `np.asarray(df, dtype=float)` returns a *view*, not a copy. The subsequent `a[np.isnan(a)] = 0.0` therefore mutates `df` itself. On the very first call the 2%-NaN fixture gets scrubbed in place; every one of the remaining `n_iter-1` timed calls then finds zero NaNs, so `if np.isnan(a).any(): a[np.isnan(a)] = 0.0` short-circuits to the cheap `False` branch and the boolean-indexed assignment (the operation actually under test) is never executed again. The reported "new" wall time is therefore an average that is heavily biased toward the cheap post-mutation calls, not the real per-call cost the pattern would have on fresh data (as it would in every real invocation in a production loop). The benchmark's own headline speedup number for this lever is invalid as a result. Separately, this demonstrates a live example of the general "aliasing + in-place mutation of caller-owned data" bug class the project's own CLAUDE.md explicitly calls out as a "silent correctness bug class" (coercion + error swallowing) — worth fixing here specifically because it is the kind of one-liner that gets copy-pasted into real code once a benchmark appears to endorse it.

**FS_BENCHMARKS_B-2 (P2) — `any(dict.values())` conflates "not all None" with "not all falsy".**
`fs_hybrid/run_experiment.py` computes `row["auc_mean"]` by filtering `None` entries out of `aucs.values()` and averaging the rest, but gates the whole expression on `any(aucs.values())` rather than `any(v is not None for v in aucs.values())`. Concretely: if two of the three downstream model fits (lgbm/logit/knn) raise and are recorded as `None`, but the third produces a genuine AUC of exactly `0.0`, `any([None, None, 0.0])` evaluates to `False` (every element is falsy) and the row is written with `auc_mean=None`, silently discarding the one real result instead of reporting it. I confirmed the surrounding code already knows the right pattern — the list comprehension one line earlier explicitly filters `if v is not None` — so the `any()` guard is the one place that regressed to a truthiness check. AUC exactly `0.0` is a rare but real outcome (a systematically-inverted classifier), so the failure mode is narrow but genuine, and it is exactly the class of "coercion/truthiness" bug the project's standing conventions ask reviewers to catch on sight.

**FS_BENCHMARKS_B-3..B-7 (P3) — dead/discarded-expression leftovers.**
Five separate spots across the `_benchmarks` cluster contain a computed value that is never assigned, printed, or otherwise used: an entirely unreachable, deliberately obfuscated helper function in `bench_pair_maxt_kernel_hoist.py` that duplicates logic the file already does inline a few lines later; and four bare `expr` statements (`round(...)`, `list(...)`, or an arithmetic expression) in various `round4_*` scripts that read as debugging leftovers where a `print(...)` or variable assignment was dropped during editing. None of these change behaviour (Python happily evaluates and discards them), but they are exactly what `ruff`'s `B018` ("useless expression") rule exists to catch, and each one is a small trap for a future reader who assumes the computed value is being used somewhere.

**FS_BENCHMARKS_B-8 (P3) — legacy `RandomState` in one file out of the whole family.**
`bench_medoid_corr_method.py` seeds its RNG via `np.random.RandomState(seed)` (`.randn`/`.integers` style) while literally every other file across the 147 reviewed — including its immediate siblings doing the same kind of seeded-scenario generation — uses `np.random.default_rng(seed)`. This is not a correctness defect (both are valid, seeded, reproducible RNGs), but it is a naming/API inconsistency the project's own conventions (S6/consistency-with-siblings) call out as worth fixing, and it is a one-line change.

**FS_BENCHMARKS_B-9 (P3) — one file in `fs_quality/` imports its sibling via `sys.path` hack instead of the package path its neighbors use.**
`qual24_adaptive_nbins_large_n_reg_confirm.py` reaches for `sys.path.insert(0, str(Path(__file__).resolve().parent))` plus a bare `from mrmr_largeN_campaign import _make_dgp`, while `mrmr_largeN_campaign2_jmim_threshold.py` and `mrmr_synergy_regime_bench.py` — in the very same directory, doing the same kind of cross-script reuse — both use the clean `from mlframe.feature_selection._benchmarks.fs_quality.mrmr_largeN_campaign import ...`. Purely cosmetic (both import styles work when the file is run as `python qual24_....py` from its own directory), but it is the kind of small inconsistency worth normalizing while nearby files are touched.

## Dimensions with zero findings (explicitly noted, not omitted)

- **Data leakage (train/val/test/OOF boundary violations):** none found. Every benchmark that fits a stateful transform (target encoding, median/threshold gates, quantile edges, cluster reps) fits it on the TRAIN split only and replays the stored parameters on TEST; this is called out explicitly and correctly in comments/docstrings throughout (e.g. `round4_fe_median_gated_bench.py`, `bench_numeric_cat_te_feedforward.py`, `fe_richops_bench.py`'s `_fit_params`/`_apply_op`).
- **Reproducibility (unseeded RNG / hidden global state):** essentially clean; every stochastic generator is seeded via `np.random.default_rng(seed)` (or, in the one exception above, `RandomState(seed)` — still seeded). No unseeded `np.random.rand()`/module-global RNG usage was found in the reviewed files.
- **Calibration correctness / sample_weight threading:** not exercised by this cluster (these are feature-selection quality/perf benchmarks, not calibration or weighted-loss benchmarks); no findings because the dimension largely does not apply here.
- **Mutable-default-argument bugs:** none found; no `def f(x, cache={})`-style defaults anywhere in the reviewed files.
- **Overly broad `except` clauses hiding real errors:** the cluster uses broad `except Exception` extensively, but essentially always paired with `logger.debug(...)` (never silent) and a `# nosec B110`/documented "best-effort path" comment, consistent with these being human-read exploratory scripts where "one config in a sweep crashed, log it and keep going" is the intended behavior, not error-swallowing. No instance was found where a broad except hides a systematic failure the way the project's own documented `_MI_BACKEND` regression did in production code.
- **Empty/degenerate-input robustness of the benchmark harnesses themselves:** not applicable in the traditional sense — these scripts construct their own synthetic inputs (never accept arbitrary caller data), so classic "empty DataFrame" / "all-NaN column" edge cases are not reachable attack surface the way they would be for a public API.
