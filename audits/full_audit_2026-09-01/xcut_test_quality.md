# xcut_test_quality
Test files reviewed: 3272 `test_*.py` (3411 `.py` total under `tests/`) swept by targeted AST/regex scans across all 100 test directories; ~40 files read in full.

## Summary
The suite has unusually strong meta-gates (`tests/test_meta/test_no_inspect_getsource.py`, `test_no_source_text_proxy.py`, `test_no_single_shot_timing_assertion.py`, `test_no_unsafe_module_reload.py`) and the two originally-confirmed machine-premise GPU-VRAM defects have genuinely been fixed (`tests/feature_selection/filters/test_fe_gpu_vram_cushion_no_reprobe.py` now simulates cupy's absence instead of asserting it). The residual damage is concentrated in what those gates cannot see. The largest single problem is a 322-assertion cluster of source-text proxies in `tests/training/test_audit_*.py` that routes every prod-file read through a local `_read()` helper: because the AST scanners key on a `read_text()` call bound in the asserting scope, that one level of indirection makes all of them invisible, and they assert on exact lambda bodies, exact log-string wording including newlines and indentation, and even on the presence of explanatory comments. The second cluster is timing: the single-shot gate only recognises a division compared to a constant, so ~40 `assert elapsed < X` sites and three `cProfile.total_tt < X` sites pass straight through, while the four sites that are real budget contracts (`test_biz_val_runtime_budget.py`) skip themselves under xdist, i.e. never execute on CI -- the only place the full suite runs. Beyond those: one illegitimate fuzz canonicalisation that disables RFECV for every imbalanced binary target because sklearn crashes on its single-class inner folds; an undersized 1%-positive fixture whose own docstring records per-seed degeneracy and whose floors were consequently softened to "majority of seeds"; eight coverage tests that skip themselves if a first-party private helper is renamed; a session-fixture mutation tripwire that is structurally incapable of failing; and one dead `raising=False` mock aimed at a name that does not exist in the module it targets.

## Findings

### XCUT_TEST_QUALITY-1 [P1] source-text-assertion
**File:** tests/training/test_audit_global_rng_mutation.py:85
**Summary:** A 33-file, 322-assertion cluster asserts on prod source text read through a local `_read()` helper, defeating both source-proxy meta-gates by one level of indirection.

Where no behavioural equivalent exists, add these files to the existing `WHITELIST` in `tests/test_meta/test_no_inspect_getsource.py` so the debt is tracked rather than invisible, and extend `_prod_source_read_text_names` to follow one level of intra-module helper indirection (a function whose body contains `read_text()` and whose return feeds a `.find` / `in` compare).
**Evidence:** grep -c over the 33 files defining `def _read(` yields 322 source-text assertions. ### XCUT_TEST_QUALITY-2 [P1] source-text-assertion
**File:** tests/training/test_audit_stable_sort_determinism.py:139
**Summary:** Determinism of RFECV/SFFS tie-breaking is asserted by pinning the exact source text of a lambda, not by running the selector twice on tied data.

### XCUT_TEST_QUALITY-4 [P2] source-text-assertion
**File:** tests/training/test_ensembling_caching_future_fixes.py:237
**Summary:** Asserts the byte order of two code fragments inside a prod module read via `open(...).read()`, dodging the read_text-keyed position-proxy gate.
**Failure scenario:** `reuse_pos = src.index("cached_pb = _per_bin_first_pass.get")` (:236) followed by `assert reuse_pos < m.start()` (:239) claims the reuse branch precedes the recompute branch. That holds for any file where the two literals appear in that order -- including in two different functions, or with the reuse branch behind a permanently-false guard. A regression that re-runs the K-fold LGBM fits while keeping both literals in place passes.
**Suggested fix:** Call the per-bin path twice with a counting spy on the LGBM fit and assert the second call performs zero fits. Extend `test_no_source_text_position_proxy_in_test_files` to recognise `open(...).read()` and `fh.read()` bindings, not only `.read_text()`.
**Evidence:** Read tests/training/test_ensembling_caching_future_fixes.py:225-240; `src` is bound at :225 from `open(cd.__file__).read()` and only then extended with sibling `read_text()` in a loop, so `_prod_source_read_text_names` never registers it. Same `open(mod.__file__).read()` shape at tests/reporting/test_renderer_audit_regressions.py:145-146.

**Disposition:** RESOLVED. The byte-order assertion over a CONCATENATION of sibling files is replaced by an AST check scoped to one function: the per-bin cache lookup must appear before the recompute inside the same function body. The per-file sources are kept separately for that reason -- a concatenation can satisfy "A before B" with A and B in different files, which is precisely the hole the finding names.

### XCUT_TEST_QUALITY-6 [P1] single-shot-timing
**File:** tests/reporting/test_panel_emphasis.py:359
**Summary:** A single-shot wall-clock budget expressed as a cProfile `total_tt` compared to a constant -- exactly the shape the single-shot-timing meta-gate cannot see.
**Failure scenario:** `assert total < 0.5, s.getvalue()` measures one profiled run of 20 calls over 1M rows, no warmup, no best-of-N, under a profiler whose overhead is itself load-dependent. On a contended runner this flakes red for reasons unrelated to the code; the predictable repair is to raise the constant, after which a genuine O(n^2) regression in `select_binary_emphasis_panels` fits under the new ceiling. The gate at tests/test_meta/test_no_single_shot_timing_assertion.py:55-70 only matches `<division> <cmp> <constant>`, so a bare `total < 0.5` is structurally exempt.
**Suggested fix:** Drop the profiler and assert the complexity class instead: time the derivation at n and 4n with `min(... for _ in range(3))` per side and assert the ratio stays under ~6x; or assert a call-count invariant (one pass over `y`) with a counting spy.
**Evidence:** Read tests/reporting/test_panel_emphasis.py:340-359, and the detector at tests/test_meta/test_no_single_shot_timing_assertion.py:55-108 whose own sample at :191-197 documents `assert elapsed < 5.0` as deliberately not flagged.

**Disposition:** RESOLVED. The cProfile `total < 0.5` became a complexity-class assertion. A single n-vs-4n ratio was not robust enough either -- measured on this box the same linear pass gave ratios from 6.7x to 14.6x across trials, with its absolute time at 1M swinging from 9.6ms to 102ms under load -- so the assertion is the MEDIAN per-doubling ratio over four doublings. Linear measured 2.40 / 2.00 / 1.88 / 4.16 (median 2.2) against a bar of 3.0; quadratic would be ~4 per doubling.

### XCUT_TEST_QUALITY-11 [P1] undersized-rare-class-fixture
**File:** tests/feature_selection/biz_val/test_biz_val_imbalanced_rare_class.py:159
**Summary:** The 1%-positive-rate contract is measured at n=4000 (~40 positives), and the file's own docstring records the resulting per-seed degeneracy, which was then absorbed by softening the floors to "majority of seeds".
**Failure scenario:** ~40 minority rows split across train/val/test leaves single-digit positives per slice, so any recovery metric computed on the minority has a standard error comparable to its own value. **Suggested fix:** Size the fixture from the minority count, not the total: at 1% use n >= 20000 for a per-seed floor (~200 positives, ~20 per 10% slice), n >= 8000 as a minimum; at 5% use n >= 2000. Then tighten the assertion back to per-seed. If the wall cost is prohibitive, keep the small fixture for the structural contracts (non-empty, non-full) and move the recovery floor to a `@pytest.mark.slow` variant at proper size.
**Evidence:** Read tests/feature_selection/biz_val/test_biz_val_imbalanced_rare_class.py:1-45 (docstring and its measured recovery matrix) and :113-215.

**Disposition:** RESOLVED. The 1% leg is sized from the minority count: n=20000 (~200 positives, ~20 per 10% slice) instead of n=4000 (~40). Measured there across seeds 0/1/2: recov=[3,3,3], nsel=[3,3,3] -- clean and identical per seed -- so the floor is tightened from a median-of-seeds back to a PER-SEED 3/3, plus a per-seed nsel ceiling. The 3% and 10% legs keep their majority floors at n=3000, and the comment says why: no measurement was taken at a larger size for them.

### XCUT_TEST_QUALITY-12 [P1] deferred-bug
**File:** tests/training/_fuzz_combo/combo.py:2319

**Evidence:** Read tests/training/_fuzz_combo/combo.py:2296-2322 against tests/training/_fuzz_combo/__init__.py:14-49.

**Disposition:** RESOLVED with the production fix, and the canon rule is deleted. It now reduces the fold count to what the minority supports, with a warning naming the reduction, and raises only below 2 where no stratified split exists at all. Verified: 10 positives at n=1000 fits, 2 positives reduces to cv=2, 1 positive raises. `tests/feature_selection/wrappers/test_rfecv_runs_on_rare_positive_targets.py` covers all three plus a guard that the canon rule stays gone. Note the sklearn error the rule cited ("Invalid classes inferred") no longer reproduces: the wrapper already had a clearer guard, and `is_classifier` -- which selects StratifiedKFold over plain KFold here -- only started answering True for in-repo estimators after the MODELS_ESTIMATORS-4 mixin fix in this same campaign.
