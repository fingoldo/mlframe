# _conditional_quantile_rank_gpu (2026-11-06)

Device twin of `conditional_quantile_rank_fe` for the case where the ranked rows are the fitted rows. One `lexsort` over (bin, value), tie-run ends from a cumulative sum of run starts, bin starts from `bincount`; non-finite rows sit in a sentinel bin and come back NaN. Dispatch: `use_device_cqr` (`MLFRAME_CQR_DEVICE=0|1` forces; default from 50000 rows with a usable device); a device fault returns `None` and the host loop runs. Test: `tests/feature_selection/fe/test_conditional_quantile_rank_gpu.py` (ties, NaN / inf, negative bin ids, single bin; exact equality with the host loop on float32 input).

Measured in one process, 100000 rows, 10 bins, float32 (`PYTHONPATH` on the worktree): host 27 to 29 ms per call, device 6.5 ms per call once warm (first call 53 ms: cupy kernel compilation). `generate_conditional_quantile_rank_features` over 6 columns (30 pairs): host 1.18 s, device 0.54 s warm with the host loop for the per-bin sorted references, 0.30 s warm once those references come from the same device sort (`with_sorted_bins`; recipes and columns equal between the paths in `test_generate_recipes_equal_between_paths`). The first call of a process pays about 1.4 s for cupy kernel compilation. Not measured inside the full fit yet.
