# Device conditioned-scan TreeSHAP interaction kernel profile (GTX 1050 Ti, sm_61), 2026-11-17

Module `_shap_proxy_treeshap_interactions_gpu`: the conditioned-scan interaction kernel (one thread per sample, two path scans per conditioning feature, double precision). It is the reference and the fallback of the pair-table kernel (`_shap_proxy_treeshap_interactions_table_gpu`, record `_shap_proxy_treeshap_interactions_table_gpu.md`) and runs when the ensemble does not fit the table form. Host twin: the numba conditioned-scan kernel `interaction_tensor_reference` of `_shap_proxy_treeshap_interactions` (record `_shap_proxy_treeshap_numba.md`).

Workload: XGBoost 200 trees depth 4, 40 features, 3000 rows; whole call of the path kernel 14 949 ms (one call after a warm-up call); the pair-table kernel does the same tensor in 55 ms (contended run) and numba conditioned scan in 7088 ms.
nvprof (2 calls, one of them the warm-up on 200 rows): GPU activities 99.95 percent kernel `treeshap_interactions` (24.19 s in 2 calls, 8.99 s to 15.20 s each), 0.05 percent device-to-host copies (11.7 ms), host-to-device copies 0.18 ms: GPU utilization over the profiled window: the kernel is the whole GPU timeline (99.95 percent) and nothing else; the time is compute and local-memory bound, not transfer bound, so there is no transfer bandwidth figure to optimise.
Resources: 64 registers per thread and 2720 bytes of local memory per thread (the path weights and the double-precision accumulators), block 64. Theoretical occupancy from the registers on sm_61 (65 536 registers per SM): 64 threads x 64 registers = 4096 registers per block, 16 resident blocks = 1024 of 2048 threads, 0.5; the measured occupancy counters are not available on this host (profiling counters permission), so achieved occupancy is not recorded.
Launches per call: 1 kernel per row block (+ memsets and the two copies); rows stream through the device in blocks sized so the (rows, P, P) double-precision tensor, the main effect and the float32 X of a block take at most 40 percent of the free memory (`interaction_tensor_gpu_path`).
Host side (cProfile of the whole call): nothing of note, the call waits on the kernel.
Disposition: kept as the reference and the fallback; the speed path is the pair-table kernel (270x faster at this size). Tuner: the device-or-host choice is `shap_proxy_treeshap_interactions_backend` (`_shap_proxy_treeshap_interactions_ktc`), which reaches this module only when the ensemble does not fit the table.
