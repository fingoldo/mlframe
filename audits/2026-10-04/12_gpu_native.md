# 12 GPU / CUDA / numba-native safety audit (2026-10-04)

READ-ONLY. Scope: src/mlframe (+ pyutilz kernel_tuning for the fingerprint finding). Deduplicated against audits/ (grep for `(long)`, `65535`, `hw_fingerprint`, `searchsorted_right_2d` found no prior row).

## Scope and method
- Enumerated: ~50 files with RawKernel/cuda.jit, ~230 files with prange, 114 `fastmath=True` sites (top: hermite_basis_eval 12, core/arrays 12, dummy_numba_kernels 8, numba_polynom_optimizer 8, hurst 8).
- Read in full or in the kernel bodies: `_batch_pair_mi_cuda_kernels.py`, `_batch_pair_mi_cuda_shared_fused.py`, `_batch_mi_noise_gate_kernels.py`, `gpu.py` (RawKernels), `_gpu_batched.py`, `_gpu_pairs.py`, `discretization/_discretization_cuda.py`, `info_theory/_cmi_cuda.py` (hist + fused CMI), `info_theory/_batch_kernels.py`, `_mi_prange_kernel.py`, `core/arrays.py`, `transformer/_kernels_cupy.py` (stream/pinned pipeline), `_gpu_resident_select_kernels.py` (transposes), `_gpu_hw_launch.py`, `metrics/_gpu_metrics.py` (RMSE), pyutilz `cache_base.hw_fingerprint`.
- Mechanical sweep: scripted AST-free scan of every `prange` body for `arr[idx_not_loopvar] +=` on arrays NOT allocated inside the loop. 4 hits remained; all are per-thread-slot accumulators (`tp_a[get_thread_id()]`, `target_quantile._bucket_sums_counts`), race-free. No `np.random` inside prange (counter-LCG per iteration, n_workers independent). No shared-array prange race found.
- Probe (1 process, 2 threads, 4 bytes of VRAM): NVRTC `sizeof(long)` = 4 and `sizeof(long long)` = 8 on this Windows box (verified output `[4 8]`). No test suites run, no files edited.

## Progress checkpoints

3. NVRTC `long` probe confirmed 4 bytes -> G1.

## Verified clean (no finding)
- `_gpu_pairs.py` gridDim.y guard (65535), per-column range screen, int64 joint_offsets with 4 GiB guard, np.int32 narrowing correct.
- `_batch_pair_mi_cuda_kernels.py` row-chunked path: validates codes and class range, launch-count ceiling, pair-subchunking, shared-memory budget with driver headroom.
- shared-fused kernel: long long indexing, `mi_accum` alignment, shared budget includes headroom, property-set + launch under `_SHARED_MEM_SET_LOCK`.
- `_mi_prange_kernel.py`: per-iteration private copy and LCG seeded from (seed,i), serial twin bit-identical; no shared writes.
- rff stream pipeline: slot sync order is correct (each slot synced before its host or device buffers are reused; final batch synced).
- `_gpu_hw_launch.py`: grid/block derived from device attributes, not hardcoded.
- 4 flagged prange `+=` patterns are per-thread slots (race-free).

## Verdict and not worth fixing
Fix first: G3 (reachable in a default `auto` path, crashes a fit), G6 (silently selects the wrong tuning file for 7 days), G1/G2 (silent garbage or sticky CUDA error, but only on >=24 GB cards or CMI/TreeSHAP at ~8 GB working sets; the 4 GB dev GPU can never reach them, which is why CI never saw them), G7 (reproducibility).
Not worth fixing: G14 (dead code, delete), G13 (ULP-level, documented class), G16, G4/G5 until a >=48 GB target exists. G8 only if an exact tie-break is added downstream.
Not covered: calibration/, metrics/regression/, hurst, wavelet njit bodies (fastmath NaN gating beyond core/arrays), `_numba_polynom_optimizer`, `_hermite_basis_eval` fastmath sites; cache=True cross-file callee staleness (no mitigating gate found beyond the seed stamps) was not exercised.
