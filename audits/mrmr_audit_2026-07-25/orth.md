## Proposals (perf / refactor / test — not bugs)

1. **Fix ORTH-1 + ORTH-2 together**: recompute `_evaluate_basis_column(X[leg], basis, deg, return_params=True)` once per distinct leg (dedup shared legs) and pass `preprocess_params_i/j/k/l` into all three recipe-build sites; route arity-2/3 through `build_orth_triplet_cross_recipe`/`build_orth_pair_cross_recipe` (which call `_freeze_preprocess_params`) instead of the inline `EngineeredRecipe(...)` that bypasses freezing. Add an arity 2/3/4 row-slice replay-parity regression test.
2. **Fix ORTH-3**: implement the tie-corrected Chatterjee estimator (`r_i` = count of `y_j <= y_(i)`, denominator `2*sum L_i(n-L_i)`), which reduces to the current form when y has no ties; add a discrete-y biz_value test asserting `xi ~ 1` for a step-function target with a binary y.
3. **Grep-based CI gate** flagging any `orth_pair_cross`/`orth_triplet_cross` `EngineeredRecipe(...)` or `build_orth_*_cross_recipe(...)` call whose kwargs omit `preprocess_params_*` — this exact "fix landed on the univariate copy, not the multi-leg copy" slip has now recurred across two fix waves.
