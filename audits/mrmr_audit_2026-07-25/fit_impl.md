## Non-findings / confirmed-clean angles

- **Fit-cache key groups fold (recently patched):** `_fit_impl_core.py:244-250` folds `_groups_sig` into `_cache_key` ONLY when `group_aware_mi` is truthy AND `groups is not None`, leaving the group-naive key byte-identical, and `group_aware_mi` itself is already inside `_params_sig`. Two same-X/y/params fits with different groups therefore cannot false-replay, and a group-naive fit's key is unchanged. Correct.
- **Lock-protected replay & store:** the cache-hit lookup+`move_to_end`+`_replay_fitted_state` all run inside one `_MRMR_FIT_CACHE_LOCK` critical section (264-268); the store side holds the same lock across `setdefault`/`move_to_end`/LRU-`popitem`/byte-cap eviction (9848-9890) and uses first-writer-wins `setdefault`. `_skip_fit_cache`, `fit_cache_max=0` (clear-all) and `None`→4 fold are all handled. No race or torn-attribute read found.
- **Group-aware final demotion correctness (other than FIT_IMPL-1):** both scoring paths use `use_mm=True` (`group_relevance_mi` defaults it True at `_group_mi.py:169`; the retention-only path passes it explicitly at 10028), so the exactly-zero threshold is consistent across the fast/replay branches. `_engineered_features_` is filtered in lockstep with `_engineered_recipes_` (10035-10037). NaN group-MI (`_grp_mi_f == _grp_mi_f` guard) is left alone. The "runs last, after retention re-attach" ordering claim in the comment is accurate.
- **p>=n cap ordering (FIT_IMPL_B-2 area):** the second cap (9779-9805) is the true end of raw-selection mutation; the only later `support_` writer is the UAED elbow trim, which only shrinks. EMIT-BOTH re-attach and augmentation both sit above it. Cap invariant holds end-to-end.
- **Rescue-split determinism (FIT_IMPL_B-3 area):** all three gates seed on `random_seed`, reproducible and order-insensitive on sorted/grouped input. Verified at 7444/7598/7745.
- **`support_nonlinear_` re-sync (9962-9963):** re-points to the final `support_` after every raw mutation; the group demotion does not touch `support_`, so it stays valid.
- **`_finalise_empty_support_fallback` (`_finalise.py`):** index-space translation (input-space `support_` vs cols-space `cached_MIs`), redundancy/cluster/engineered-operand exclusions, permutation-significance + redundancy dedup gates, count-floor top-up, and never-empty guarantee all read consistently; `support_` written as `int64` uniformly. No bug found.
- **`fe_decide_on_subsample` (`_helpers.py`):** closed-form-only correctness boundary is documented; shared-subsample-idx validation bounds-checks `max() < n`; empty-result is treated as a valid decision (no wasted full-n re-run); partial-recipe-coverage and replay errors fall back to the full-data decision. No whole-frame copy. Clean.
- **`_eng_dedup_batch_corr.py`:** two-pass centered Pearson with a relative-variance floor, append-only buffer + active-mask (no per-candidate re-copy); assumes finite inputs, which the caller guarantees. Clean.
- **`_fe_stage_temporal_agg.py`:** duplicate-label drop after concat, MI-gate, recipe capture; non-pandas X path warns and skips. Clean.
- **mypy:** `Success: no issues found` on `_fit_impl_core.py` (shared cache-dir). Not re-checked on the 4 tiny siblings individually but they were mypy-clean in the prior wave and unchanged in signature.
- **Security:** no eval/exec/subprocess/pickle.load/SQL/HTTP surface anywhere in the six files (grep-confirmed); only internal log interpolation of feature names.

## Proposals (perf / refactor / test — not bugs)

1. **Regression test for FIT_IMPL-1:** a `group_aware_mi=True` fixture with a between-group-only engineered leak feature, asserting `len(m.mrmr_gains_) == m.n_features_ == len(m.get_feature_names_out())` after fit. No existing test exercises the demotion path together with the gains-alignment contract (the alignment tests do not set `group_aware_mi`), which is exactly why the desync shipped.
2. **Single-source the gains alignment:** factor the 9944-9954 trim/pad into a tiny `_align_mrmr_gains(self)` helper and call it as the very last statement before `return self`, so any future post-alignment `n_features_` mutation (a third demotion-style pass) cannot re-introduce this class of desync.
3. **B-1 decomposition (still open, tracked-exempt):** `_fit_impl` remains ~9990 lines / one function. The post-selection reconciliation chain (cluster-collapse re-strip, search-space enforcement, both p>=n caps, EMIT-BOTH re-attach, raw-signal augmentation, UAED trim, group demotion) is a self-contained tail reading a fixed local set (`self, data, cols, nbins, selected_vars, target_indices, classes_y, cached_MIs, n_engineered_out`) and is a clean carve candidate into a `_post_selection_bookkeeping.py` sibling — which would also make FIT_IMPL-1's ordering unit-testable in isolation. Not a bug; noted for the carve backlog.
