# FE_PAIRS — audit (2026-07-25)

Scope: the FE unary/binary pair-search core subpackage `_feature_engineering_pairs/`
(`_pairs_core.py`, `_pairs_score.py`, `_pairs_emit.py`, `_pairs_chunks.py`, `_pairs_dispatch.py`,
`_pairs_gates.py`, `_pairs_materialise.py`, `_pairs_setup.py`, `_pairs_common.py`, `__init__.py`),
the polynom optimizers (`polynom_pair_fe.py`, `_numba_polynom_optimizer.py`, `_cupy_polynom_optimizer.py`),
and the FE frame/matrix seam (`_fe_batch_dispatch.py`, `_fe_cpu_batch.py`, `_fe_frame_ops.py`,
`_fe_matrix_io.py`, `_fe_mi_contract.py`, `_feature_engineering_mem_budget.py`). This engine builds a
per-operand unary pool (library unaries + optional learned prewarp / median-gate pseudo-unaries), evaluates
every binary op, scores each form's MI against the (optionally subsampled) target via a CPU-njit / GPU
dispatch with a permutation noise-gate, admits winners past the joint-prevalence / marginal-uplift /
tail-concentration gates, and packs survivor columns + leak-safe recipes. Cross-checked against the prior
`fe_pairs_core.md` / `_TRACKER.md` (2026-07-22): FE_PAIRS_CORE-2/-3/-4 are now FIXED in-tree (memoized GPU
gates; gate_med variance guard added at `_pairs_setup.py:214-223`; `bincount(minlength=)` added at
`_pairs_core.py:556`) and are NOT re-reported. FE_PAIRS_CORE-1 (chunk-pipeline thread-safety) and -5
(`_pairs_core`/`_pairs_score` >1k LOC, both on the LOC_BUDGET_EXEMPT list) remain OPEN and unchanged;
see Non-findings. The findings below are new, current, source-verified issues.

## Proposals (perf / refactor / test — not bugs)
1. **FE_PAIRS-1 fix**: guard `_GPU_GATE_CACHE` with a module-level `threading.Lock` around the check-evict-write (mirror `_pairs_common._TIMES_SPENT_LOCK` / `_MRMR_FIT_CACHE_LOCK`), or replace the hand-rolled FIFO with a locked bounded cache; add a `backend="threading"`, ≥65-distinct-`(n,K)` stress test that asserts no `KeyError`/`RuntimeError` across concurrent `_fe_gpu_binning_enabled` calls.
2. **FE_PAIRS-3 fix**: fold the strict-mode / auto-fit-n signal into the cache key (or clear `_GPU_GATE_CACHE` at fit entry) so a mid-process strict-mode flip re-evaluates the backend choice; bench-neutral since the lookup body is cheap.
3. **FE_PAIRS-2 cleanup**: strip the finding-ID `fix` references and `audit A3`/`P1-6` tags, keeping the WHY prose (rationale) that follows each. Mechanical, no behavior change.
