# Audit report: reporting_charts_b

**Cluster:** reporting_charts_b
**Scope:** 14 chart builders under `src/mlframe/reporting/charts/`: `class_structure_heatmap.py`, `confusion_matrix_plot.py`, `decision_curve.py`, `drift.py`, `engineered_separability.py`, `error_analysis.py`, `fairness_calibration.py`, `fuzzy_membership.py`, `interaction_strength.py`, `ltr.py`, `model_card.py`, `model_comparison.py`, `multiclass.py`, `multilabel.py`

**Files reviewed:** 14 (all read in full). `renderers/matplotlib.py`, `renderers/plotly.py`, `reporting/spec.py` were read in the relevant parts to root-cause the reported `model_card.py` defect; findings living there are marked **(renderer)**.

**LOC reviewed:** 5,683 in-scope — `error_analysis.py` 934, `multiclass.py` 827, `drift.py` 810, `multilabel.py` 568, `ltr.py` 494, `model_card.py` 466, `model_comparison.py` 345, `fairness_calibration.py` 262, `decision_curve.py` 237, `engineered_separability.py` 209, `confusion_matrix_plot.py` 201, `class_structure_heatmap.py` 185, `fuzzy_membership.py` 78, `interaction_strength.py` 67.

## Summary by dimension

**1. Correctness (statistical).** Largest yield; three repeating families. **(a) Fixed thresholds that don't scale with n** (5 confirmed live): PSI's 0.10/0.25 lines, the ECE-disparity 0.05/0.10 lines, the target-drift `0.25*train_std` (and a hardcoded 0.25 absolute for classification rates), adversarial `AUC>=0.6`, and `decision_curve`'s newly-scaled margin (correct in form, fed the wrong `n`). Reproduced: a perfectly fair, perfectly calibrated model gets a **RED** disparity verdict because one group has 30 rows; a no-drift feature reads PSI 0.26-0.91 ("significant drift") at 50 rows/bucket and 0.003 at 5000. **(b) Degenerate branches returning a misleading value instead of an explanation** (9 sites): PSI reports **0.00 "stable" forever** for a feature constant during the baseline and exploding afterwards; a 4x jump in a rare-event class rate reads "No material drift from train"; `ltr.py` plants fabricated `0.0` data on four empty-data paths, one of which then prints "mean=0.000, 95% CI [0.000, 0.000]". **(c) Catastrophic cancellation** (`drift.py:288-289`): per-bucket residual std as `E[x^2]-E[x]^2` then `clip(...,0,None)` — at residual centre 1e8 / true std 0.01 the reported stds are `[5.099, 0.0, 0.0, 0.0, 7.616]`. Fourth instance of a class CLAUDE.md documents three of. Plus: `multiclass` top-k breaks ties by class index so a **uniform predictor reports top-1 accuracy 0.798 or 0.100** depending on class ordering; `model_comparison` reports **rho=1.000 between two constant models**; `model_card` silently accepts multiclass labels and out-of-[0,1] scores (`ECE=2.7`, `nan` Brier).

**2. Efficiency.** Three quantified: `drift` PSI builds a full-`n` mask + copy per (feature,bucket) cell — 40x10=400 full-`n` passes where the `order` permutation for a single contiguous sweep is already computed; `multiclass` top-k is O(n*K^2) where an argsort-inverse + cumulative histogram is O(n*K); `ltr._top1_by_qsize_panel` runs a per-query Python loop with its own second group sort, bypassing the `shared` cache the module docstring says all heavy per-query work uses. Everything else is genuinely aggregate-first and well benched.

**3. Architecture.** Three files at/over the "carve before ~800-900 LOC" line (934/827/810). Three near-identical group-capping helpers; two near-identical one-vs-rest rank-AUC helpers; `fairness_calibration` duplicates its whole per-group loop between composer and headless metric. One dead branch (`order = order`), one dead guard (`max(1, n_pos)`).

**4. Informativeness (HIGH-VALUE).** **13 of 14 builders emit no `FigureSpec.caption`** — only `decision_curve` does, and only because it was just added; repo-wide only 3 of ~42 builders populate it, which `tests/reporting/test_chart_explanations.py`'s own docstring already flags. Proposed caption text for all 13 is below. Beyond captions the recurring gap is **support**: `class_structure_heatmap` computes `_counts` and throws it away; `multiclass._confused_pairs_panel` ranks by row-normalised rate with no support floor or `n`; `fairness_calibration` puts `n` in the curve legend but not on the ECE bars; `drift.psi_heatmap` shows no bucket `n` at all. Several figures state no verdict on *this* data.

**5. UI/UX.** A live reproducible layout defect in `model_card` (below). A cross-backend axis-label swap for horizontal bars making one backend wrong on every horizontal bar in the repo. `model_card` wastes a third of its top row on a `None` cell. `error_analysis.weak_segment_heatmap` prints **counts** in cells whose colour and colorbar encode **mean error**. `class_structure_heatmap`/`drift.psi_heatmap` render up to 620/400 cell numbers with no large-K suppression, unlike `multiclass` and `confusion_matrix_plot` which both have one.

**6. Edge cases.** `error_analysis._resolve_feature_matrix` uses a bare `zip` and **silently drops every column past `len(feature_names)`**. `model_comparison._corr_heatmap_panel` raises, killing the entire 3-panel figure. `decision_curve` has a dead operator-precedence guard. `fuzzy_membership` raises where every sibling degrades. `_tag_error_groups` puts every row in both OVER and UNDER when the signed error is constant.

**7. Test coverage.** 165 tests across the 14 modules, overwhelmingly *shape and wiring* assertions. **No test in scope compares a computed statistic against an independent reference**, and none exercises the regimes where every P1 above lives. `multiclass.py`/`multilabel.py` have zero tests asserting a metric *value*.

**8. OSS hygiene.** Tracker IDs in docstrings at 5 sites (`(R-12)`, `(INV-26)`, `(INV-9)`, `(R-1)`, `(R-3 / INV-11)`) including a broken `(INV-)` with no number; a `# Wave 21 P2:` marker plus a design-deliberation comment ending in a question mark; a `v1:/v2:/v3 (current):` refactor-history narration in a docstring. No mojibake; no `--`-in-prose violations (the `--` occurrences are inside strings rendered on figures).

## Narrative detail

### The live `model_card.py` rendering defect: root cause

I built the card for a dummy/constant-prediction model on both backends and inspected the specs and rendered figures.

**(a) The overlap is real, and the cause is in the matplotlib renderer, not the builder.** `MatplotlibRenderer._annotation` (`renderers/matplotlib.py:252`) draws the header with `ax.text(..., transform=ax.transAxes, wrap=True)`. Matplotlib's `Text._get_wrap_line_width()` computes the wrap budget **against the figure's window extent**, not the axes': for centre-aligned text it returns `2 * min(dist_to_fig_left, dist_to_fig_right)`. Measured directly on the rendered card: **wrap line width 643.8 px, annotation axes width 532.9 px, bar axes starting at x = 663.5 px.** So matplotlib permits lines 21% wider than the panel, reaching within 20 px of the bar panel — and since it only breaks at spaces, a single long token (`DummyClassifier(strategy=prior)`) isn't broken at all. Rendering with a realistic estimator name produced a header line spanning x approximately 70-575 px, already off the left edge; a longer name overlaps the bar panel outright. `savefig(bbox_inches="tight")` in `MatplotlibRenderer.save` masks part of this by expanding the canvas, so the defect is worse in a notebook/HTML embed than in a saved PNG. On plotly (`renderers/plotly.py:345`) there is **no wrapping at all**, and plotly paints annotations above traces, so the overflow lands visually on top of the bar panel. `model_card.py` compounds it by putting the header in a 1/3-width column while leaving the adjacent third `None` (finding -4).

**(b) The `-2..1` axis — what I found and what I could not reproduce.** I could **not** reproduce a `-2..1` x-range on either backend. Across every input tried (constant probabilities, anti-correlated score, 2-row input, regression dummy with zero-variance predictions, constant target) the matplotlib bar axis came back `(0.0, ~1.05)` or, all-zero, `(0.0, 0.525)`; plotly leaves the range on autorange with the trace confirmed `orientation="h"`, `x=values`, `y=categories`. `_headline_bar` does clip every value into `[0,1]` (`model_card.py:206`), so no negative value can reach the trace.

What I **did** reproduce is a closely-matching symptom with a concrete cause: `np.clip` propagates NaN, and `fast_brier_score_loss` returns **NaN** for scores outside `[0,1]` (confirmed: `fast_brier_score_loss(y, [-2.2,...])` returns `nan`). A card built from `decision_function` margins yields `values = [0.5, 0.277, 0.049, 0.0, 0.0, nan]`, the `1-Brier` bar silently vanishes, the header prints `Brier nan`, `compute_ece_and_brier_decomposition` returns `ECE = 2.7` (impossible for a probability, and it feeds the traffic light at `model_card.py:117`), and the matplotlib bar axis collapses to **`(0.0, 0.525)`** — a value axis that visibly does not span `[0,1]` despite every plotted value being clipped to it. With *all* values NaN the axis becomes `(0.4725, 0.5275)`, centred on the `hline`. That is the closest reproducible match, and a genuine P2 regardless (finding -6).

I also found a definite, independently confirmed axis defect on this panel: **plotly puts `BarPanelSpec.xlabel` on the wrong axis for horizontal bars** (`renderers/plotly.py:747-748`). Dumping the plotly layout for the model card gives `yaxis2.title = "quality"` and `xaxis2.title = ""` — the *category* axis carries the value's unit and the value axis is unlabelled, the opposite of matplotlib. Since `fairness_calibration.py` passes the *category* name in `xlabel` while `model_card.py`/`multiclass.py` pass the *value* name, one backend is wrong on every horizontal bar in the repo; I confirmed the matplotlib fairness bar renders its 0-0.20 ECE axis labelled **"subgroup"**.

I flag `-2..1` as **not reproduced** rather than guessing. If the reporter can share the exact call (task, `y_score` range, backend, `plot_outputs` format), the NaN-collapse path above is the first thing to check.

### How the "fixed threshold" family was confirmed

Each was confirmed by generating data with **no** effect and watching the figure's own verdict turn red, or a large effect and watching it stay green:

- **fairness_calibration (-12):** perfectly calibrated `p ~ U(0,1)`, `y ~ Bernoulli(p)`, identical mechanism in both groups, n_A=200000 / n_B=30 gives `{'A': 0.00207, 'B': 0.19276}`, gap 0.1907, `traffic_light = 'red'`.
- **drift PSI (-17):** i.i.d. `N(0,1)` over time, 10 buckets. 50 rows/bucket gives `[0, 0.26, 0.15, 0.21, 0.38, 0.20, 0.83, 0.29, 0.91, 0.44]` — "significant drift" in 5 of 9 comparable buckets. 5000 rows/bucket gives `[0, 0.0058, 0.0026, ...]`. Note also that column `t0` is structurally exactly 0 (the baseline *is* bucket 0), which reads as a "getting worse over time" gradient that is partly an artefact.
- **error_analysis._target_drift_verdict (-24):** train 5/1000 = 0.5%, test 20/1000 = 2.0% gives `"Mean shift (class-1 rate shift vs train): test +0.015; train mean=0.005. No material drift from train."`
- **decision_curve (-8):** N=200000 labels, random finite scores on only the first 150 rows gives `useful=True`, `best_pt_advantage=0.0054`, margin applied 0.00219 (from n=200000) where the correct margin for 150 effective rows is 0.080. The scaling is correct in form; it is simply fed the wrong `n`.

### The variance-cancellation instance (-18)

`residual_vs_time` accumulates `mean` and `mean_sq` per bucket via two `np.bincount` calls, then `var = clip(mean_sq - mean*mean, 0, None)`. Fed residuals with a large mean relative to spread — exactly the price/revenue shape the module docstring calls out:

| residual centre | true std | reported per-bucket std (first 5) |
|---|---|---|
| 1e5 | 1e-4 | `[0.0, 0.0, 0.00517, 0.00517, 0.00239]` |
| 1e6 | 1e-3 | `[0.0, 0.0, 0.0, 0.0765, 0.0541]` |
| 1e8 | 1e-2 | `[5.099, 0.0, 0.0, 0.0, 7.616]` |

The `clip` is what makes it silent: a negative computed variance becomes a **zero-width band**, read as "this bucket's errors are perfectly consistent". CLAUDE.md documents three prior instances of this exact expansion; this is a fourth, in a different subsystem, and the same two-pass centred fix applies.

### The tie-breaking family (-32, -41)

`multiclass._top_k_acc_panel` argsorts `-proba`, so with identical probabilities the winner is class index 0. On a **uniform, zero-information** predictor with prevalences `[0.8, 0.1, 0.1]` it reports top-1 accuracy **0.798**; with `[0.1, 0.1, 0.8]`, **0.100**. Both should be 1/K = 0.333. A collapsed model reads as 80% accurate on the very figure meant to catch that.

`model_comparison._spearman_corr_matrix` ranks with a single argsort and no tie averaging. A constant column doesn't have zero rank-variance — it gets ranks `0..n-1` in **row order** — so the `std > 0` guard the docstring relies on never fires:

```
           const1  const2   real
const1      1.00    1.00   -0.04
const2      1.00    1.00   -0.04
real       -0.04   -0.04    1.00
```

The heatmap's stated purpose is "~1.0 cells flag near-redundant models", so two models sharing no information are flagged maximally redundant and the promised NaN handling is dead code. The same mechanism biases correlation between heavily-quantised tree outputs toward their row-order agreement.

- **`model_card`** — "Each headline bar is rescaled so **longer = better on [0,1]**: discrimination metrics (ROC_AUC, PR_AUC, KS, MCC) shown directly, error metrics as `1 - metric`; the grey line at 0.5 is the midpoint, not a pass mark.
