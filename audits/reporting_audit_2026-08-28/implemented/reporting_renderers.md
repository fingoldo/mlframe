# Audit report: reporting_renderers

**Cluster:** reporting_renderers
**Scope:** every `.py` under `src/mlframe/reporting/renderers/`.

**Files reviewed:** 11, each read in full — `__init__.py` (25), `base.py` (58), `_shared_helpers.py` (122), `_trend.py` (74), `_plotly_color.py` (75), `_plotly_interactivity.py` (122), `_plotly_network.py` (137), `_kaleido.py` (339), `save.py` (347), `matplotlib.py` (789), `plotly.py` (936).
**LOC reviewed:** 3,024. `src/mlframe/reporting/spec.py` (404) was read as reference for panel-field contracts but is out of scope for findings.

**Method:** every claim was confirmed by rendering a purpose-built `FigureSpec` on both backends in this working tree and inspecting the returned native figure object (matplotlib `Figure`/`Axes` attributes, plotly `fig.layout` / `fig.data`), except where the narrative says otherwise.

## Summary by dimension

1. **Correctness bugs:** 5 confirmed, 4 silent-wrong-output. Two spec fields accepted then never applied (`LinePanelSpec.ylim`, on BOTH backends), one fill mode filling to the wrong reference (plotly, `fill_baseline != 0`), one heatmap overlay drawn in the wrong coordinate space, and matplotlib's `autofmt_xdate()` erasing the very tick labels the new `x_is_time` formatting just computed.
2. **Computational efficiency:** no hot-path defects. Both known plotly quadratic traps (per-cell and per-arrow `add_annotation`) are already batched with benches cited. Remaining: one loop-invariant `nanmin`/`nanmax` recomputed per contour level, and several avoidable `.tolist()` materializations.
3. **Architecture and clarity:** `_shared_helpers.py` holds 5 helpers while three numeric constants and the bar-tick-thinning algorithm are duplicated between renderers — and the copies have already drifted. `plotly.py` is 936 LOC against the "carve before ~800-900" rule. One dead-code block.
4. **Informativeness:** panel vocabulary is rich (hover templates naming real quantities, per-cell support in tooltips, rangesliders, `AnnotationPanelSpec` instead of fake degenerate charts). Gaps at the edges: regime-shading labels invisible in HTML, `inline_labels` positions discarded by plotly, matplotlib violins all one colour.
5. **UI/UX (highest yield):** 9 findings, dominated by backend divergence — the same spec yields a mirrored heatmap, a differently-sized plot area, a ghost empty axes cell, a different legend, and a different violin palette. Plus a real element-overlap defect (stacked plotly colorbars) and a red/green pair on the default regression scatter.
6. **Edge cases:** 3 confirmed degenerate-input crashes, each asymmetric across backends, all swallowed by `render_and_save` into a throttled WARN.
7. **Test coverage:** the `x_is_time` contract is pinned by a SINGLE-PANEL fixture — precisely the shape where the `autofmt_xdate` bug cannot fire. Nothing tests `fill_baseline`, `ylim`, `legend_label`, `None` grid cells, or backend parity.
8. **OSS hygiene:** 9 comments carry banned process metadata (date stamps, combo IDs, finding IDs); one dash-pair reaches rendered output as a title separator.

## Narrative detail

**-1 (ylim silently dropped).** `spec.py:262-264` documents the field as "overrides autoscale (e.g. clipping a net-benefit panel's floor below a steeply-diving treat-all reference so the informative region near 0 stays readable)", and `charts/decision_curve.py:176-181` computes exactly that window. Grepping `ylim` under `renderers/`, the only reads are in `_scatter` and its perfect-fit branch; `_line` never touches it on either backend. Confirmed by rendering a two-series line panel with `ylim=(-1.0, 1.0)` and a second series diving to -20: matplotlib reported `get_ylim() == (-21.05, 2.05)` (pure autoscale), plotly's `layout.yaxis.range` was `None`. The decision curve ships with precisely the defect its own comment says the field prevents.

**-2 (autofmt_xdate erases labels figure-wide).** `matplotlib._line` ends with `if fig is not None: fig.autofmt_xdate()`. That is a FIGURE-level method: with more than one axes it hides x tick labels of every non-last-row axes and clears their `xlabel`. Rendering a 2x2 spec whose only temporal panel was cell (0,0) gave the temporal panel's own freshly-computed date ticks invisible and its "time" label gone, and an unrelated bar panel in the same row lost its category labels, while row-1 axes kept theirs. This is the second-order failure of an otherwise-correct recent fix: the tick values are now right, then a figure-level call hides them.

**-3 (`tonexty` is not a baseline fill).** In plotly `"tonexty"` fills between this trace and the PREVIOUS trace; it has no relationship to `fill_baseline`'s value. A two-series panel with `fill_to_baseline=(True, True), fill_baseline=0.5` returned `fills == ['tonexty', 'tonexty']`: series 0 fills to whatever preceded it, series 1 fills down to series 0. matplotlib does `fill_between(xi, 0.5, y)`.

**-4 / -5 (density heatmap mirrored and carrying an off-axis overlay).** Confirmed in one render: a 10x10 `histogram2d` of a pred-vs-actual cloud around 5000, with `trend_line="theil-sen"`. matplotlib: `images[0].origin == 'lower'`, `xlim == (-0.5, 9.5)`, lines `['y=x', 'robust fit (theil-sen)']`. plotly: `layout.yaxis.autorange == 'reversed'`, one overlay trace at raw VALUE coordinates on a 10-category axis, and no `y=x` trace. `matplotlib.py:469-472` carries a comment explaining exactly this value-vs-index trap; the fix was applied to one backend only. The exact plotly outcome (line invisible vs axis blown out) depends on client-side category autorange, which could not be observed from the figure object; the coordinate-space mismatch itself is confirmed.
